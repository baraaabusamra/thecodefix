# نموذج أمان اختبارات HTML والشهادات

**آخر تحديث:** 2026-09-04

يوثّق هذا الملف حدود الثقة والضوابط الأمنية لمسار اختبارات دروس HTML، والامتحان النهائي، وإصدار الشهادة. المرجع التنفيذي النهائي هو الشيفرة والقيود في قاعدة البيانات؛ هذه الوثيقة تشرح المقصود منها وتسهّل مراجعتها.

## حدود الثقة

- المتصفح غير موثوق: معرّفات الأسئلة، ترتيب الخيارات، الإجابات، الوقت، الدرجة، عنوان المسار، ومعرّف الشهادة يمكن التلاعب بها.
- جلسة المستخدم تُثبت على الخادم في كل Server Action. لا يُقبل `userId` من العميل.
- بنوك الأسئلة وإجاباتها الصحيحة تُحمّل في وحدات خادمية فقط. يصل المتصفح إلى نص السؤال والخيارات بعد حذف الإجابة والتفسير.
- قاعدة البيانات هي مصدر الحقيقة للمحاولات، الأهلية، النتائج، والشهادات.

## الضوابط المطبّقة

1. ينشئ الخادم محاولة الاختبار ويختار الأسئلة وترتيب الخيارات، ثم يخزّنهما قبل عرض النسخة المنقّحة للعميل.
2. التصحيح خادمي بالكامل اعتمادًا على بنك الأسئلة والترتيب المخزّن؛ لا تُقبل درجة محسوبة من المتصفح.
3. كل قراءة أو تعديل لمحاولة يتحقق من مالكها، وحالتها، وانتهاء وقتها حيث ينطبق.
4. أهلية امتحان HTML تتطلب نجاح المستخدم في اختبارات جميع الدروس المطلوبة في `src/lib/quiz-requirements.ts`.
5. إصدار شهادة HTML يبحث خادميًا عن محاولة امتحان ناجحة للمستخدم نفسه، ويستخدم UUID مولّدًا على الخادم.
6. مسار الإصدار القديم يرفض أي مسار لديه بنك امتحان آمن، لذلك لا يمكن استخدامه لتجاوز امتحان HTML باستدعاء Server Action مباشر.
7. عنوان المسار المخزّن يُشتق من بيانات المحتوى على الخادم، والاسم الظاهر يُنظّف من محارف التحكم واتجاه النص ويُحدّد طوله.
8. فهرس فريد جزئي على `(userId, track)` للشهادات ذات الحالة `valid` يمنع أكثر من شهادة صالحة للمستخدم والمسار، مع الاحتفاظ بروابط الشهادات الملغاة. تعارض إصدارين متزامنين يُحل بإرجاع الشهادة الفائزة.
9. تحديد المعدل مطبّق على بدء المحاولات، حفظ الإجابات، التسليم، وإصدار الشهادة.
10. فهارس جزئية فريدة تمنع أكثر من محاولة درس واحدة `in_progress` لكل مستخدم/درس، وأكثر من محاولة امتحان واحدة `in_progress` لكل مستخدم/مسار. طلبا البدء المتزامنان يتقاربان على الصف الفائز نفسه.

## ثوابت قاعدة البيانات

- `lesson_quiz_attempt.userId` و`exam_attempt.userId` يرتبطان بالمستخدم مع `ON DELETE CASCADE`.
- `certificate.examAttemptId` يرتبط بـ`exam_attempt.id` مع `ON DELETE SET NULL` للحفاظ على سجلات الشهادات التاريخية.
- `certificate(userId, track)` فريد عندما تكون الحالة `valid`. يعلّم الترحيل النسخ التاريخية الأقدم للمستخدم والمسار كـ`revoked` قبل إنشاء الفهرس، دون حذفها أو كسر رابط التحقق الخاص بها.

## مخاطر متبقية وحدود مقصودة

- تحديد المعدل الحالي محلي للعملية؛ النشر متعدد النسخ يحتاج مخزنًا مشتركًا مثل Redis حتى تكون الحدود عالمية.
- المسارات التي لا تملك بنك امتحان آمن ما زالت تستخدم تدفق الشهادة القديم. لا ينبغي وصف شهاداتها بأنها مبنية على تصحيح خادمي إلى أن تُرحّل.
- سرية بنك الأسئلة تعتمد على بقائه خارج وحدات العميل وحزم المتصفح؛ يجب فحص ذلك بعد أي إعادة هيكلة للاستيرادات.

## فحوص ما قبل الدمج والنشر

- تشغيل `npx tsx --experimental-test-module-mocks --test tests/quiz-exam-certificate-security.test.mjs`.
- تشغيل اختبارات المستودع، TypeScript، ESLint، وفحوص المحتوى والروابط عبر أوامر CI المعتمدة.
- مراجعة SQL الترحيل والتحقق من أن كل مجموعة شهادات تاريخية ستحتفظ بأحدث نسخة صالحة وتلغي الأقدم دون حذفها.
- عدم تنفيذ الترحيل على الإنتاج ضمن فحص محلي؛ التطبيق يحتاج نافذة نشر وخطة رجوع مستقلة.
