# سياسة SEO التقنية — The Code Fix

> القواعد الميكانيكية الصلبة لكل محتوى منشور على الموقع، واللي بتتفحّص تلقائيًا
> قبل كل نشر. هاي مكمّلة لـ[استراتيجية SEO](seo-strategy.md) (الـ**لماذا**
> والأولويات) و[دليل الكلمات المفتاحية](seo-keywords.md) — هذا الملف هو الـ**كيف**
> الصارم: حدود رقمية وقواعد بنيوية، كل وحدة منها مربوطة بفحص آلي دائم بـ`run-ci.cmd`.

كل قاعدة هون طلعت من **بَق حقيقي انلقى ووصلح** بجلسة تدقيق شاملة (2026-08-21-22)،
مش قواعد نظرية. لو عندك شك ليش قاعدة موجودة، اقرأ الملاحظة تحتها.

---

## 1) العناوين (`<title>`)

- **الحد الأقصى: 60 حرف للعنوان المعروض فعليًا في نتائج البحث** — مو العنوان
  الخام بالـfrontmatter، العنوان **بعد** أي بادئة/لاحقة تلقائية.
- **الدروس (`/learn/<track>/<lesson>`)**: تستخدم `title.absolute` بلا لاحقة
  عامة. الصيغة المفضلة هي `"<عنوان المسار> بالعربي: <عنوان الدرس>"` عندما
  تبقى ضمن 60 حرفًا؛ وإلا يُستخدم `seoTitle` الصريح، أو عنوان الدرس النظيف
  إذا كان وحده ضمن الحد (شوف `src/app/learn/[tech]/[lesson]/page.tsx`).
- **مقالات المدونة (`/blog/<slug>`)**: تستخدم `seoTitle` بالـfrontmatter لو
  موجود (مطلق، بدون لاحقة)، وإلا `title` + `" | The Code Fix"` (15 حرف إضافية).
  **مقارنات/عناوين طويلة لازم يكون عندها `seoTitle` صريح** وإلا رح تتجاوز الحد
  بسهولة (مثال حقيقي: عنوان خام 95 حرف بعد إضافة اللاحقة صار عمليًا غير قابل
  للعرض الكامل بجوجل).
- **فحص**: `npm run seo:title-audit` (يدوي، غير مانع للـbuild — الحد إرشادي
  مرن مش خطأ صارم لأنه مرتبط بمحتوى الصفحة نفسها).

## 2) الأوصاف (`meta description`)

- **مطلوب على كل صفحة محتوى** (درس، مقال، مدخل مرجعي) — بدون استثناء.
  لقينا 12 صفحة حية بدون أي `<meta name="description">` إطلاقًا لأنه الحقل
  كان ناقص بالـfrontmatter (لا خطأ build، لا تحذير — يختفي بصمت).
- **الطول المثالي: 50–160 حرف.** أقل من هيك ضعيف، وأكثر بيُقصّه جوجل.
- **فحص**: `npm run check:frontmatter` (تراكات) و`npm run check:blog-ref`
  (مدونة + مرجع) — يوقفان الـCI لو في حقل ناقص.

## 3) عنوان H1 وحيد فقط

- **لا تفتح جسم أي درس/مقال بـ`# عنوان`** — العنوان يظهر تلقائيًا كـ`<h1>`
  من حقل `title` بالـfrontmatter. أي `# ...` إضافي بالمحتوى نفسه = H1 مكرّر
  على نفس الصفحة (سيّئ لإمكانية الوصول والـSEO معًا).
- لقينا 10 ملفات حية بهذا الخطأ (نفس "الدفعة" يلي كانت ناقصة الوصف أيضًا —
  علامة على أنها أُنتجت بعملية مختلفة عن باقي الموقع).
- **فحص**: `npm run check:redundant-h1`.

## 4) الروابط الداخلية يجب أن تُحلّ فعليًا

- أي رابط `](/learn/...)` أو `](/blog/...)` أو `](/reference/...)` **لازم
  يأشّر لصفحة موجودة فعليًا**. لقينا 84 رابط مكسور حي (24 منها كسرت التنقّل
  بمسار كامل — Microservices — لأنه اتفاق تسمية الملفات فيه كان مختلف عن
  باقي الموقع).
- **عند حذف/دمج صفحة كانت منشورة سابقًا**: أضف تحويل 301 دائم بـ
  `next.config.ts` (قسم `redirects()`) **ونظّف** أي مُدخل مطابق بـ
  `src/content/lesson-dates.json`. لا تحذف رابط حي بدون تحويل أبدًا.
- **فحص**: `npm run check:links`.
- **تغيير اسم/رقم درس منشور أو حذفه** (مثل `24-summary` → `29-summary` لما
  يكبر المسار): أضف `{ "from", "to" }` بـ`src/content/lesson-moves.json` —
  بيتحوّل تلقائيًا لـ301 بـ`next.config.ts`. سجل كل درس انتشر يومًا
  (`src/content/published-lessons.json`) بيتحدّث مع `npm run dates:generate`.
  لقينا 30 رابط درس حي بيرجّع 404 بـ Search Console (2026-10-16) من هالسبب
  بالضبط.
- **فحص**: `npm run check:lesson-redirects`.

## 5) لا صفحة يتيمة (Orphan Pages)

- كل مقال مدونة لازم يكون قابل للوصول عبر **إما** واجهة "اقرأ أيضًا"
  التلقائية (`getRelatedPosts()` بـ`src/lib/blog.ts` — تتطابق حسب تداخل
  الكلمات المفتاحية/العنوان) **أو** رابط يدوي حقيقي من صفحة أخرى (درس أو
  مقال). لقينا 19 مقال (من 90) مالهم أي مسار وصول — غير مكتشَفين إلا عبر
  البحث المباشر أو الـsitemap.
- عند كتابة مقال بموضوع ضيّق (خطأ تقني محدد، مقارنة تقنيتين نادرتين) **لا
  تعتمد على الخوارزمية التلقائية** — أضف رابطًا يدويًا من الدرس الأكثر
  صلة بالموضوع بنفسك وقت النشر.
- **فحص**: `npm run check:orphan-blog`.

## 6) لا تكرار/تنافس كلمات مفتاحية داخل نفس القسم المرجعي

- مدخلان بنفس القسم المرجعي (`src/content/reference/<section>.json`) ما
  لازم يشتركوا بنفس الكلمة المفتاحية بالضبط — كل كلمة لصاحبها الأنسب فقط.
  **استثناء مقبول**: وسم تصنيف عام تشترك فيه عدّة مداخل عمدًا (كل مدخل
  له كمان معرّف أدق يميّزه) — هذا مو تنافس حقيقي.
- **فحص**: `npm run check:ref-keywords` (إعلامي، يحتاج حكمًا بشريًا —
  مو كل تشابه هو خطأ).

## 7) روابط `related[]` بالمرجع لازم تُحلّ ضمن نفس القسم

- حقل `related` بأي مدخل مرجعي بيتفلتر **بصمت** لو أشار لسلق غير موجود
  بنفس القسم (`getRefEntry(section, slug)` بترجع `undefined` فتُستبعد بلا
  أي خطأ ظاهر). لقينا 60 رابط ذات-صلة مكسور بهذا الشكل بالضبط.
- **`related` ما بيشتغل عبر أقسام مختلفة** — لو بدك تربط مفهومين بقسمين
  مختلفين، استخدم رابط Markdown عادي بحقل `description`... **بس انتبه**:
  حقل `description` نفسه **ما بيعالج صيغة Markdown للروابط** إلا لو كانت
  `[نص](/مسار)` بالضبط (شوف `renderInlineLinks` بـ
  `src/app/reference/[section]/[slug]/page.tsx`) — أي صيغة تانية بتظهر
  كنص حرفي بأقواس.
- **فحص**: `npm run check:ref-related`.

## 8) ترتيب دروس "الخلاصة"

- درس "الخلاصة/الملخّص" بأي مسار **لازم يكون عنده أعلى قيمة `order`** بذلك
  المسار — الترتيب الحقيقي للتنقّل (أزرار التالي/السابق) مبني بالكامل على
  حقل `order`، مش اسم الملف. لقينا **11 مسارًا** فيها درس خلاصة برقم ترتيب
  قديم (من وقت ما كان المسار أقصر)، فكان الطالب يوصل "أنت خلّصت!" بمنتصف
  المسار الفعلي.
- **فحص**: `npm run check:summary-order`.

## 9) قبل إنشاء أي صفحة جديدة

- طبّق **اختبار وجود الصفحة** الستة الموجود بـ
  [content-guidelines.md § 7](content-guidelines.md) قبل أي محتوى جديد —
  هذا الملف يغطّي القواعد الميكانيكية بعد النشر، وذاك يغطّي **هل يستاهل
  ينُشر أصلًا**.
- نمط خطر معروف تكرّر الليلة بعدّة مسارات: درس أساسي (`X.mdx`) + درس
  "بعمق" (`X-deep.mdx`) بنفس المحتوى تقريبًا مُعاد تدريسه من الصفر بدل
  البناء عليه. لو بتضيف درسًا بلاحقة `-deep`/`-advanced`، تأكّد إنه
  **يبني على** الدرس الأساسي (رابط "يبني على" + محتوى جديد فعليًا)، لا
  يعيد شرح نفس الأمثلة.
- نفس المنطق لمقالات "X مقابل Y" — راجع
  [content-guidelines.md § 37](content-guidelines.md) قبل كتابة أي
  مقارنة جديدة.

## 10) البيانات المهيكلة (Schema.org)

- كل نوع صفحة رئيسي عنده JSON-LD مخصّص عبر مكوّن `<JsonLd>`
  (`src/components/JsonLd.tsx`) — 16 نوع صفحة مغطّاة حاليًا (دروس، مسارات،
  مدونة، مرجع، اختبارات، خرائط طريق، وظائف، أكاديمي، منشئي محتوى، الرئيسية).
  **أي نوع صفحة جديد لازم ياخذ نفس المعاملة** — راجع صفحة مشابهة موجودة
  كمرجع قبل البناء من الصفر.

## 11) الفهرسة، robots.txt، وخريطة الموقع

- **النمط المعتمد بالموقع** (`src/app/robots.ts`): الصفحات الخاصة تُمنع
  بطريقتين متكاملتين لا واحدة بس — `disallow` بـrobots.txt **للمسارات
  الإدارية فقط** (`/admin`, `/api/`)، بينما الصفحات الخاصة الفردية
  (`/account`, `/login`) تُترك **مسموحة بالزحف** لكن بعلامة `noindex` على
  مستوى الصفحة. **ليش هيك مقصود**: لو منعت الزحف بـrobots.txt، جوجل ما
  رح يشوف علامة `noindex` أصلًا، فممكن الصفحة تنفهرس "عمياء" لو في رابط
  خارجي إليها (بتظهر بـGSC كـ"Indexed, though blocked by robots.txt" —
  عكس المطلوب تمامًا). **لا تضيف `/account` أو صفحة مشابهة لـ`disallow`
  بدون فهم هذا الفخ.**
- **صفحة `/search` تحديدًا**: مسموحة بالزحف + `noindex` + `follow` — حتى
  تبقى الروابط المكتشَفة فيها قابلة للمتابعة رغم إنها هي نفسها ما بتنفهرس.
- **خريطة الموقع** (`src/app/sitemap.ts`) تُبنى ديناميكيًا من نفس دوال
  المحتوى (`getTracks`, `getLessons`, `getPosts`...) — **لا يوجد خطر
  تكرار أو رابط ميت فيها بنفسه** لأنه أي حذف محتوى ينعكس تلقائيًا. الخطر
  الوحيد هو نسيان تنظيف `redirects()` بـ`next.config.ts` (قسم 12 تحت).

## 12) نوع التحويلات (301 مقابل 302 مقابل 410)

- **حذف/دمج صفحة كانت منشورة**: تحويل **301 دائم** (`permanent: true`
  بـ`next.config.ts`) لصفحة بديلة **حقيقية وذات صلة** — أبدًا للصفحة
  الرئيسية كحل افتراضي. كل تحويل عملناه الليلة كان لصفحة الدمج الفعلية
  (مثلًا `/learn/docker/07-dockerfile-deep` → `/learn/docker/02-dockerfile`،
  مش `/learn/docker`).
- **محتوى مؤقت الطبيعة** (مثل عروض وظائف Jooble منتهية الصلاحية):
  يستاهل تفكير منفصل — 302 لو رح يرجع، أو صفحة "غير متاح حاليًا" بدل
  تحويل قسري، بدل التعامل معه كصفحة دائمة الحذف.

## 13) صدق حقول الحداثة

- حقل `updated` بالـfrontmatter (تراكات) يُستخدم فعليًا بمخطّطات
  `dateModified` — **لا تُحدّثه إلا مع تغيير محتوى فعلي وذي معنى**.
  تحديث التاريخ فقط لإيهام جوجل بمحتوى "طازج" هو بالضبط النوع يلي
  Google's helpful-content systems مصمّمة تكتشفه وتعاقب عليه.

## 14) قبل إضافة فلترة/بحث ديناميكي (وقائي — مافي فعليًا اليوم)

- صفحات الدول الحالية (`/jobs/<country>`, `/training/<country>`) قائمة
  **محدودة وثابتة** (`COUNTRIES` بـ`src/lib/job-search.ts`) — لا خطر
  تفجّر روابط حاليًا. **لو انضافت فلترة تفاعلية لاحقًا** (بحسب لغة/مستوى/
  سعر...)، القرار الافتراضي: **لا تجعل كل تركيبة فلتر URL قابلة للفهرسة**
  — فهرسة تركيبة واحدة "canonical" لكل فئة حقيقية بس، والباقي عبر
  `?query params` غير مفهرسة أو بـ`noindex`.

## 15) أمان SEO — منع التلاعب عبر مدخلات خارجية

- **مصادر المحتوى الخارجية بالموقع** يجب أن لا تتحكّم مباشرة بعناصر SEO
  حسّاسة (`<title>`, canonical, structured data) بدون تعقيم:
  - قسم `creators` (محتوى منشئين) — أي نص يُدخله مستخدم خارجي (عنوان
    منشور، وصف) لازم يُعامَل كنص خام بالـmetadata، لا يُدرَج كـHTML خام
    أو يُستخدم مباشرة كـcanonical/structured-data بدون تحقّق.
  - نظام استخراج المناهج (`src/lib/curriculum/`) بيجيب محتوى من مصادر
    خارجية (Tavily/PDF) — هذا محتوى **مسودة تحت مراجعة بشرية** عبر
    `pipelineReviewQueue` (التفاصيل الكاملة بـ
    [`docs/factual-data-governance.md`](factual-data-governance.md))،
    ممنوع يوصل لأي صفحة عامة أو structured data بدون المرور بالبوابة
    البشرية أولًا.
- **لا تسمح لأي مدخل مستخدم يتحكّم بـ**: قيمة `noindex`/`nofollow`،
  رابط canonical، أو محتوى JSON-LD — هذي دائمًا مبنية من الكود، لا من
  مدخلات نموذج مباشرة.

## 16) النموذج الدلالي للكيانات (Entity Model)

المسار البرمجي (Track) هو **الكيان الأساسي** بالموقع — مو الجامعة:

```
Track → Lesson → (Reference entries ذات الصلة) → Quiz → (Roadmap يحتوي المسار)
```

قسم الجامعات (`academic-universities` + `academic-study-plans`) كيان
**فرعي مستقل** بنفس الأهمية التقنية لكن نطاق أضيق حاليًا (بيانات حقيقية
لجامعة واحدة فقط لهلق، البقية أسماء بدون محتوى — التفاصيل بـ
[`docs/curriculum-pipeline-audit.md`](curriculum-pipeline-audit.md)):

```
Country → University → Specialization → (Study Plan إذا وُجد)
```

**لا تخلط الاثنين** عند بناء الربط الداخلي أو الـbreadcrumbs — كل سلسلة
لها منطقها، والمسارات هي يلي بتحمل غالبية الزيارات والمحتوى فعليًا.

## جدول الفحوصات الكاملة (`run-ci.cmd`)

| الفحص | الأمر | ماذا يمنع |
|---|---|---|
| اختبارات الوحدة | `npm test` (عبر tsx) | كسر منطق الـpipeline |
| روابط داخلية مكسورة | `check:links` | 404 لصفحات مفهرسة |
| ترتيب دروس الخلاصة | `check:summary-order` | تنقّل خاطئ داخل المسار |
| وصف/ترتيب ناقص (تراكات) | `check:frontmatter` | صفحات بلا meta description |
| حقول ناقصة (مدونة/مرجع) | `check:blog-ref` | نفس الشيء لصفحات المدونة/المرجع |
| H1 مكرّر | `check:redundant-h1` | عنوانين H1 بنفس الصفحة |
| روابط `related[]` مرجعية | `check:ref-related` | روابط "ذات صلة" تختفي بصمت |
| تنافس كلمات مفتاحية (مرجع) | `check:ref-keywords` | (إعلامي) تنافس داخلي على نية بحث واحدة |
| سلامة الاختبارات | `check:quizzes` | إجابة بفهرس خاطئ/خيارات مكرّرة |
| سلامة خرائط الطريق | `check:roadmaps` | إشارة لمسار غير موجود |
| سلامة الجامعات | `check:academic` | سلق جامعة مكرّر |
| سلامة مواد أكاديمية | `check:academic-courses` | إشارة لمسار غير موجود |
| مقالات مدونة يتيمة | `check:orphan-blog` | مقال بلا أي مسار اكتشاف داخلي |
| دروس منشورة بلا تحويل | `check:lesson-redirects` | رابط درس كان منشور صار 404 |

كل هذي (عدا الاثنين المُعلَّمين "إعلامي") **توقف الـCI** لو لقت مشكلة —
مش تحذيرات تُتجاهل.
