# ADR 0001 — Monorepo بـ npm workspaces + Turborepo

- **الحالة:** مقترح (فرع `thecodefix-v2`)
- **التاريخ:** 2026-10-16

## السياق

V1 كان تطبيق Next.js واحد، كل الكود بـ `src/`. التوسع المطلوب (لغات، موبايل، فيديو، اشتراكات، جامعات) بيحتاج أكثر من «تطبيق» واحد يشارك نفس المنطق: الموقع اليوم، API للموبايل، وربما لوحة إدارة منفصلة بكرا.

## القرار

- **npm workspaces** (نفس مدير الحزم الحالي، نفس `package-lock.json`، بدون تغيير على أجهزة الفريق أو `run-ci.cmd`): `apps/*`، `packages/*`، `modules/*`.
- **Turborepo** فوقها لتنظيم المهام وكاشها (`turbo.json`)، بإعدادات الوثائق المرفقة مع النسخة المثبتة (الـ skill `turborepo`).
- **حزم «Just-in-Time»:** كل حزمة بتصدّر مصدر TypeScript مباشرة (`exports: { "./*": "./src/*.ts", "./ui/*": "./src/ui/*.tsx" }`). Next.js/Turbopack وtsx وtsc بيترجموها وقت الاستخدام — ما في خطوة بناء لكل حزمة.
- **بدون barrel files:** الاستيراد دايمًا لملف محدد (`@tcf/content/tracks`) مش لـ `index.ts` بيجمّع كل إشي — حسب قاعدة `bundle-barrel-imports` من skill Vercel للأداء.
- **`envMode: "loose"`** بالبداية مع قائمة `env` كاملة للـ hash: بيضمن إنه البناء بيشوف نفس متغيرات البيئة اللي كان يشوفها V1. الانتقال لـ strict لاحقًا بعد التحقق على Vercel.
- كل حزمة بتعلن اعتمادياتها الحقيقية (محسوبة من الكود: `npm run workspaces:sync`). الجذر لسا فيه كل الاعتماديات (انتقالي) — npm بيرفعها لنفس `node_modules`.

## البدائل

| البديل | ليش لا |
|---|---|
| pnpm workspaces | أدق بعزل الاعتماديات، بس بيغيّر أداة الفريق وملف القفل دفعة وحدة مع إعادة الهيكلة. ممكن لاحقًا كخطوة لحالها. |
| حزم مبنية (tsup/dist) | خطوة بناء لكل حزمة بدون فائدة حقيقية طالما المستهلكين كلهم TypeScript. |
| Nx | أقوى بس أثقل؛ Turborepo كافي ومدعوم رسميًا من Vercel. |

## التحقق

`npm install` بيربط 19 حزمة تحت `node_modules/@tcf/*`؛ `tsc --noEmit` على كل المستودع = 0 أخطاء؛ البناء الإنتاجي بيولّد نفس الـ 3,967 صفحة.
