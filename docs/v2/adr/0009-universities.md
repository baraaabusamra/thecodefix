# ADR 0009 — الجانب الأكاديمي للجامعات

- **الحالة:** مقترح — تصميم
- **التاريخ:** 2026-10-16

## السياق

V1 فيه `@tcf/academic`: دول ← جامعات ← تخصصات ← خطط دراسية (بيانات حقيقية لجامعة وحدة حاليًا)، وخط استخراج مناهج مع مراجعة بشرية إلزامية (`docs/factual-data-governance.md`). V2 بده جانب أكاديمي «خاص بالجامعات»: حسابات للجامعة، طلاب، ومتابعة.

## القرار

- **المؤسسة كيان بـ `@tcf/identity`** (جدول `organizations` موجود أصلًا بـ `packages/db/src/schema/billing.ts` للمقاعد): الجامعة = مؤسسة بنوع `university`.
- **أدوار مؤسسية** فوق RBAC الحالي: `org:admin`، `org:instructor`، `org:student` — بتنفحص بنفس بوابة `requireCapability` بعد توسيعها لسياق مؤسسة.
- **مقاعد الجامعة = استحقاقات** (ADR 0008) بمصدر `organization`.
- **المحتوى:** مسارات الجامعة الخاصة بـ `content/<locale>/…` مع `visibility: org:<id>`، أو من الـ CMS (قاعدة البيانات) — نفس قارئ `@tcf/content` مع فلترة الرؤية.
- **البيانات الحقيقية** (الخطط الدراسية) بتضل تحت حوكمة البيانات الحقيقية: مصدر، تاريخ تحقق، مراجعة بشرية.
- الحدود: `@tcf/academic` ما بيستورد `@tcf/billing`؛ الاستحقاق بيتفحص عبر واجهة بـ `@tcf/identity` أو حزمة استحقاقات أساس (يُقرَّر وقت التنفيذ بـ ADR).

## خطوات التنفيذ

1. نوع مؤسسة + أدوار مؤسسية + اختبارات مصفوفة صلاحيات (على نمط `rbac-matrix`).
2. لوحة جامعة (طلاب، تقدّم) كصفحات بـ `apps/web/src/app/org/…` أو تطبيق منفصل.
3. ربط المقاعد بالاستحقاقات.
