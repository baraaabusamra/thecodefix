## 0) القرارات الحاكمة (تُغيّر كل ما تحته)

| المحور | القرار | الأثر على الخطة |
|---|---|---|
| **الهدف التجاري** | ترافيك + بناء علامة (لا Pro/تراخيص الآن) | "صفحات المال" = صفحات محورية تجمع السلطة؛ المقياس = زيارات عضوية + بحث عن العلامة |
| **الفيديو** | مكتوب فقط (لا يوتيوب) | نستهدف عمدًا كلمات نتائجها **مكتوبة**، ونتجنّب ما يسيطر عليه يوتيوب |
| **Google Search Console** | موصول سابقًا؛ **لا تصدير بيانات حيّ متاح بهذا التحديث** | لا نفترض عدد نقرات/ظهور/فهرسة فعلية — TBD حتى تصدير فعلي. رقم sitemap الحي الحالي (بنية/عدد الروابط، ليس بيانات GSC): **2,641 رابطًا بتاريخ 2026-09-05** (تاريخيًّا: 3,636 بتاريخ 2026-08-28، قبل تفعيل بوابة الفهرسة الأكاديمية أدناه) |
| **المؤلّف / E-E-A-T** | علامة فقط (بلا مؤلّف شخصي) | نبني إشارات الخبرة **مؤسسيًا**: صور أصلية، تواريخ، منهجية، schema المنظّمة — **بشرط أن تعكس الحقيقة فعليًّا** (راجع 0.5 نقطة 5) |
| **بوابة أهلية الفهرسة الأكاديمية** | **منفَّذة ومُتحقَّق منها** (`isStudyPlanPublishable`، `src/lib/academic-indexability.ts`) — صفحة `/academic/<دولة>/<جامعة>/<تخصص>` لا تدخل الـ sitemap إلا بخطة دراسة حقيقية منشورة لتلك الجامعة | حسمت القرار الذي كان مفتوحًا سابقًا (كانت 1,038 صفحة تعرض محتوى احتياطي مشترك بتاريخ 2026-08-28؛ اليوم رابط تخصّص واحد فقط مفهرس) — راجع مبدأ "فهرسة الصفحات ذات الأولوية" أدناه لكيف يُستخدَم هذا كمثال ناجح |

## 0.5) التوجيه الحاكم الحالي (Master Direction — سبتمبر 2026)

كل قرار SEO أدناه يُختبَر أولًا مقابل هذه المبادئ الستة، بالترتيب:

1. **القياس أولًا (Measurement first).** لا قرار محتوى/فهرسة جديد بلا بيانات
   GSC فعلية تدعمه. إن لم تتوفّر، الفعل الصحيح هو تصدير البيانات
   (`seo-baseline-template.md`)، لا التخمين.
2. **تحسين/دمج قبل إنشاء رابط جديد.** أي صفحة جديدة تمرّ أولًا باختبار وجود
   الصفحة الستة (`content-guidelines.md` §7). التوسّع الأخير في المسارات
   (من 31 إلى 51) يعني أولوية قريبة هي **تقوية/دمج** المسارات الـ20 الجديدة
   (لا اختبار لها بعد، مرجع محدود) قبل أي مسار #52.
3. **فهرسة الصفحات ذات الأولوية، لا فرض فهرسة الكتلة الكاملة.** مثال مُطبَّق
   فعليًّا لا نظري: صفحات `/academic/*` كانت 1,038 رابطًا بمحتوى احتياطي
   مشترك غير مُميَّز لكل جامعة (تدقيق 2026-08-28). بدل دفعها كلها للفهرسة،
   أُضيفت بوابة أهلية (`isStudyPlanPublishable`) تستثني أي صفحة تخصّص بلا
   خطة دراسة حقيقية — النتيجة اليوم (2026-09-05): **رابط تخصّص واحد فقط**
   بالـ sitemap، والباقي محجوب حتى تُنشَر خطط حقيقية له. طبّق نفس المنطق على
   أي كتلة محتوى مستقبلية: ادفع GSC's Request Indexing نحو الصفحات المحورية
   والمقالات القوية القائمة فعليًّا فقط، لا الكتلة الكاملة.
4. **محتوى للناس أولًا (People-first).** كل صفحة تُبنى لتُجيب سؤال متعلّم
   حقيقي، لا لتغطية مصفوفة كلمات مفتاحية آليًّا (نفس مبدأ
   `content-guidelines.md` §2-3، مؤكَّد هنا كأولوية SEO أيضًا).
5. **صدق إشارات التأليف/المراجعة.** لا تُعرَض بيانات مسودة (خطط دراسة
   مستخرَجة آليًّا لم تجتز `pipelineReviewQueue`) على أنها محتوى نهائي موثوق
   — هذا المبدأ **مُطبَّق آليًّا الآن** لصفحات `/academic` عبر بوابة
   `isStudyPlanPublishable` (راجع القسم 0 أعلاه)، لا مجرّد توصية. حقل
   `updated` لا يتغيّر إلا مع تعديل حقيقي (already codified in
   `seo-technical-policy.md` §13) — لا "تنشيط" مصطنع.
6. **حلقات قياس 14/28 يومًا متكرّرة، لا موعد واحد منتهي.** استبدلت "مراجعة
   14 يوليو" (قسم 5 القديم) — كل 14 يومًا: مراجعة أداء سريعة (فهرسة + صفحات
   مركز 5-20)؛ كل 28 يومًا: مراجعة كاملة (CWV، اتجاه الكلمات، قرار محتوى
   تالٍ) باستخدام `seo-baseline-template.md` كأداة تشغيل ثابتة لكل دورة.

## 1) الفلسفة (Reality Checks)

- **لا أحد يضمن المركز #1.** نبني أكبر عدد من "شروط الفوز" لأعلى احتمال.
- **لن نربح** الكلمات المشبعة (`تعلم البرمجة`, `جافاسكريبت`) — مسيطر عليها منافسون كبار (حسوب، Elzero، إدراك...).
- **سنربح** الذيل الطويل منخفض المنافسة: `الفرق بين X و Y بالعربي` · `حل خطأ X بالعربي` · `ما هي X`.
- **الأولوية > التنفيذ.** لا نحتاج #1 لكل كلمة؛ نرتّب بصرامة حسب الموارد.

---

## 2) الخطوة 1 — النية + الشكل (فلتر ما قبل الكتابة)

بما أننا **مكتوب فقط**، قبل استهداف أي كلمة نفحص SERP العربي:

- **SERP مكتوب** (مقالات/جداول/W3Schools-style) → اكتب، الفرصة موجودة. ✅
- **SERP يسيطر عليه يوتيوب** (شائع في `كيف/شرح`) → تجاهل أو توقّع سقفًا منخفضًا. ⚠️
- ركّز على النوايا المكتوبة: `ما هي` · `الفرق بين` · `حل خطأ` · `تعريف` · `مقارنة`.
- طابق **نية جوجل المفترضة** (ماذا يظنّ جوجل أنّ الباحث يريد)، لا فهمك الشخصي فقط.

**توافقك الحالي ممتاز:** مقدمات "ما هي X" (نية تعريفية) · مقالات "الفرق بين" (مقارنة) · مقالات الأخطاء (استكشاف أخطاء).

---

## 3) الخطوة 2 — أفضل صفحة + E-E-A-T (أضعف نقطة = أقوى عامل)

**عدد الكلمات ليس عامل ترتيب** — السؤال: هل غطّيت ما يحتاجه الباحث كاملًا؟

بما أن المؤلّف **علامة**، نبني الخبرة (Experience — أثقل عامل اليوم) مؤسسيًا:

1. **صور أصلية** — سكرين‑شوت مخرجات الكود/الطرفية + دياغرام توضيحي. ولو واحدة لكل صفحة محورية/مقدّمة. *(الفجوة الأكبر حاليًا.)*
2. **تواريخ ظاهرة** — "نُشر" + "آخر تحديث" على الدروس والمقالات + `dateModified` في schema.
3. **بنية متّسقة + TLDR** — صندوق "باختصار" أعلى مقالات المقارنة/الأخطاء + جدول مقارنة موحّد + خلاصة/حكم (يوحي بمنهجية).
4. **TOC ظاهر** — تفعيل "على هذه الصفحة" للجوال في المقالات الطويلة (حاليًا xl+ فقط).
5. **إشارات مؤسسية** — صفحة "من نحن" + org author + شعار في schema (موجود جزئيًا).

**ما هو منجَز فعلًا (يوليو 2026):** روابط خارجية DoFollow لكل الدروس والمقالات · صورة داخل كل درس بـalt غنيّ بالكلمة · عناوين keyword‑first · إغناء 31 درس مقدّمة · إصلاحات تقنية (noindex للبحث، robots، sitemap، H2 الرئيسية).

---

## 4) الخطوة 3 — Topical Authority + الروابط الداخلية (نقطة القوة)

- بنية العناقيد والربط الداخلي **قوية أصلًا** (51 مسارًا + sidebar/related/breadcrumbs). نوجّهها لتصبّ في **صفحات محورية (Pillars)**:
  - الـPillar = صفحة المسار `/learn/<tech>` → هَب شامل يربط كل دروس + مقالات مقارنة + مقالات أخطاء اللغة.
  - كل درس/مقال يربط **لأعلى** للـPillar بنصّ رابط وصفي (لا "التالي" فقط).
- **أفضل رهان محتوى:** توسعة **عنقود مقالات الأخطاء** (`حل خطأ X بالعربي`) — تكرار عالٍ + منافسة منخفضة + شكل مكتوب + يناسب هدف الترافيك. (الفجوة المفتوحة في [دليل الكلمات](seo-keywords.md).)
- **الباك‑لينكس لاحقًا:** ابنِ السلطة الموضوعية أولًا. لموقع عربي جديد، الروابط الطبيعية من: مجتمعات المطوّرين العربية، صفحات موارد الجامعات/البوتكامبات، والإجابة في المنتديات برابط لمحتواك (يناسب مرحلة التوزيع).

## 5) الجدول الزمني (Timeline) — حلقات متكرّرة، لا موعد واحد

نسخة يوليو من هذا القسم كانت تبني كل شيء حول موعد واحد ("14 يوليو") انقضى
منذ أشهر بلا مراجعة بيانات فعلية موثّقة هنا. البديل الحالي (مبدأ 0.5 نقطة 6):

### كل 14 يومًا (مراجعة سريعة)
1. **GSC — تسريع الفهرسة:** `URL Inspection → Request Indexing` لأهم ~15
   صفحة من القائمة المحورية/المقالات القوية القائمة فعليًّا. صفحات
   `/academic/*` لم تعد بحاجة استبعاد يدوي — بوابة `isStudyPlanPublishable`
   تستثني غير المؤهَّل منها تلقائيًّا من الـ sitemap نفسه (مبدأ 0.5 نقطة 3).
2. **GSC — راقب الفهرسة:** تقرير Pages — Indexed مقابل Not-indexed
   (بتفصيل السبب، ليس فقط الإجمالي). سجّل الرقم في
   `seo-baseline-template.md`، لا هنا (هذا الملف استراتيجية، لا سجلّ بيانات).
3. **فرص سريعة:** صفحات بمركز 5–20 (GSC Performance) = ضربة صغيرة
   (عنوان/إغناء/رابط داخلي) بأعلى ROI — حسّن، لا تبنِ جديدًا.

### كل 28 يومًا (مراجعة كاملة)
1. Core Web Vitals (mobile/desktop) + اتجاه النقرات/الظهور/CTR (فرعي حسب
   العلامة مقابل غير العلامة إن توفّر الفصل).
2. قرار المحتوى التالي: عنقود الأخطاء أولًا (أفضل رهان مكتوب/منخفض المنافسة)
   إلا إن أظهرت البيانات فرصة أعلى تحديدًا.
3. **مراقبة انحدار بوابة `/academic`:** تأكّد أن عدد روابط التخصّص بالـ
   sitemap يبقى مطابقًا لعدد خطط الدراسة الحقيقية المنشورة فقط (لا يعود
   يظهر محتوى احتياطي مشترك بالخطأ) كلّما نُشرت خطة جديدة.

### مستمر
- **E-E-A-T:** صور أصلية + تواريخ ظاهرة + `dateModified` + TLDR + TOC للجوال
  للصفحات الجديدة والمُحدَّثة — حالة الإنجاز الفعلية لكل بند **لم تُعَد
  التحقّق منها بهذا التحديث**؛ تحقّق مباشرةً من القوالب قبل افتراض الاكتمال.
- تحديث المحتوى دوريًا (refresh) · بناء العناقيد حول كل Pillar · Outreach
  للباك‑لينكس بعد بناء السلطة.
