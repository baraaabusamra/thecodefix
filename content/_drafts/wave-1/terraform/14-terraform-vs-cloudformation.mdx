كلاهما أداة بنية تحتية كرمز تصريحية، فأيّهما تختار؟ يعتمد الجواب أساسًا على مدى ارتباطك بـ AWS. تبني هذه الصفحة على [المزوّدين في Terraform](/learn/terraform/03-providers).

## الفرق الجوهري: النطاق

- **CloudFormation**: خدمة أصلية من AWS، **تدير موارد AWS فقط**. متكاملة بعمق مع AWS.
- **Terraform**: أداة مستقلّة **متعدّدة المنصّات**؛ بالمنطق واللغة نفسها تدير AWS و Azure و Google Cloud وغيرها عبر [المزوّدين](/learn/terraform/03-providers).

هذا هو المحور الأهمّ في القرار: هل أنت داخل AWS حصريًا، أم تتعامل مع عدّة سحابات؟

## جدول المقارنة

| | Terraform | CloudFormation |
|---|---|---|
| النطاق | متعدّد المنصّات | AWS فقط |
| اللغة | HCL | YAML / JSON |
| الحالة | يديرها بنفسه (State) | يديرها AWS نيابةً عنك |
| النظام البيئي | وحدات ومزوّدون من مجتمع واسع | تكامل عميق مع خدمات AWS |
| التكلفة | مجّاني (النواة) | مجّاني (تدفع للموارد فقط) |

## اعتبارات إضافية

- **الحالة**: Terraform يجعلك تدير [ملفّ الحالة](/learn/terraform/02-state) (محلّي أو بعيد)، بينما يخفي CloudFormation ذلك ويديره AWS.
- **النظام البيئي**: Terraform يملك مجتمعًا ضخمًا ووحدات جاهزة عبر المنصّات؛ CloudFormation يتفوّق في سرعة دعم أحدث ميزات AWS.

## كيف تختار؟

- **AWS حصريًا وتريد تكاملًا أصيلًا وأقلّ إدارة للحالة؟** → CloudFormation خيار وجيه.
- **عدّة سحابات، أو تريد أداة ولغة موحّدة عبرها، أو نظامًا بيئيًا أوسع؟** → Terraform.

كثير من الفرق يختار Terraform لمرونته عبر المنصّات حتى داخل AWS، لكنّ الخيار يعتمد على سياقك.
