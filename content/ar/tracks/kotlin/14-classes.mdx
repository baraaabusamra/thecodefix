## صنف بباني أساسي

```kotlin
class Person(val name: String, var age: Int) {
    fun greet() = "أهلًا $name"
}

val p = Person("براء", 25)
println(p.name)        // براء
p.age = 26             // var قابل للتعديل
println(p.greet())
```

> 💡 تعريف الخصائص يتمّ مباشرة في الباني — أوجز بكثير من Java.

لاحظ الفرق بين `val`/`var` داخل القوسين وبدونها:

```kotlin
class A(val name: String)   // name خاصية في الكائن: a.name ✅
class B(name: String)       // name معامل للباني فقط: b.name ❌ خطأ ترجمة
```

بدون `val` أو `var`، القيمة متاحة فقط أثناء الإنشاء (في `init` وفي تعريف الخصائص)، ولا تُحفظ في الكائن.

ولا حاجة لكلمة `new`: `Person("براء", 25)` تنشئ الكائن مباشرة.

## كتلة init

```kotlin
class User(val email: String) {
    init {
        require(email.contains("@")) { "بريد غير صالح" }
    }
}
```

الباني الأساسي لا جسم له، فأي كود يجب أن يعمل لحظة الإنشاء (تحقّق من المدخلات، تجهيز قيمة) يوضع في `init`. هنا `User("خطأ")` يرمي `IllegalArgumentException` فورًا، فلا يمكن أن يوجد كائن `User` ببريد غير صالح في أي مكان من البرنامج.

## خصائص بقيم محسوبة

```kotlin
class Rectangle(val w: Int, val h: Int) {
    val area: Int
        get() = w * h
}
```

`area` لا تُخزَّن، بل تُحسب **كل مرة** تقرأها، فتبقى صحيحة دائمًا مع `w` و`h`.

### setter مخصّص

لتتحكّم بما يُكتب في خاصية، اكتب `set`. داخلها، `field` هي القيمة المخزّنة فعليًا:

```kotlin
class Account {
    var balance: Int = 0
        set(value) {
            require(value >= 0) { "الرصيد لا يكون سالبًا" }
            field = value
        }
}

val acc = Account()
acc.balance = 100   // ✅
acc.balance = -5    // ❌ IllegalArgumentException
```

> ⚠️ داخل `set` اكتب `field = value` لا `balance = value`؛ الثانية تستدعي الـ setter نفسه من جديد بلا نهاية وتنتهي بـ `StackOverflowError`.

## بانٍ ثانوي

```kotlin
class Box(val size: Int) {
    constructor() : this(0)   // باني افتراضي
}
```

كل باني ثانوي يجب أن يستدعي الأساسي بـ `this(...)`. لكن في أغلب الحالات لا تحتاجه أصلًا: قيمة افتراضية في الباني الأساسي تؤدي نفس الغرض بسطر أقل:

```kotlin
class Box(val size: Int = 0)   // Box() و Box(5) كلاهما يعمل
```

## الأصناف مغلقة افتراضيًّا

كل صنف في Kotlin `final` ما لم تقل غير ذلك: لا أحد يقدر يرث منه. هذا مقصود، لأن الوراثة من صنف لم يُصمَّم لها تكسر بسهولة. التفاصيل وكلمة `open` في الدرس القادم.

## أخطاء شائعة

- **نسيان `val` في الباني:** يصبح المعامل غير متاح كخاصية.
- **`balance = value` داخل الـ setter:** استدعاء ذاتي لا ينتهي؛ استخدم `field`.
- **باني ثانوي حيث تكفي قيمة افتراضية:** كود أطول بلا فائدة.
