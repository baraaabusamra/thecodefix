## data class

لحمل البيانات؛ يولّد Kotlin تلقائيًّا دوال مفيدة:

```kotlin
data class User(val name: String, val age: Int)

val u = User("براء", 25)
println(u)              // User(name=براء, age=25) ← toString تلقائي
```

## ماذا يتغيّر بكلمة data؟

نفس الصنف بدون `data`:

```kotlin
class Plain(val name: String, val age: Int)

val p1 = Plain("براء", 25)
val p2 = Plain("براء", 25)
println(p1)          // Plain@1b6d3586 — عنوان في الذاكرة، لا القيم
println(p1 == p2)    // false — يقارن المرجع
```

مع `data`، نفس السطرين يطبعان `User(name=براء, age=25)` و`true`. هذا كل الفرق: Kotlin تكتب عنك دوالًا كنت ستكتبها يدويًّا (وتنسى تحديثها حين تضيف خاصية).

## ما يُولَّد تلقائيًّا

- `toString()` مقروء.
- `equals()` / `hashCode()` (مقارنة بالقيم).
- `copy()` لنسخ مع تعديل.
- `componentN()` للتفكيك.

## المقارنة بالقيمة

```kotlin
val a = User("براء", 25)
val b = User("براء", 25)
println(a == b)         // true (نفس القيم)
```

## copy

```kotlin
val older = u.copy(age = 26)   // نسخة بتعديل العمر فقط
```

لماذا `copy` بدل تعديل الكائن؟ لأن خصائص data class تكون غالبًا `val`، والكائن لا يتغيّر بعد إنشائه. هذا يجعل تتبّع الحالة أسهل: إذا مرّرت `u` لدالة، فأنت متأكد أنها لن تغيّره من تحتك.

> ⚠️ `copy` نسخة **سطحية**: إذا كانت إحدى الخصائص قائمة قابلة للتعديل (`MutableList`)، تتشارك النسختان نفس القائمة.

## التفكيك (Destructuring)

```kotlin
val (name, age) = u
println("$name - $age")
```

## انتبه: فقط خصائص الباني الأساسي تُحسب

`equals` و`toString` و`copy` و`componentN` تُبنى من الخصائص المعرّفة **داخل قوسي الباني** فقط. أي خاصية في جسم الصنف تُتجاهَل:

```kotlin
data class Product(val id: Int) {
    var views = 0                 // ليست في الباني
}

val a = Product(1).apply { views = 10 }
val b = Product(1).apply { views = 99 }
println(a == b)    // true — views لا تدخل في المقارنة
println(a)         // Product(id=1)
```

## القيود

- يجب أن يحتوي الباني الأساسي على خاصية واحدة على الأقل.
- كل معاملات الباني الأساسي يجب أن تكون `val` أو `var`.
- لا يكون `abstract` ولا `open` ولا `sealed` ولا `inner`.

> 💡 استخدم data class لأي صنف وظيفته حمل البيانات (DTO، نماذج).

## أخطاء شائعة

- **وضع خاصية مهمة في جسم الصنف:** لا تدخل في `equals`، فيُعتبر كائنان مختلفان متساويين.
- **data class لكائنات لها سلوك وهوية:** حساب بنكي له معرّف فريد لا يكون "مساويًا" لحساب آخر لأن أرصدتهما متطابقة. data class للبيانات، والصنف العادي للكيانات.
- **`var` في data class مستخدمة كمفتاح في `HashMap` أو `HashSet`:** تعديلها بعد الإضافة يغيّر الـ `hashCode` فيضيع العنصر داخل المجموعة.
