## ما هو CI/CD؟

**CI (Continuous Integration)** — التكامل المستمر: دمج تغييرات الكود في المستودع الرئيسي بشكل متكرر، مع تشغيل اختبارات آلية لكل تغيير.

**CD (Continuous Delivery / Deployment)** — التسليم أو النشر المستمر: أتمتة عملية نشر التطبيق بعد اجتياز الاختبارات.

> ⚠️ لا تخلط بين التسليم المستمر (Continuous Delivery) والنشر المستمر (Continuous Deployment). الأول يتطلب موافقة يدوية للنشر، والثاني ينشر تلقائياً.

## مكونات Pipeline أساسية

```yaml
# مثال توضيحي لخط أنابيب CI/CD
pipeline:
  stages:
    - build
    - test
    - deploy
```

## مراحل Pipeline نموذجية

1. **Build** — بناء التطبيق وتجميعه
2. **Test** — تشغيل اختبارات الوحدة والتكامل
3. **Analyze** — تحليل جودة الكود
4. **Package** — إنشاء حزمة قابلة للنشر
5. **Deploy** — النشر إلى البيئة المستهدفة

## فوائد CI/CD

- اكتشاف الأخطاء مبكراً قبل وصولها إلى الإنتاج
- تقليل الوقت المستغرق في المراجعة اليدوية
- تسليم إصدارات أكثر استقراراً
- أتمتة المهام المتكررة لتوفير وقت الفريق

## مثال Pipeline نصي

```bash
# خطوات أساسية في أي pipeline
git clone https://github.com/user/project.git
cd project
npm install
npm run build
npm test
```
