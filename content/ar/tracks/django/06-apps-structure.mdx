## المشروع مقابل التطبيق

- **المشروع (project):** الموقع كاملًا: الإعدادات، وجدول المسارات الرئيسي، وقاعدة البيانات.
- **التطبيق (app):** وحدة **وظيفية** واحدة بنماذجها وعروضها وقوالبها: المدوّنة، والمتجر، والحسابات، والإشعارات.

المشروع يحتوي عدّة تطبيقات، وحتى Django نفسه مبني هكذا: لوحة الإدارة (`django.contrib.admin`) ونظام المستخدمين (`django.contrib.auth`) تطبيقات تجدها مسجّلة مسبقًا في `INSTALLED_APPS`.

## إنشاء تطبيق

```bash
python manage.py startapp blog
```

```text
blog/
├── __init__.py
├── admin.py       تسجيل النماذج في لوحة الإدارة
├── apps.py        إعداد التطبيق (اسمه، وكود يعمل عند الإقلاع)
├── migrations/    ملفات ترحيل قاعدة البيانات (تُولَّد تلقائيًا)
│   └── __init__.py
├── models.py      نماذج البيانات (الجداول)
├── tests.py       الاختبارات
└── views.py       العروض: المنطق الذي يردّ على الطلبات
```

ستضيف بنفسك عادة:

```text
blog/
├── urls.py                   مسارات التطبيق
├── forms.py                  النماذج (Forms)
└── templates/blog/           قوالب HTML
    └── post_list.html
```

لاحظ التكرار في `templates/blog/`: Django يجمع قوالب **كل** التطبيقات في مساحة أسماء واحدة. لو كتبت `templates/list.html` في تطبيقين، سيختار Django أول واحد يجده فقط. المجلّد الفرعي باسم التطبيق يجعل القالب `blog/post_list.html` فريدًا.

## تسجيل التطبيق

إنشاء المجلّد وحده لا يكفي. Django لا يعرف التطبيق حتى تضيفه:

```python
# mysite/settings.py
INSTALLED_APPS = [
    "django.contrib.admin",
    "django.contrib.auth",
    "django.contrib.contenttypes",
    "django.contrib.sessions",
    "django.contrib.messages",
    "django.contrib.staticfiles",
    "blog",                      # تطبيقك
]
```

بدون التسجيل: `makemigrations` لا ترى نماذجه، وقوالبه لا تُكتشف، ولوحة الإدارة تتجاهله، وكل ذلك **بلا رسالة خطأ واضحة**.

## كيف أقسّم مشروعي؟

السؤال الذي يساعدك: "هل أستطيع وصف هذا التطبيق بجملة واحدة بلا كلمة و؟"

- ✅ `blog`: المقالات والتعليقات عليها.
- ✅ `accounts`: التسجيل والملف الشخصي.
- ✅ `orders`: الطلبات والدفع.
- ❌ `core` أو `main` فيه كل شيء: يصبح بعد سنة ملفًا من ثلاثة آلاف سطر.

ولا تبالغ في التقسيم أيضًا: تطبيق لكل نموذج يجعل العلاقات بين التطبيقات متشابكة. ابدأ بتطبيقات قليلة واضحة، وقسّم حين يكبر أحدها فعلًا.

## ربط مسارات التطبيق بالمشروع

```python
# blog/urls.py (أنشئه بنفسك)
from django.urls import path
from . import views

app_name = "blog"
urlpatterns = [
    path("", views.post_list, name="post_list"),
]
```

```python
# mysite/urls.py
from django.contrib import admin
from django.urls import include, path

urlpatterns = [
    path("admin/", admin.site.urls),
    path("blog/", include("blog.urls")),
]
```

المشروع يفوّض كل ما يبدأ بـ `blog/` لملف مسارات التطبيق. هكذا يبقى كل تطبيق مستقلًا بمساراته، ويمكن نقله لمشروع آخر بتغيير سطر واحد. التفاصيل في [درس المسارات](/learn/django/12-urls-routing).

## أخطاء شائعة

- **نسيان إضافة التطبيق لـ `INSTALLED_APPS`:** نماذج بلا جداول وقوالب لا تُوجد، بلا خطأ صريح.
- **قوالب بلا مجلّد فرعي باسم التطبيق:** تعارض أسماء بين التطبيقات، فيظهر القالب الخطأ.
- **تطبيق باسم مكتبة أو وحدة Python** (`email` أو `json` أو `test`): تعارض في الاستيراد.
- **تطبيق واحد لكل المشروع:** يصعب فهمه واختباره.
- **استيراد دائري بين تطبيقين:** `blog.models` تستورد `orders.models` والعكس. في العلاقات استخدم النص `"orders.Order"` بدل الاستيراد.
