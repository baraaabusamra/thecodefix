## المشكلة التي تحلّها الملكية

كل برنامج يحجز ذاكرة ويجب أن يحرّرها. اللغات حلّت هذا بطريقتين:

- **يدويًا** (C و C++): أنت تحرّر بـ `free`. سريع، لكن نسيان التحرير تسرّب، والتحرير مرّتين أو الاستخدام بعده ثغرات أمنية.
- **جامع النفايات** (Java وGo وPython): برنامج مساعد يبحث عن الذاكرة غير المستخدمة ويحرّرها. آمن، لكن له كلفة وتوقّفات غير متوقّعة.

Rust تختار طريقًا ثالثًا: **قواعد يتحقّق منها المترجم**، فيعرف بالضبط متى تنتهي كل قيمة ويضع التحرير بنفسه. أمان جامع النفايات بسرعة C، والثمن تعلّم القواعد.

## القواعد الثلاث

1. لكل قيمة **مالك** واحد (متغيّر).
2. مالك واحد فقط في كل لحظة.
3. حين يخرج المالك من النطاق (`}`)، تُحرَّر القيمة تلقائيًا.

```rust
{
    let s = String::from("مرحبًا");   // s تملك النص
    println!("{s}");
}   // هنا تنتهي s، فيُحرَّر النص تلقائيًا (Rust تستدعي drop)
// s غير موجودة هنا
```

## النقل (Move)

```rust
let s1 = String::from("مرحبًا");
let s2 = s1;            // الملكية انتقلت إلى s2
// println!("{s1}");    // ❌ borrow of moved value: `s1`
println!("{s2}");       // ✅
```

لماذا لا تُنسخ؟ `String` من ثلاثة أجزاء على المكدّس (مؤشّر، وطول، وسعة) والحروف نفسها على الكومة. `let s2 = s1` تنسخ الأجزاء الثلاثة فقط، فيصبح لدينا مؤشّران لنفس الحروف. لو بقي الاثنان صالحين لحاول كلاهما تحرير الذاكرة نفسها عند انتهائه (double free). Rust تحلّ هذا بإبطال `s1`: المالك واحد دائمًا.

## النسخ الصريح: clone

```rust
let s1 = String::from("مرحبًا");
let s2 = s1.clone();    // نسخة كاملة جديدة على الكومة
println!("{s1} {s2}");  // ✅ الاثنان صالحان
```

`clone` واضحة في الكود عن قصد: حين تراها تعرف أن هناك نسخًا قد يكون مكلفًا. لا تضعها في كل مكان لإسكات المترجم؛ غالبًا الاستعارة هي الحل الصحيح.

## الأنواع Copy: تُنسخ تلقائيًا

```rust
let x = 5;
let y = x;             // نسخة: الأرقام صغيرة ورخيصة
println!("{x} {y}");   // ✅ كلاهما صالح
```

الأنواع البسيطة التي تعيش كلها على المكدّس تُنسخ بدل النقل: الأعداد، و`bool`، و`char`، والصفوف والمصفوفات المكوّنة منها فقط. هذه الأنواع تحقّق السمة `Copy`. أما `String` و`Vec` و`Box` وكل ما يملك ذاكرة على الكومة فتُنقل.

## الدوال والملكية

تمرير قيمة لدالة مثل الإسناد تمامًا: **نقل** أو **نسخ**:

```rust
fn takes(s: String) {
    println!("استلمت {s}");
}   // s تنتهي هنا ويُحرَّر النص

fn makes() -> String {
    String::from("جديد")       // الملكية تنتقل للمستدعي
}

fn main() {
    let s = String::from("hi");
    takes(s);
    // println!("{s}");        // ❌ s نُقلت إلى takes
    let t = makes();
    println!("{t}");
    let n = 5;
    println!("{}", n + 1);     // n من نوع Copy: لا مشكلة
}
```

نقل الملكية للدالة ثم إرجاعها في كل مرة سيكون مرهقًا. لهذا يوجد الحل الذي تستخدمه 90% من الوقت: **الاستعارة** بـ `&`، الدرس التالي.

## مثال حقيقي: من يملك الإعدادات؟

```rust
struct Config {
    name: String,
}

fn print_config(c: &Config) {      // تستعير: تقرأ فقط
    println!("الإعدادات: {}", c.name);
}

fn consume(c: Config) -> String {  // تأخذ الملكية: تحوّلها لشيء آخر
    format!("[{}]", c.name)
}

fn main() {
    let cfg = Config { name: String::from("prod") };
    print_config(&cfg);
    print_config(&cfg);            // ✅ ما زالت ملكنا
    let label = consume(cfg);      // انتقلت؛ لا نحتاجها بعد هذا
    println!("{label}");
}
```

تصميم التوقيع يقول للقارئ الكثير: `&Config` تعني "سأقرأ وأعيدها لك"، و`Config` تعني "سآخذها نهائيًا".

## أخطاء شائعة

- **"borrow of moved value":** استخدمت متغيّرًا بعد نقله. مرّر `&x` بدل `x`، أو `clone()` إن احتجت فعلًا نسختين.
- **`clone()` في كل مكان:** يعمل، لكنه يُخفي تصميمًا يحتاج استعارة، ويُبطئ البرنامج.
- **النقل داخل حلقة:** `for _ in 0..3 { takes(s); }` خطأ، لأن `s` تُنقل في الدورة الأولى.
- **ظنّ أن كل الأنواع تُنقل:** الأعداد و`bool` و`char` تُنسخ.
- **الصراع مع المترجم بدل قراءة الرسالة:** رسائل الملكية تشير للسطر الذي نُقلت فيه القيمة والسطر الذي استُخدمت فيه بعدها.
