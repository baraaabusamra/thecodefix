## ما هي العملية؟

البرنامج ملف على القرص. حين تشغّله يصبح **عملية** (process): نسخة تعمل في الذاكرة، لها رقم فريد (**PID**)، ومالك، واستهلاك معالج وذاكرة. وكل عملية لها **أب**: العملية التي شغّلتها (الـ Shell غالبًا)، وأصل الشجرة كلها عملية رقم 1 (`systemd` في التوزيعات الحديثة).

## عرض العمليات

```bash
ps aux                  # كل العمليات على النظام
ps aux --sort=-%mem | head -5   # أكثر 5 استهلاكًا للذاكرة
pgrep -a nginx          # PID ومعلومات عمليات nginx
ps -ef --forest         # شجرة العمليات: من شغّل من
```

أعمدة `ps aux` المهمة: `USER` المالك، و`PID`، و`%CPU` و`%MEM`، و`STAT` الحالة (`R` تعمل، و`S` نائمة تنتظر، و`Z` زومبي)، و`COMMAND`.

### top و htop: مراقبة حيّة

```bash
top          # داخله: M ترتيب بالذاكرة، P بالمعالج، k إيقاف عملية، q خروج
htop         # أوضح وأجمل، ويحتاج تثبيتًا: sudo apt install htop
```

أول سطر في `top` فيه **load average**: ثلاثة أرقام لمتوسّط الحِمل في آخر 1 و5 و15 دقيقة. قارنها بعدد الأنوية (`nproc`): إذا كان الرقم أكبر من عدد الأنوية باستمرار، فالمهام تنتظر دورها.

## إيقاف العمليات: الإشارات

`kill` لا "تقتل" بالضرورة؛ هي **ترسل إشارة**، والبرنامج يقرّر كيف يتصرّف:

```bash
kill 1234            # SIGTERM (15): "من فضلك انتهِ" — يحفظ ويغلق بنظام
kill -9 1234         # SIGKILL (9): إيقاف فوري تفرضه النواة، بلا تنظيف
kill -HUP 1234       # SIGHUP (1): كثير من الخوادم تعيد قراءة إعداداتها بها
pkill -f "node server.js"   # بالاسم أو سطر الأوامر بدل الرقم
```

**ابدأ دائمًا بـ `kill` العادية**، وانتظر ثوانٍ، ثم `-9` فقط إذا لم تستجب. لأن `SIGKILL` لا تعطي البرنامج فرصة لحفظ البيانات، أو حذف ملفاته المؤقتة، أو إغلاق اتصالات قاعدة البيانات بنظام، فقد تترك ملفات تالفة أو أقفالًا عالقة.

و`Ctrl+C` في الطرفية ترسل `SIGINT` للبرنامج الذي يعمل في المقدّمة.

## المقدّمة والخلفية

```bash
sleep 300 &          # & : شغّل في الخلفية وأعد المحثّ فورًا
jobs                 # المهام في هذه الجلسة: [1]+ Running sleep 300 &
fg %1                # أعدها للمقدّمة
# Ctrl+Z             # علّق المهمة الحالية (توقّفها مؤقتًا)
bg %1                # أكملها في الخلفية
```

سيناريو حقيقي: بدأت نسخًا طويلًا ونسيت `&`. اضغط `Ctrl+Z` (تعليق)، ثم `bg` (أكمل في الخلفية)، والطرفية لك من جديد.

## البقاء بعد إغلاق الجلسة

المهام في الخلفية تموت عادة حين تغلق الطرفية أو ينقطع SSH، لأنها تتلقّى `SIGHUP`. الحلول من الأبسط للأصحّ:

```bash
nohup ./long-task.sh > task.log 2>&1 &   # تتجاهل SIGHUP، والمخرجات إلى ملف
```

- **`nohup`**: لمهمّة لمرة واحدة.
- **`tmux` أو `screen`**: جلسة كاملة تبقى حيّة وتعود إليها لاحقًا ([درس tmux](/learn/linux/27-tmux-screen)).
- **خدمة systemd**: للخوادم والتطبيقات الدائمة، تعيد التشغيل تلقائيًا عند الانهيار أو إعادة الإقلاع ([درس الجدولة والخدمات](/learn/linux/20-cron-services)).

## مثال: المنفذ مشغول

```bash
# Error: listen EADDRINUSE: address already in use :::3000
sudo ss -tlnp | grep :3000     # من يستخدم المنفذ؟ يُظهر PID والبرنامج
kill 48213                     # أوقفه بلطف
```

## أخطاء شائعة

- **`kill -9` كأول خيار:** بيانات قد تتلف وملفات قفل تبقى. جرّب `kill` أولًا.
- **`ps aux | grep x` يجد نفسه:** يظهر سطر `grep x` في النتائج. استخدم `pgrep -a x`.
- **تشغيل خادم بـ `&` على خادم إنتاج:** يموت مع الجلسة ولا يعود بعد إعادة الإقلاع. اجعله خدمة systemd.
- **قتل عملية بالاسم بتعجّل:** `pkill python` توقف **كل** عمليات Python، ومنها أدوات النظام. استخدم `-f` بنمط محدّد، أو الـ PID.
- **عمليات زومبي (`Z`):** انتهت لكن أباها لم يقرأ حالتها. لا يمكن قتلها؛ المشكلة في العملية الأب.
