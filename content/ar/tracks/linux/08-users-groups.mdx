## لماذا حسابات منفصلة؟

كل شيء في Linux يعمل باسم مستخدم ما: أنت، وخادم الويب (`www-data`)، وقاعدة البيانات (`postgres`). هذا الفصل خطّ دفاع حقيقي: إذا اختُرق خادم الويب، يحصل المهاجم على صلاحيات `www-data` فقط، لا على النظام كله. ولهذا القاعدة الذهبية: **كل خدمة بحسابها، وأقلّ صلاحيات ممكنة**.

## root و sudo

`root` (رقمه 0) يتجاوز كل الصلاحيات: يقرأ ويعدّل ويحذف أي شيء. العمل به دائمًا يعني أن أي خطأ إملائي قد يدمّر النظام. لذلك تعمل كمستخدم عادي، وترفع الصلاحية **لأمر واحد** عند الحاجة:

```bash
sudo apt update        # أمر واحد بصلاحيات root (يطلب كلمة سرّك أنت لا كلمة root)
sudo -i                # جلسة root كاملة: استخدمها نادرًا، واخرج بـ exit
sudo -u postgres psql  # تشغيل أمر باسم مستخدم آخر
```

`sudo` يسجّل كل أمر في السجلّات (من نفّذ ماذا ومتى)، ويتذكّر كلمة السرّ لدقائق. ومن يحقّ له استخدامه محدّد في `/etc/sudoers`، وعادة يكفي أن يكون المستخدم في مجموعة `sudo` (على Debian وUbuntu) أو `wheel` (على Fedora وRHEL).

## من أنا؟

```bash
whoami        # اسم المستخدم الحالي
id            # uid=1000(baraa) gid=1000(baraa) groups=1000(baraa),27(sudo),998(docker)
groups        # المجموعات فقط
```

النظام لا يعمل بالأسماء بل بالأرقام: `uid` للمستخدم و`gid` للمجموعة. الأسماء للبشر فقط. المستخدمون العاديون يبدؤون عادة من 1000، وما تحتها حسابات نظام للخدمات.

## إدارة المستخدمين

```bash
sudo useradd -m -s /bin/bash sara    # -m مجلّد home، -s الـ shell
sudo passwd sara                     # كلمة السر
sudo usermod -aG sudo sara           # أضفها لمجموعة sudo
sudo userdel -r sara                 # حذف مع مجلّدها (-r)
```

على Debian وUbuntu يوجد أيضًا `adduser` (بلا اختصار)، وهو تفاعلي ويسأل عن كل شيء، فهو أسهل للاستخدام اليدوي، أما `useradd` فأنسب للسكربتات.

## المجموعات: صلاحيات لعدّة أشخاص

بدل إعطاء كل مستخدم صلاحية على مجلّد مشترك، أنشئ مجموعة:

```bash
sudo groupadd devteam
sudo usermod -aG devteam baraa
sudo usermod -aG devteam sara
sudo chgrp -R devteam /srv/project
sudo chmod -R g+rwX /srv/project
```

الآن كل أعضاء `devteam` يقرؤون ويعدّلون المشروع، وإضافة عضو جديد سطر واحد. مثال شائع آخر: الإضافة لمجموعة `docker` تسمح بتشغيل `docker` بلا `sudo` (ولاحظ أنها عمليًا تعادل صلاحيات root، فلا تضف إليها إلا من تثق به).

### ⚠️ `-aG` لا `-G`

```bash
sudo usermod -G docker baraa    # ❌ يستبدل كل مجموعات baraa بـ docker وحدها!
sudo usermod -aG docker baraa   # ✅ a = append: أضف دون حذف الباقي
```

بدون `-a` يخرج المستخدم من كل مجموعاته الأخرى، ومنها `sudo`، فقد تفقد صلاحية الإدارة على خادمك.

### الانضمام لا يُطبَّق فورًا

بعد إضافتك لمجموعة، جلستك الحالية لا تعرف بذلك: `groups` لا تُظهرها بعد. اخرج وادخل من جديد (أو `newgrp docker` للجلسة الحالية).

## أين تُخزَّن الحسابات؟

```bash
grep baraa /etc/passwd
# baraa:x:1000:1000:Baraa:/home/baraa:/bin/bash
```

الحقول بالترتيب: الاسم، و`x` (كلمة السر ليست هنا)، وuid، وgid، والوصف، ومجلّد home، والـ shell. كلمات السر **مُجزّأة** (hashed) في `/etc/shadow` الذي لا يقرؤه إلا root. والمجموعات في `/etc/group`.

## أخطاء شائعة

- **`usermod -G` بلا `-a`:** يحذف المستخدم من كل مجموعاته الأخرى.
- **انتظار تطبيق المجموعة الجديدة فورًا:** أعد تسجيل الدخول.
- **العمل كـ root دائمًا** أو تشغيل التطبيقات كـ root: أي ثغرة تصبح سيطرة كاملة.
- **تعديل `/etc/sudoers` مباشرة بمحرّر عادي:** خطأ صياغة واحد يحرمك من `sudo` نهائيًا. استخدم `sudo visudo` الذي يفحص الملف قبل الحفظ.
- **مشاركة حساب واحد بين عدّة أشخاص:** لا تعرف من فعل ماذا. لكل شخص حسابه، ومجموعة للمشترك.
