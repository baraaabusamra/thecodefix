## لماذا مدير حزم؟

في Windows تنزّل ملف تثبيت من موقع البرنامج. في Linux تطلب البرنامج بالاسم من **مستودع** (repository) موثوق تديره التوزيعة، ومدير الحزم:

- ينزّل البرنامج **وكل ما يعتمد عليه** (التبعيات) تلقائيًا.
- يتحقّق من التوقيع الرقمي، فلا يُثبَّت ملف عُبث به.
- يحدّث **كل** برامج النظام بأمر واحد.
- يعرف أي ملف ينتمي لأي حزمة، فالإزالة نظيفة.

## مدير الحزم حسب التوزيعة

| العائلة | التوزيعات | الأداة | صيغة الحزم |
| --- | --- | --- | --- |
| Debian | Ubuntu، Debian، Mint | `apt` | `.deb` |
| Red Hat | Fedora، RHEL، Rocky، Alma | `dnf` | `.rpm` |
| Arch | Arch، Manjaro | `pacman` | `.pkg.tar.zst` |
| Alpine | Alpine (شائعة في Docker) | `apk` | `.apk` |

لمعرفة توزيعتك: `cat /etc/os-release`.

## apt: الأكثر استخدامًا

```bash
sudo apt update              # حدّث **قائمة** الحزم المتاحة (لا يثبّت شيئًا)
sudo apt upgrade             # رقِّ كل الحزم المثبّتة لأحدث إصدار
sudo apt install nginx git   # ثبّت حزمة أو أكثر
sudo apt remove nginx        # أزلها (تبقى ملفات الإعداد)
sudo apt purge nginx         # أزلها مع ملفات إعدادها
sudo apt autoremove          # أزل التبعيات التي لم يعد يحتاجها أحد
apt search "web server"      # ابحث
apt show nginx               # الوصف والإصدار والتبعيات
apt list --installed | grep nginx   # هل هي مثبّتة؟
```

### update ليست upgrade

أكثر خلط شائع: `apt update` **لا تحدّث البرامج**. هي تنزّل قائمة "ما المتاح الآن" من المستودعات. و`apt upgrade` هي التي تثبّت الإصدارات الجديدة. لذلك الترتيب دائمًا:

```bash
sudo apt update && sudo apt upgrade
```

وبدون `update` قبل `install`، قد يحاول apt تنزيل إصدار قديم لم يعد في المستودع، فيفشل بخطأ 404.

## dnf و pacman

```bash
sudo dnf install nginx       # Fedora/RHEL
sudo dnf upgrade             # يحدّث القائمة ويرقّي معًا
sudo dnf remove nginx

sudo pacman -Syu             # Arch: حدّث كل شيء
sudo pacman -S nginx         # ثبّت
sudo pacman -R nginx         # أزل
```

المفاهيم واحدة، والأسماء تختلف.

## في Docker و CI

```bash
apt-get update && apt-get install -y --no-install-recommends curl \
    && rm -rf /var/lib/apt/lists/*
```

في السكربتات وملفات `Dockerfile` استخدم `apt-get` (واجهتها ثابتة لا تتغيّر بين الإصدارات، عكس `apt` المصمّمة للبشر)، و`-y` للموافقة تلقائيًا، و`--no-install-recommends` لصورة أصغر، وحذف القوائم في نفس الطبقة. التفاصيل في [مسار Docker](/learn/docker/00-intro).

## مصادر خارج المستودع الرسمي

```bash
sudo dpkg -i package.deb     # ملف .deb نزّلته يدويًا
sudo apt install ./package.deb   # أفضل: يحلّ التبعيات أيضًا
```

وهناك مستودعات إضافية (PPA في Ubuntu، أو مستودع رسمي لبرنامج مثل Docker أو Node.js)، وأنظمة حزم مستقلّة عن التوزيعة مثل **Snap** و**Flatpak**. كل مصدر خارجي تضيفه **تثق به بصلاحيات root**، فلا تضف إلا مصادر رسمية معروفة.

## أخطاء شائعة

- **`apt install` بلا `update` قبله على نظام جديد:** أخطاء 404 لإصدارات لم تعد موجودة.
- **ظنّ أن `update` تحدّث البرامج:** تحدّث القائمة فقط؛ `upgrade` هي التي تثبّت.
- **`Could not get lock /var/lib/dpkg/lock`:** عملية apt أخرى تعمل (غالبًا تحديث تلقائي). انتظر؛ لا تحذف ملف القفل.
- **نسخ أوامر تضيف مستودعًا من مدوّنة مجهولة:** كأنك تعطي صاحبها root على جهازك.
- **`apt` في السكربتات:** يطبع تحذير "does not have a stable CLI interface". استخدم `apt-get`.
