## المشكلة التي يحلّها

بدأت فرع `feature` من `main`، وعملت commitين. في الأثناء دُمج في `main` تغيير آخر:

```text
* 95a3ddc E: login validation      ← feature
* 1939c31 D: login form
| * 5add9a3 C: readme              ← main
|/
* d87b211 B
* 506fe47 A
```

فرعك مبني على `B`، و`main` صار عند `C`. لتحصل على `C` عندك، عندك طريقتان: **merge** يضيف commit دمج يجمع الخطّين ([درس الدمج](/learn/git/13-merge))، أو **rebase**: "انقل نقطة بداية فرعي، كأنني بدأته من `C`".

## ماذا يفعل rebase؟

```bash
git switch feature
git rebase main
```

```text
Successfully rebased and updated refs/heads/feature.
```

```text
* 488112e E: login validation      ← feature
* a871a63 D: login form
* 5add9a3 C: readme                ← main
* d87b211 B
* 506fe47 A
```

خطّ واحد مستقيم، كأن `C` حدث قبل أن تبدأ. لكن انظر للأرقام: `D` كان `1939c31` وصار `a871a63`، و`E` من `95a3ddc` إلى `488112e`.

rebase **لا ينقل** commits، بل يعيد **تطبيق** تغييرات كل منها، واحدًا تلو الآخر، فوق `main`، فينشئ commits **جديدة** بنفس الرسائل والتغييرات وأرقام مختلفة. الأصلية تبقى في المستودع بلا اسم يشير إليها (ويمكن استرجاعها عبر [reflog](/learn/git/28-reflog) لفترة).

بعدها يصبح دمج `feature` في `main` تقديمًا بسيطًا للمؤشّر (fast-forward) بلا commit دمج.

## merge أم rebase؟

| | merge | rebase |
| --- | --- | --- |
| التاريخ | يحفظ ما حدث فعلًا، بتفرّعاته | يعيد كتابته كخطّ مستقيم |
| commits جديدة | commit دمج واحد | نسخة جديدة من كل commit في فرعك |
| الأرقام (hashes) | لا تتغيّر | تتغيّر لكل commits فرعك |
| التعارضات | مرة واحدة، لكل الفرع | قد تتكرّر لكل commit يُعاد تطبيقه |
| آمن على فرع مشترك؟ | نعم | **لا** |

لا يوجد فائز مطلق: الفرق في قيمة التاريخ عندك. فرق كثيرة تستخدم **rebase لتحديث فرعها الشخصي** قبل المراجعة (تاريخ مقروء)، و**merge لإدخال الفرع في `main`** (أثر واضح لكل ميزة دُمجت).

## القاعدة الذهبية

> ⚠️ **لا تُعِد بناء commits رفعتها وبنى عليها غيرك.**

إذا رفعت `feature` وسحبه زميلك وبنى عليه، ثم أعدت بناءه بـ rebase، فـ commits التي عنده **لم تعد موجودة** في نسختك؛ عنده `D` و`E` القديمان وعندك الجديدان، بنفس التغييرات وأرقام مختلفة. حين يسحب، يرى Git تاريخين متوازيين، فتتكرّر الـ commits ويتعقّد كل شيء.

rebase آمن تمامًا على: فرعك المحلي الذي لم ترفعه، أو فرع رفعته **وحدك تعمل عليه** (فرع PR شخصي مثلًا).

## الرفع بعد rebase

```bash
git push
```

```text
 ! [rejected]        feature -> feature (non-fast-forward)
error: failed to push some refs to 'origin'
```

البعيد ما زال يحمل `D` و`E` القديمين، ونسختك لا تحتويهما، فيرفض Git الرفع حتى لا تُحذف commits. لأنك **تقصد** الاستبدال:

```bash
git push --force-with-lease
```

`--force-with-lease` تستبدل الفرع البعيد **فقط إن لم يتغيّر** منذ آخر مرة سحبته. إن رفع زميلك commit في الأثناء، ترفض بدل أن تمحو عمله. أما `--force` فتمحو بلا سؤال. لا تستخدمها على فرع مشترك، وعلى `main` أبدًا.

## التعارضات أثناء rebase

لأن rebase يطبّق commits واحدًا واحدًا، يتوقّف عند أي commit يتعارض:

```bash
# Git يتوقّف ويخبرك بالملف المتعارض
# 1. حلّ التعارض في الملف كالمعتاد
git add config.txt
git rebase --continue      # تابع مع الـ commit التالي

git rebase --skip          # تخلَّ عن هذا الـ commit كليًّا (نادرًا)
git rebase --abort         # ألغِ كل شيء وعُد لما قبل rebase
```

وتذكّر أن `--ours` و`--theirs` **معكوسان** هنا مقارنة بالدمج ([درس التعارضات](/learn/git/14-conflicts)). وإن كان فرعك طويلًا ويتعارض في كل commit تقريبًا، فقد يكون merge أقل إرهاقًا.

## pull --rebase

```bash
git pull --rebase
```

`git pull` العادي يدمج (`fetch` ثم `merge`)، فيضيف commit دمج كلما كان زميلك قد رفع شيئًا قبلك: "Merge branch 'main' of github.com:..." بلا أي معنى. `--rebase` تضع commits المحلية **فوق** ما سحبته، فيبقى التاريخ مستقيمًا. هذا آمن لأن commits التي يُعاد بناؤها هي commits لم ترفعها بعد. لجعله افتراضيًّا: `git config --global pull.rebase true`.

## ما بعد rebase العادي

`git rebase -i` (التفاعلي) يتيح إعادة ترتيب commits فرعك ودمجها وتعديل رسائلها قبل المراجعة، وهو موضوع [درس rebase التفاعلي](/learn/git/29-interactive-rebase).

## أخطاء شائعة

- **rebase على فرع مشترك:** تاريخان متوازيان عند الجميع.
- **`git push --force` بعد rebase:** استخدم `--force-with-lease`.
- **`git pull` بعد رفض الرفع الذي سببه rebase:** يدمج القديم مع الجديد فتتكرّر commits. استخدم `--force-with-lease` إن كنت وحدك على الفرع.
- **الذعر في منتصف rebase متعارض:** `git rebase --abort` يعيدك للبداية.
- **rebase على `main` نفسه** (`git switch main && git rebase feature`): يعيد كتابة الفرع الذي يعتمد عليه الجميع. rebase يكون **من** فرعك **على** `main`، لا العكس.
