## متى تستخدم REST؟

REST هو الخيار الأفضل في الحالات التالية:

### 1. واجهات بسيطة وموارد محدودة

إذا كان لديك عدد صغير من الموارد (Users, Posts, Comments) وعلاقاتها بسيطة، REST أسهل وأسرع.

### 2. التخزين المؤقت (Caching)

REST يستفيد من **HTTP Caching** (ETag, Cache-Control, CDNs). إذا كانت القراءة أكثر من الكتابة بكثير، REST يتفوق.

```javascript
// REST — يمكن تخزين الاستجابة في CDN
GET /api/popular-posts
// Cache-Control: public, max-age=3600
```

### 3. رفع الملفات

REST يتعامل مع `multipart/form-data` بسهولة، بينما GraphQL يحتاج مكتبات إضافية.

### 4. خدمات بسيطة — فريق صغير

إذا كنت تبني MVP أو مشروعاً صغيراً، REST يقلل التعقيد.

## متى تستخدم GraphQL؟

### 1. تطبيقات معقدة ذات علاقات كثيرة

مثل: فيسبوك، تويتر — حيث كل منشور له تعليقات، إعجابات، مستخدمون، صور.

```graphql
query {
  post(id: "1") {
    title
    author { name avatar }
    comments { text author { name } }
    likes { count }
  }
}
// طلب واحد — كل البيانات المطلوبة
```

### 2. تطبيقات متعددة المنصات (Mobile + Web)

كل منصة تحتاج بيانات مختلفة. GraphQL يسمح لكل منصة بطلب ما تحتاجه بالضبط.

### 3. المنتجات سريعة التطور

إضافة حقول جديدة لا يؤثر على الاستعلامات القديمة — لا حاجة لإصدارات API.

### 4. أنظمة حية (Real-time)

إذا كنت تحتاج Subscriptions + Queries في مكان واحد، GraphQL يوحّد كل شيء.

## المشاريع الهجينة

ليس عليك اختيار واحد فقط. كثير من المشاريع تستخدم الاثنين معاً:

| الاستخدام | التقنية |
|-----------|---------|
| جلب البيانات الأساسية | REST (مخزّن في CDN) |
| استعلامات معقدة ومخصصة | GraphQL |
| رفع الملفات | REST |
| الإشعارات الحية | GraphQL Subscriptions |
| إدارة المخزون/المستخدمين | REST (للواجهة الإدارية) |

### مثال: بنية هجينة

```javascript
// 🟢 REST — للموارد البسيطة
GET /api/products
GET /api/products/:id

// 🔵 GraphQL — للصفحات المعقدة
POST /graphql
query {
  product(id: "1") {
    name
    price
    reviews { rating comment user { name } }
    relatedProducts { name price }
  }
}

// 🟢 REST — رفع الصور
POST /api/upload
Content-Type: multipart/form-data
```

> ⚠️ البنية الهجينة تزيد التعقيد التشغيلي — تأكد من أن الفريق قادر على صيانة النظامين معاً.

## جدول المقارنة الشامل

| المعيار | REST | GraphQL |
|---------|------|---------|
| جلب البيانات | Endpoints متعددة | نقطة نهاية واحدة |
| التحكم بالحقول | خادم يتحكم | عميل يتحكم |
| Over-fetching | موجود | لا يوجد |
| Under-fetching | موجود | لا يوجد |
| Caching | ممتاز (HTTP) | معقّد (ID-based) |
| Real-time | WebSocket منفصل | Subscriptions مدمجة |
| رفع الملفات | سهل (FormData) | يحتاج مكتبات |
| الإصدارات | v1, v2, ... | إضافة حقول |
| أدوات المطورين | Swagger, Postman | GraphiQL, Apollo Studio |
| منحنى التعلم | سهل | متوسط |
| الأداء مع البيانات المتداخلة | جيد | قد يحدث N+1 |

## الخلاصة

- **REST** — بسيط، سريع الإعداد، ممتاز للتخزين المؤقت، مثالي للخدمات الصغيرة والموارد المحدودة.
- **GraphQL** — مرن، يقلل حجم الاستجابة، يوحّد الواجهة لمنصات متعددة، مثالي للتطبيقات المعقدة.
- **البنية الهجينة** — تجمع أفضل ما في العالمين، لكنها تحتاج خبرة تشغيلية.

اختر الأداء الصحيح للمشروع — لا تتبع الموضة فقط.
