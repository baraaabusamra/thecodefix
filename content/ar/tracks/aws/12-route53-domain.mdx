Route 53 هو خدمة DNS من AWS. سنستخدمه لربط نطاق مخصّص (مثل `example.com`) بمواردك. يفترض الدرس فهمًا أساسيًا لـ [نظام أسماء النطاقات (DNS)](/learn/networking/09-dns).

> ⚠️ الأوامر تمثيلية؛ استبدل `example.com` بنطاقك، وشغّلها في حساب حقيقي. تحتاج نطاقًا مسجّلًا (لدى AWS أو مُسجِّل آخر).

## كيف يعمل DNS باختصار؟

DNS يترجم الأسماء التي يحفظها البشر (`example.com`) إلى عناوين IP التي تفهمها الأجهزة. Route 53 يخزّن «سجلّات» هذه الترجمة ويجيب استعلامات الزوّار.

## الخطوة 1: أنشئ منطقة مستضافة (Hosted Zone)

المنطقة المستضافة حاوية لسجلّات DNS الخاصّة بنطاقك:

```bash
aws route53 create-hosted-zone \
  --name example.com \
  --caller-reference $(date +%s)
```

`--caller-reference` قيمة فريدة (استخدمنا الطابع الزمني). تعيد الأداة **أربعة خوادم أسماء (Name Servers)**.

## الخطوة 2: حدّث خوادم الأسماء عند المُسجِّل

انسخ خوادم الأسماء الأربعة، واذهب إلى لوحة **مُسجِّل نطاقك** واضبطها بدل الافتراضية. بهذا يصبح Route 53 هو المسؤول عن DNS لنطاقك.

> ℹ️ قد يستغرق انتشار هذا التغيير عبر الإنترنت وقتًا (من دقائق إلى ساعات) — وهو أمر طبيعي.

## الخطوة 3: أضف سجلًّا لتوجيه النطاق

أضف سجلًّا يربط نطاقك بعنوان مورد (خادم مثلًا). أبسط مثال، سجلّ `A` يشير إلى عنوان IP:

```json
{
  "Changes": [{
    "Action": "UPSERT",
    "ResourceRecordSet": {
      "Name": "example.com",
      "Type": "A",
      "TTL": 300,
      "ResourceRecords": [{ "Value": "203.0.113.10" }]
    }
  }]
}
```

طبّقه عبر:

```bash
aws route53 change-resource-record-sets \
  --hosted-zone-id <معرّف-المنطقة> \
  --change-batch file://record.json
```

> 💡 لتوجيه النطاق إلى موارد AWS (مثل موزّع أحمال أو موقع CloudFront)، يُستخدم عادةً سجلّ **Alias** بدل عنوان IP ثابت.

## أخطاء شائعة

- **النطاق لا يعمل بعد**: خوادم الأسماء لم تُحدَّث عند المُسجِّل، أو التغيير لم ينتشر بعد.
- **سجلّ خاطئ**: نوع السجلّ (`A` مقابل `CNAME` مقابل Alias) غير مناسب للهدف.

## التنظيف

احذف السجلّات المخصّصة أوّلًا، ثم المنطقة المستضافة عبر `aws route53 delete-hosted-zone`.
