HTML وCSS وJavaScript ليست ثلاث لغات بديلة تختار بينها، بل ثلاث **طبقات** في كل صفحة ويب، ولكل واحدة سؤال تجيب عنه:

| | HTML | CSS | JavaScript |
|---|---|---|---|
| **السؤال** | ماذا يوجد في الصفحة؟ وما معناه؟ | كيف يبدو؟ | ماذا يحدث عند حدث أو تغيّر بيانات؟ |
| **النوع** | لغة ترميز (Markup) | لغة أنماط (Stylesheet) | لغة برمجة |
| **لو تعطّلت** | لا توجد صفحة أصلًا | المحتوى يبقى مقروءًا بشكل خام | الصفحة تظهر، لكن التفاعل يتوقف |

الجدول وحده لا يكفي لتفهم الفرق فعلًا، لذلك سنبني بطاقة منتج واحدة طبقة طبقة ونرى ما تضيفه كل لغة.

## الطبقة الأولى: HTML يحدّد المحتوى ومعناه

```html
<article class="product">
  <h2>سماعة لاسلكية</h2>
  <p class="price">35 دينار</p>
  <details>
    <summary>المواصفات</summary>
    <p>بطارية 30 ساعة، بلوتوث 5.3</p>
  </details>
  <button id="add">أضف للسلة</button>
  <p id="cart">السلة: 0</p>
</article>
```

افتح هذا الملف في المتصفح بدون أي CSS أو JavaScript وستلاحظ أن:

- العنوان يظهر كبيرًا لأن `<h2>` **يعني** عنوانًا، وقارئ الشاشة يعلن عنه كعنوان، ومحرّك البحث يفهمه كعنوان.
- "المواصفات" **تنفتح وتنغلق بالنقر** دون سطر JavaScript واحد؛ هذا سلوك عنصر `<details>` نفسه.
- الزر يُضغط ويأخذ التركيز بمفتاح Tab ويُفعَّل بـ Enter. فقط لا يفعل شيئًا بعد.

HTML إذن ليس "هيكلًا فارغًا" كما يُقال كثيرًا: فيه سلوك جاهز ومعنى يفهمه المتصفح وأدوات الوصول ومحرّكات البحث. تفاصيل العناصر ومعانيها في درس [HTML الدلالي](/learn/html/06-semantic).

## الطبقة الثانية: CSS يحدّد الشكل

```css
.product {
  max-width: 320px;
  padding: 16px;
  border: 1px solid #ddd;
  border-radius: 12px;
}
.price {
  font-weight: bold;
  color: #0a7d32;
}
#add {
  background: #6d28d9;
  color: white;
  border: 0;
  padding: 8px 16px;
  border-radius: 8px;
}
#add:hover {
  background: #5b21b6;
}
```

لم يتغيّر أي شيء في **ما** تحتويه الصفحة، فقط **كيف تبدو**. لاحظ `:hover`: تغيير اللون عند مرور الماوس شأن من شؤون الشكل، فمكانه CSS لا JavaScript. ابدأ تعلّم التنسيق من [مسار CSS](/learn/css).

## الطبقة الثالثة: JavaScript يضيف السلوك

```html
<script src="app.js" defer></script>
```

```javascript
// app.js
let count = 0;
const cart = document.querySelector("#cart");

document.querySelector("#add").addEventListener("click", () => {
  count++;
  cart.textContent = `السلة: ${count}`;
});
```

هذا ما لا يقدر عليه HTML ولا CSS: **حالة** (عدد المنتجات) تتغيّر مع كل نقرة، والصفحة تتحدّث حسبها. في التطبيقات الحقيقية هنا يُرسل طلب للخادم ويُحفظ الطلب. شرح `querySelector` والأحداث في درسَي [DOM](/learn/javascript/18-dom) و[الأحداث](/learn/javascript/19-events).

## كيف تعمل الثلاثة معًا داخل المتصفح

1. المتصفح يقرأ HTML ويبني منه شجرة العناصر (**DOM**).
2. يقرأ CSS ويحسب شكل كل عنصر في الشجرة، ثم يرسم الصفحة.
3. JavaScript يقرأ عناصر الـ DOM ويعدّلها بعد ذلك، فيعيد المتصفح الرسم.

النقطة الثالثة هي سبب أشهر خطأ يقع فيه المبتدئ حين يربط الثلاثة لأول مرة. لو وضعت السكربت في `<head>` **بدون** `defer`:

```html
<head>
  <script src="app.js"></script>
</head>
```

يتوقف المتصفح عند هذا السطر وينفّذ `app.js` **قبل** أن يقرأ الزر من الأسفل، فيرجع `querySelector("#add")` بـ `null` وتظهر في الـ Console:

```text
Uncaught TypeError: Cannot read properties of null (reading 'addEventListener')
```

الحل إضافة `defer` (ينفّذ السكربت بعد اكتمال قراءة HTML) أو وضع `<script>` في آخر `<body>`. نفس عائلة هذا الخطأ مشروحة في [Cannot read properties of undefined](/blog/cannot-read-properties-of-undefined).

## القاعدة العملية: أين أضع هذا الجزء؟

استخدم **أبسط طبقة تكفي**:

- إذا كان الجزء **محتوى أو معنى** (عنوان، قائمة، زر، حقل إدخال إلزامي) فهو HTML.
- إذا كان **شكلًا أو تخطيطًا أو حالة بصرية** (لون، مسافة، hover، تجاوب مع حجم الشاشة، حركة بسيطة) فهو CSS.
- إذا كان يعتمد على **حالة أو بيانات تتغيّر** (سلة، بحث فوري، طلب للخادم) فهو JavaScript.

### أخطاء شائعة سببها الخلط بين الطبقات

**1) زر مصنوع من `<div>`:**

```html
<!-- ❌ -->
<div onclick="addToCart()">أضف للسلة</div>

<!-- ✅ -->
<button onclick="addToCart()">أضف للسلة</button>
```

الـ `div` يستجيب للماوس فقط: لا يصل له المستخدم بمفتاح Tab ولا يُفعَّل بـ Enter، وقارئ الشاشة لا يعرف أنه زر. `<button>` يعطيك كل ذلك مجانًا. محاولة تعويضه بـ JavaScript (`tabindex` ومستمع لوحة مفاتيح وخاصية `role`) كود إضافي لحل مشكلة صنعتها بنفسك. المزيد في درس [إمكانية الوصول](/learn/html/21-accessibility).

**2) التحقق من النماذج بـ JavaScript فقط:**

```html
<input type="email" required>
```

هذا السطر وحده يمنع إرسال النموذج إن كان الحقل فارغًا أو لا يحتوي `@`، ويعرض المتصفح رسالته الخاصة (في Chrome بالإنجليزية: *Please fill out this field.*). ابدأ بما يعطيك HTML ثم أضف JavaScript لما يعجز عنه، مثل التحقق من أن اسم المستخدم غير محجوز. وتذكّر أن تحقق المتصفح، سواء بـ HTML أو JavaScript، يسهل تجاوزه؛ التحقق الحقيقي مكانه الخادم. تفاصيل الحقول في درس [النماذج المتقدمة](/learn/html/11-forms-advanced).

**3) تغيير الشكل من JavaScript مباشرة:**

```javascript
// ❌ الشكل مكتوب داخل المنطق
button.style.background = "red";
button.style.color = "white";

// ✅ JavaScript يغيّر الحالة، وCSS يقرّر شكلها
button.classList.add("is-error");
```

```css
.is-error { background: red; color: white; }
```

بهذه الطريقة يبقى كل الشكل في ملف CSS، ويقدر المصمّم تعديله دون أن يلمس المنطق.

## ما الترتيب الصحيح للتعلّم؟

1. **[HTML](/learn/html):** ابنِ صفحة بعناوين وفقرات وروابط وصور ونموذج. لا تنتظر حتى تحفظ كل العناصر.
2. **[CSS](/learn/css):** نسّق تلك الصفحة نفسها، ثم تعلّم Flexbox وGrid والتجاوب مع الشاشات.
3. **[JavaScript](/learn/javascript):** ابدأ بأساسيات اللغة (متغيّرات، شروط، دوال)، ثم انتقل لـ DOM والأحداث لتربطها بصفحاتك.

السبب ليس أن كل لغة "أصعب" من التي قبلها، بل أن JavaScript في المتصفح يعمل **على** عناصر HTML ويغيّر **حالات** يرسمها CSS؛ إن لم تفهم الطبقتين، ستكتب JavaScript لحل مشاكل لا تخصّه.

بعدها يصبح السؤال التالي عادةً: هل أكمل في الواجهات أم أنتقل للخادم؟ الفرق مشروح في [الفرق بين Frontend و Backend](/blog/frontend-vs-backend).
