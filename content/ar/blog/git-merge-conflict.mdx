تشغّل `git merge` أو `git pull` فتظهر الرسالة المخيفة (هذه من تجربة حقيقية على Git 2.43):

```text
Auto-merging app.js
CONFLICT (content): Merge conflict in app.js
CONFLICT (modify/delete): notes.txt deleted in feature/new-tax and modified in HEAD.  Version HEAD of notes.txt left in tree.
Automatic merge failed; fix conflicts and then commit the result.
```

اهدأ — **لم يضِع شيء ولم ينكسر شيء**. [Git](/learn/git) فقط يقول: "شخصان
عدّلا نفس الأسطر، ولن أخمّن أيّهما الصحيح — قرّر أنت".

## لماذا يحدث التعارض؟

Git يدمج الفروع تلقائيًّا ببراعة ما دام كل تعديل في **أسطر مختلفة**. التعارض
يحدث فقط عندما:

- عدّل فرعان **نفس الأسطر** في نفس الملف، أو
- حذف أحدهما ملفًّا عدّله الآخر.

## شكل التعارض داخل الملف

افتح الملف المذكور في الرسالة وسترى:

```text
<<<<<<< HEAD
const tax = 0.15;
=======
const tax = 0.16;
>>>>>>> feature/new-tax
const currency = "JOD";
```

السطر الأخير خارج العلامات لأن الطرفين لم يختلفا عليه، فدمجه Git وحده. التعارض يقتصر دائمًا على الأسطر المختلف عليها.

اقرأها هكذا:

| العلامة | معناها |
|---------|--------|
| `<<<<<<< HEAD` | بداية **نسختك** الحالية |
| `=======` | الفاصل بين النسختين |
| `>>>>>>> اسم-الفرع` | نهاية **نسخة الفرع الآخر** |

## الحل خطوة بخطوة

### 1) اعرف أي الملفات متعارضة

```bash
git status
```

```text
On branch main
You have unmerged paths.
  (fix conflicts and run "git commit")
  (use "git merge --abort" to abort the merge)

Unmerged paths:
  (use "git add/rm <file>..." as appropriate to mark resolution)
	both modified:   app.js
	deleted by them: notes.txt
```

لاحظ أن هناك نوعين مختلفين:

- **`both modified`**: الطرفان عدّلا نفس الأسطر. هذا الذي فيه علامات `<<<<<<<` داخل الملف.
- **`deleted by them`** (أو `deleted by us`): أحد الفرعين حذف الملف والآخر عدّله. **لا توجد علامات** داخل الملف هنا؛ Git ترك نسختك المعدّلة ويسألك: هل تبقيه أم تحذفه؟ إن أردت إبقاءه: `git add notes.txt`. وإن وافقت على الحذف: `git rm notes.txt`.

### 2) افتح الملف وقرّر

احذف العلامات الثلاث واترك الكود النهائي. أمامك ثلاثة خيارات:

```js
// الخيار أ: تُبقي نسختك
const tax = 0.15;

// الخيار ب: تأخذ نسختهم
const tax = 0.16;

// الخيار ج: تدمج بنفسك (الأفضل غالبًا)
const tax = getTaxRate(country);
```

> ⚠️ تأكد من حذف أسطر `<<<<<<<` و `=======` و `>>>>>>>` كلها — نسيان واحدة
> منها يكسر تشغيل الكود، وهي أشهر هفوة بعد أول تعارض.

### 3) تأكد أنه لم تبقَ علامات

`git add` **لا يتحقق** من أنك حللت التعارض فعلًا؛ هو فقط يسجّل الملف كما هو. جرّبنا إضافة الملف والعلامات ما زالت فيه، فقبل Git الـ commit بلا أي اعتراض، ودخلت أسطر `<<<<<<<` إلى التاريخ. لذلك قبل `git add` شغّل:

```bash
git diff --check
```

```text
app.js:1: leftover conflict marker
app.js:3: leftover conflict marker
app.js:5: leftover conflict marker
```

لا مخرجات تعني لا علامات متبقية.

### 4) أعلِم Git أنك انتهيت

```bash
git add app.js          # "حللت التعارض في هذا الملف"
git commit              # يُنهي الدمج برسالة جاهزة تلقائيًا
```

`git merge --continue` تؤدي نفس عمل `git commit` هنا. أما إن كان التعارض أثناء `git rebase` (أو `git pull --rebase`) فالأمر مختلف: `git rebase --continue`، وقد يتكرر التعارض مع كل commit. الفرق بين الطريقتين في [الفرق بين git rebase و merge](/blog/git-rebase-vs-merge).

### اختصار: خذ نسخة كاملة لملف

إن كنت تعرف أن نسخة أحد الطرفين صحيحة **للملف كله**:

```bash
git checkout --ours app.js     # نسخة فرعك الحالي (HEAD)
git checkout --theirs app.js   # نسخة الفرع القادم
git add app.js
```

انتبه: أثناء rebase ينعكس معنى `ours` و`theirs`.

### طريق الهروب: التراجع الكامل

غير جاهز للتعامل مع التعارض الآن؟ أعد كل شيء كما كان قبل الدمج:

```bash
git merge --abort
```

## اعرض النسخة الأصلية أيضًا: zdiff3

العلامات الافتراضية تعرض نسختين فقط، فلا تعرف ماذا كان السطر **قبل** أن يعدّله أي منكما. اطلب عرض الأصل:

```bash
git checkout --conflict=zdiff3 app.js
```

```text
<<<<<<< ours
const tax = 0.15;
||||||| base
const tax = 0.10;
=======
const tax = 0.16;
>>>>>>> theirs
```

الآن تفهم القصة: الضريبة كانت 0.10، وكل فرع رفعها لقيمة مختلفة. القرار هنا ليس تقنيًا بل سؤال لصاحب المتطلب. ولتظهر هذه الصيغة في كل تعارض تلقائيًا (Git 2.35 أو أحدث):

```bash
git config --global merge.conflictStyle zdiff3
```

## الحل من VS Code (أسهل للمبتدئين)

عند فتح ملف متعارض في VS Code يظهر فوق كل تعارض أزرار جاهزة:

- **Accept Current Change** — يُبقي نسختك.
- **Accept Incoming Change** — يأخذ نسخة الفرع الآخر.
- **Accept Both Changes** — يضع النسختين معًا.

وزر **Resolve in Merge Editor** يفتح عرضًا ثلاثيًّا (نسختك | النتيجة |
نسختهم) يجعل التعارضات الكبيرة أوضح بكثير. بعد الانتهاء: `git add` ثم
`git commit` كالمعتاد.

## كيف تقلّل التعارضات مستقبلًا؟

- **اسحب باستمرار**: `git pull` قبل بدء العمل وقبل أي دمج.
- **فروع صغيرة قصيرة العمر** — فرع يعيش أسبوعين يتعارض حتمًا.
- **قسّم الملفات الضخمة** — ملف واحد يلمسه الجميع = مصنع تعارضات.
- نسّق مع فريقك من يعمل على أي ملف.

## الخلاصة

تعارض الدمج ليس خطأً بل **سؤال**: "أي نسخة تريد؟". الإجابة: افتح الملف واترك الكود الصحيح بلا علامات ← `git diff --check` ← `git add` ← `git commit`. وإذا ضاق صدرك: `git merge --abort` يعيدك لنقطة البداية بأمان.
