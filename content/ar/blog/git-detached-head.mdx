كتبت `git checkout` لرقم commit قديم لتلقي نظرة، فاستقبلك [Git](/learn/git)
بأطول تحذير في تاريخه:

```
You are in 'detached HEAD' state. You can look around, make
experimental changes and commit them, and you can discard any
commits you make in this state without impacting any branches...
```

اسم مرعب («رأس مقطوع»!) لحالة بريئة تمامًا — لنفهمها فتتحول من ذعر
إلى أداة.

## ماذا يعني «الرأس المنفصل»؟

**HEAD** هو مؤشر «أين أنت الآن». طبيعيًا يشير إلى **فرع** (main مثلًا)،
والفرع يشير لآخر commit — فكل commit جديد يحرك الفرع معك.

عند `checkout` لرقم commit مباشرة، يقفز HEAD **فوق الفروع كلها** ويقف
على الـ commit نفسه: أنت الآن «سائح» في نقطة زمنية — ترى المشروع كما
كان بالضبط، وأي فرع لا يتحرك معك.

| تفعلها عادة عبر | مثال |
|-----------------|------|
| زيارة commit قديم | `git checkout abc1234` |
| فحص وسم إصدار | `git checkout v2.0` |
| أثناء rebase تفاعلي أو bisect | حالات مؤقتة مدارة تلقائيًا |

## السيناريو الآمن: سائح يتفرج ويعود

جئت تقرأ كودًا قديمًا فقط؟ تجوّل براحتك ثم عد لديارك:

```bash
git switch main     # عدت — وHEAD التصق بالفرع من جديد
```

انتهى. لا شيء حدث، ولا شيء كان سيحدث.

## السيناريو الخطر الوحيد: بنيت شيئًا هنا

جربت فكرة وكتبت commits **داخل الحالة المنفصلة**؟ هذه الـ commits لا
يحملها أي فرع — إن غادرت الآن أصبحت «يتيمة» وسيكنسها Git لاحقًا.

**الإنقاذ قبل المغادرة — سطر واحد:**

```bash
git switch -c experiment-rescue
# فرع جديد وُلد هنا حاملًا كل commits تجربتك — صارت بأمان للأبد
```

**غادرت فعلًا قبل الإنقاذ؟** الوقت لم يفت غالبًا:

```bash
git reflog                    # سجل كل تحركات HEAD — ابحث عن commit تجربتك
git branch rescue abc9876     # اربطه بفرع وانتهى الرعب
```

> 💡 reflog هو «التأمين الخفي» في Git — يحفظ تحركاتك حتى خارج الفروع
> لأسابيع. احفظ وجوده لكل حوادث «ضاع عملي!».

## كيف تتجنبها أصلًا؟

- للتنقل بين الفروع استخدم **`git switch اسم-الفرع`** — لا تقع بالحالة
  خطأً معها.
- أردت البناء على نقطة قديمة؟ أنشئ فرعًا منها فورًا بدل زيارتها:

```bash
git switch -c fix-old-bug abc1234   # فرع جديد من commit قديم — بلا انفصال
```

- تعرف أنك ستزور فقط؟ ادخل بوعي واخرج بـ switch — الحالة صديقة للزائر
  الواعي.

## قائمة تحقّق سريعة

- الرسالة ظهرت؟ اهدأ — لا شيء ضاع، أنت «زائر» فقط.
- تفرجت فقط؟ → `git switch main` وانتهى.
- كتبت commits هنا؟ → قبل أي مغادرة: `git switch -c اسم-جديد`.
- غادرت وضاعت؟ → `git reflog` ثم `git branch rescue <hash>`.
- مستقبلًا: switch للتنقل، وفرع جديد فوري لأي بناء على القديم.

## الخلاصة

detached HEAD ليست عطلًا بل وضع «زيارة بلا فرع». القاعدة كلها: تفرّج
بحرية وعد بـ switch — وإن بنيت شيئًا فاربطه بفرع **قبل** المغادرة،
وreflog شبكة أمانك إن نسيت.
