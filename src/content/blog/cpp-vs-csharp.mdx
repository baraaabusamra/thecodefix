**C++** و **C#** يتشابهان في الاسم لكنهما مختلفان في الفلسفة والاستخدام.

## C++ — الأداء الأقصى ➕

[C++](/learn/cpp) تعطيك **تحكّمًا مباشرًا في الذاكرة** وأقصى سرعة، وهي خيار
محرّكات الألعاب الضخمة والأنظمة عالية الأداء.

- ✅ أسرع أداء ممكن
- ✅ تحكّم كامل في الموارد
- ❌ إدارة يدوية للذاكرة (أصعب)

## C# — الإنتاجية والـ .NET #️⃣

[C#](/learn/csharp) لغة مايكروسوفت الحديثة، تدير الذاكرة تلقائيًّا وتركّز على
سرعة التطوير، وهي لغة محرّك Unity.

- ✅ أسهل وأسرع في الكتابة
- ✅ إدارة تلقائية للذاكرة
- ✅ مثالية لـ Unity وتطبيقات Windows

## مثال عملي: تخصيص وتحرير الذاكرة

**C++** — أنت المسؤول عن التحرير (أو تستخدم Smart Pointers لأتمتته):

```cpp
#include <memory>

// بدون smart pointer: عليك استدعاء delete يدويًّا، ونسيانها = تسريب ذاكرة
auto player = std::make_unique<Player>("Ali");
// يُحرَّر تلقائيًّا عند خروج player من النطاق (RAII) — بلا Garbage Collector
```

**C#** — يتولّى Garbage Collector كل شيء نيابةً عنك:

```csharp
var player = new Player("Ali");
// لا حاجة لتحرير يدوي — الـ GC يجمع الكائنات غير المُستخدَمة دوريًّا
```

الفرق الجوهري: C++ تعطيك تحكّمًا حتميًّا (تعرف بالضبط متى تُحرَّر الذاكرة عبر
RAII)، بينما C# تعطيك راحة بالاعتماد على GC — لكن بثمن توقّفات (Pause) غير
حتمية قصيرة قد تُربك تطبيقات الوقت الحقيقي الحسّاسة جدًّا للتأخير.

## جدول المقارنة

| الجانب | C++ | C# |
|--------|-----|-----|
| الأداء | الأقصى | ممتاز |
| إدارة الذاكرة | يدوية (أو RAII/Smart Pointers) | تلقائية (Garbage Collector) |
| سهولة التعلّم | أصعب | أسهل |
| الألعاب | Unreal Engine | Unity |
| التوقّف الزمني (Latency) | حتمي ومتوقَّع | قد يتوقّف لحظيًّا بسبب GC |
| منصّة العمل الأساسية | مستقلّة عن أي منصّة | .NET (لكن أصبحت عابرة للمنصّات) |

## خطأ شائع عند الاختيار

الافتراض بأن "C# أبطأ دائمًا" غير دقيق — في أغلب التطبيقات العادية (تطبيقات
سطح مكتب، خوادم، ألعاب مستقلّة عبر Unity) الفرق غير محسوس عمليًّا. اختر C++
فعليًّا فقط حين تحتاج تحكّمًا حتميًّا بالذاكرة والزمن (محرّكات ألعاب AAA،
أنظمة تداول عالية التردّد)، لا لمجرّد أنها "أسرع نظريًّا".
