كل التحديثات يلي غطّيناها بمقالات سابقة عن Next.js كانت ميزات جديدة —
Turbopack، Cache Components، Instant Navigations. هذا المقال مختلف:
تحديث **أمني** حرج، ولازم يوصل لكل مطوّر Next.js بغض النظر هل يتابع كل
إصدار أو لأ.

## شو صار بالضبط

بتاريخ 25 أغسطس 2026، أصدر فريق Next.js تحديثًا أمنيًا (Active LTS
`16.3.3` وMaintenance LTS `15.5.24`) يصلح **ثغرتين منفصلتين**، كل وحدة
منهم تسمح بتنفيذ كود عن بُعد بدون أي مصادقة (Unauthenticated RCE) —
أعلى مستوى خطورة ممكن لثغرة برمجية.

## الثغرة الأولى: صور AVIF عبر next/image

**GHSA-2xp9-vwfh-vxw4** — فيض ذاكرة (heap buffer overflow) بمكتبة
`libheif`، اللي تعتمد عليها حزمة `sharp` المستخدمة داخليًا بـ
`next/image` لمعالجة الصور. ملف AVIF مصمّم بعناية (بمراجع تشفير متداخلة
تخلق طبقتَي شفافية (alpha) بعمق بت مختلف) يخلي `libheif` يكتب تقريبًا
16 كيلوبايت خارج حدود الذاكرة المخصّصة له.

النتيجة العملية: أي endpoint يشغّل تحسين صور Next.js (next/image
Optimization) على صورة AVIF يتحكّم بمحتواها طرف خارجي — رفع صورة من
مستخدم، أو صورة من رابط خارجي مسموح بـ `remotePatterns` — معرّض لتنفيذ
كود على الخادم، بدون أي تسجيل دخول مطلوب من المهاجم.

> 💡 لو تذكر [درس الصور والخطوط](/learn/nextjs/17-images-fonts) بمسار
> Next.js، هاي بالضبط الميزة (next/image) اللي بيتكلم عنها هذا الإصلاح.

**من المتأثر؟** أي نسخة Next.js `>= 10.0.0` و`< 15.5.24`، أو أي نسخة من
خط 16 أقل من `16.3.3`.

**الإصلاح**: النسخ المُحدَّثة تعطّل تحسين AVIF مؤقتًا لحد ما يوصل إصلاح
`libheif` نفسه لأعلى بالسلسلة (upstream) — يعني الترقية تقفل الثغرة فورًا
حتى قبل ما `libheif` نفسها تُصلَح بشكل نهائي.

## الثغرة الثانية: مسارات على استضافة ويندوز فقط

**CVE-2026-75604** (GHSA-p293-qw3h-jr36) — تخصّ تطبيقات Next.js
مستضافة على خادم يشغّل **ويندوز تحديدًا** (لينكس وmacOS غير متأثرَين
إطلاقًا)، وتستخدم Pages Router أو App Router **بدون** تفعيل
[Cache Components](/learn/nextjs/27-cache-components). معالجة مسار
طلب معيّن على نظام ملفات ويندوز تسمح بالهروب من جذر التطبيق والوصول
لمواقع خارجه على القرص — وبالتالي تنفيذ كود عن بُعد، بدون مصادقة.

**من المتأثر؟** نسخ `13.4.0` – `15.5.23`، و`16.0.0` – `16.3.2` — بس
فقط لو الاستضافة على ويندوز. ما يوجد أي حل بديل غير الترقية — لو
مشروعك مستضاف على خادم ويندوز، حدّث فورًا.

> 💡 هذي ثغرة إضافية تدعمك تنتقل لـ Cache Components — التطبيقات
> المفعّلة فيها الميزة أصلًا خارج نطاق هذا المسار المتأثر.

| | AVIF / next/image | مسارات ويندوز |
|---|---|---|

| المنصّة المتأثرة | كل المنصّات | ويندوز فقط |
| الشرط | استخدام next/image على AVIF من مصدر غير موثوق | Pages/App Router بدون Cache Components |
| الإصلاح | 16.3.3 أو 15.5.24 | 16.3.3 أو 15.5.24 |
| حل بديل مؤقت | تعطيل AVIF بالتحديث نفسه | لا يوجد — الترقية إلزامية |

## كيف تحدّث

```bash
# لو مشروعك على خط الإصدار 16
npm install next@16.3.3

# لو مشروعك لسا على خط الإصدار 15
npm install next@15.5.24
```

بعد التحديث، تأكّد من رقم النسخة الفعلي:

```bash
npm ls next
```

## هل موقعي على خطر فعلي؟

لو مستضاف على **Vercel**، الشركة أعلنت إنه كل التطبيقات هناك محمية
تلقائيًا من الثغرتين، بدون أي إجراء إضافي مطلوب منك. لو مستضاف بأي مكان
تاني — خادمك الخاص، VPS، حاوية Docker، أي منصّة استضافة ثانية — الترقية
مسؤوليتك أنت مباشرة، ولازم تصير جزء من روتين النشر يلي تعلّمته
بـ[درس النشر والتحسين](/learn/nextjs/23-deployment-optimization).

## الخلاصة

ثغرتان بأعلى درجة خطورة (CVSS فوق 9 لكل منهما)، تنفيذ كود عن بُعد بدون
مصادقة، وإصلاح متوفر فورًا بدون أي كسر توافقي معروف. لا داعي للذعر —
بس لا داعي أيضًا للتأجيل: حدّث `next` لآخر نسخة أمان بأقرب فرصة، خصوصًا
لو تطبيقك يعالج صور مرفوعة من مستخدمين أو مستضاف على ويندوز.

[تابع مسار Next.js الكامل بالعربي](/learn/nextjs) — يشمل الصور والخطوط،
Cache Components، والنشر والتحسين بالتفصيل.
