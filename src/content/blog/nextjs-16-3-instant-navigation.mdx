Next.js 16 (اللي غطّيناه بمقال سابق) جاب Cache Components كنموذج تخزين مؤقّت
صريح. بعد أقل من شهر، Next.js 16.3 — الإصدار المستقر من 3 أغسطس 2026 — بنى
فوقه ميزة اسمها **Instant Navigations**: التنقّل بين صفحات تطبيقك بسرعة
تطبيق صفحة واحدة (SPA)، بدون ما تفقد فوائد الخادم.

## الفكرة الأساسية

بدل الاختيار بين "جلب الصفحة كاملة مسبقًا" أو "بلا جلب مسبق نهائيًا"، كل
مسار بتطبيقك يتصرّف الآن بواحدة من ثلاث طرق:

| الطريقة | شو يصير | متى تستخدمها |
|---|---|---|
| **Stream** | هيكل تحميل فوري عبر `<Suspense>`، والمحتوى يتدفّق بعده | مسار عليه حالة تحميل واضحة أصلًا |
| **Cache** | تصيير مخزَّن يظهر فورًا عبر `'use cache'` | بيانات ثابتة نسبيًا وتقدر تخزّنها |
| **Block** | تعطيل صريح بـ `export const instant = false` | مسار لازم يبقى مرتبطًا بالخادم بالكامل |

## التفعيل

الميزة مبنية فوق Cache Components، فتحتاج تفعيل الاثنين معًا:

```tsx
// next.config.ts
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  cacheComponents: true,
  partialPrefetching: true,
};

export default nextConfig;
```

## Partial Prefetching: هيكل واحد لكل مسار

هذا الجزء الأذكى بالميزة: Next.js يستخرج هيكل تحميل (shell) قابل لإعادة
الاستخدام من كل مسار ويخزّنه على العميل مرّة وحدة. لو عندك 20 رابط
`<Link>` كلها تشاور على `/chat/[id]`، ما راح يجلب هيكل الصفحة 20 مرّة —
مرّة وحدة بس، وكل رابط منها يعرضه فورًا عند الضغط.

فيه أيضًا أداة جديدة بـ Next.js DevTools اسمها Navigation Inspector تخليك
توقف عند مرحلة الـ shell لأي مسار وتشوف بالضبط شو انجلب مسبقًا — مفيدة
لما مسار ما يتصرّف "فوري" متل ما توقّعت.

## تحسينات أخرى بـ 16.3

Instant Navigations هي الإضافة الأبرز، بس الإصدار جاب معه تحسينات أداء
ملموسة كمان:

- **ذاكرة أقل بالتطوير**: جلسات `next dev` الطويلة تستهلك أقل بكثير من ذاكرة
  Turbopack مقارنة بالإصدارات السابقة.
- **كاش بناء دائم افتراضي**: التخزين المؤقّت الدائم لـ Turbopack بأوامر البناء
  (كان تجريبيًا بإصدارات سابقة) صار افتراضيًا، فالبناءات المتكررة تقرأ نتائج
  غير متغيّرة من الكاش بدل إعادة حسابها.
- **تصيير أسرع على الخادم**: قدرة أعلى على التعامل مع عدد أكبر من الطلبات
  المتزامنة تحت ضغط.

## هل يلزمك تفعيلها الآن؟

لا داعي للاستعجال. الميزة اختيارية بالكامل، وتطبيقك الحالي يشتغل بدون أي
تغيير لو ما لمست `next.config.ts`. أفضل مقاربة لمشروع قائم: فعّل
`cacheComponents` و`partialPrefetching` عالمستوى العام، وحط
`export const instant = false` بس على المسارات اللي لسا ما جاهزة (ما فيها
`'use cache'` ولا `<Suspense>` مناسب) — وحوّلها وحدة وحدة.

## الخلاصة

Instant Navigations توسّع فلسفة Cache Components: تحديد صريح لشو يُخزَّن
وشو يبقى ديناميكيًا، بدل تخمين ضمني من Next.js. لو مشروعك يستخدم Cache
Components أصلًا، تفعيل الميزة خطوة طبيعية تالية لتحسين إحساس التنقّل
بتطبيقك.
