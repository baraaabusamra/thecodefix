عند اختيار تقنية لبناء التطبيقات، يبرز اسمان كبيران: **React** من Meta و
**Flutter** من Google. كلاهما يبني تطبيقات لعدّة منصّات بكود واحد، لكنهما
يختلفان جوهريًّا. لنقارن.

## React — قوّة JavaScript ⚛️

[React](/learn/react) مكتبة لبناء واجهات المستخدم بلغة **JavaScript**. للويب
نستخدم React مباشرةً، وللموبايل نستخدم **React Native**.

**مميّزاته:**
- يعتمد على [JavaScript](/learn/javascript) — أكثر اللغات انتشارًا.
- مجتمع ضخم ومكتبات لا تُحصى.
- نفس المعرفة تخدمك في الويب والموبايل.

## Flutter — أداء أصلي بواجهات موحّدة 🦋

[Flutter](/learn/flutter) إطار من Google يستخدم لغة **Dart**، ويرسم الواجهة
بنفسه فيعطي مظهرًا موحّدًا وأداءً قريبًا من التطبيقات الأصلية.

**مميّزاته:**
- أداء عالٍ (يُترجَم إلى كود أصلي).
- واجهة موحّدة تمامًا على كل المنصّات.
- منصّة واحدة للموبايل والويب وسطح المكتب.

## مثال عملي: نفس الزرّ البسيط

**React Native**:

```jsx
function CounterButton() {
  const [count, setCount] = useState(0);
  return (
    <TouchableOpacity onPress={() => setCount(count + 1)}>
      <Text>ضغطت {count} مرّة</Text>
    </TouchableOpacity>
  );
}
```

**Flutter**:

```dart
class CounterButton extends StatefulWidget {
  @override
  State<CounterButton> createState() => _CounterButtonState();
}
class _CounterButtonState extends State<CounterButton> {
  int count = 0;
  @override
  Widget build(BuildContext context) {
    return GestureDetector(
      onTap: () => setState(() => count++),
      child: Text('ضغطت $count مرّة'),
    );
  }
}
```

الفرق البنيوي هنا واضح: React (وReact Native) يستخدم Hooks (`useState`) في
دالّة بسيطة، بينما Flutter يعتمد نموذج فئات (Classes) وودجت State منفصل.
كودّ Flutter أطول للحالات البسيطة، لكنه يعطيك حدودًا صريحة وواضحة بين "شكل
الواجهة" و"منطق الحالة" — بعض الفرق يفضّل هذا الفصل الصريح.

## جدول المقارنة

| الجانب | React / React Native | Flutter |
|--------|----------------------|---------|
| اللغة | JavaScript / TypeScript | Dart |
| المنصّات | الويب + الموبايل | الموبايل + الويب + سطح المكتب |
| الأداء | جيّد جدًّا | ممتاز (شبه أصلي) |
| حجم المجتمع | ضخم جدًّا | كبير ومتنامٍ |
| منحنى التعلّم | سهل لمن يعرف JS | يتطلّب تعلّم Dart |
| طريقة الرندر | يستخدم مكوّنات المنصّة الأصلية | يرسم كل بكسل بنفسه (Skia/Impeller) |
| اتّساق المظهر بين iOS/Android | قد يختلف قليلًا | متطابق 100% دائمًا |

## خطأ شائع عند الاختيار

الظنّ بأن "الأداء شبه الأصلي" لـ Flutter يعني أنه دائمًا الخيار الأسرع عمليًّا
— في الواقع React Native (خصوصًا مع New Architecture الحديثة) يقترب كثيرًا
في أغلب التطبيقات العادية. الفارق الحاسم عمليًّا غالبًا ليس الأداء الخام، بل:
هل فريقك يعرف JavaScript بالفعل (فـ React Native أسرع للانطلاق)، أم تبدأ من
الصفر بلا تفضيل (فتعلّم Dart لا يكلّفك وقتًا إضافيًّا حقيقيًّا)؟

## كيف تختار؟

- تعرف **[JavaScript](/learn/javascript)** بالفعل أو تريد الويب والموبايل معًا؟ → **[React](/learn/react)**.
- تريد **أعلى أداء وواجهات موحّدة** ولا تمانع تعلّم Dart؟ → **[Flutter](/learn/flutter)**.

لا يوجد فائز مطلق — كلاهما يبني تطبيقات احترافية متعدّدة المنصّات. القرار يعتمد
على لغتك المفضّلة وأهداف مشروعك.
