**Go** (من جوجل) و **Rust** لغتان حديثتان تنموان بسرعة، لكنهما تخدمان أهدافًا
مختلفة.

## Go — البساطة والخوادم 🐹

[Go](/learn/go) لغة جوجل، صُمّمت لتكون **بسيطة وسريعة التطوير**، وهي خيار شائع
للخوادم والخدمات السحابية و DevOps.

- ✅ سهلة التعلّم وبسيطة
- ✅ ممتازة للخوادم والأنظمة الموزّعة
- ✅ سرعة تجميع وتنفيذ عالية

## Rust — الأمان والأداء الأقصى 🦀

[Rust](/learn/rust) تركّز على **أمان الذاكرة بلا Garbage Collector**، فتعطي أداءً
بمستوى C++ مع أمان أعلى.

- ✅ أمان ذاكرة مضمون وقت الترجمة
- ✅ أداء بمستوى C++
- ❌ منحنى تعلّم أعلى (نظام Ownership)

## مثال عملي: التزامن (Concurrency)

**Go** — التزامن مدمج في اللغة نفسها عبر Goroutines وقنوات بسيطة:

```go
func worker(ch chan int) {
    for n := range ch {
        fmt.Println("معالجة:", n)
    }
}

ch := make(chan int)
go worker(ch)   // goroutine خفيفة جدًّا — آلاف منها لا تُثقل الذاكرة
ch <- 42
```

**Rust** — لا يوجد Garbage Collector، فالمترجم نفسه يمنع أخطاء الذاكرة قبل التشغيل:

```rust
fn main() {
    let data = vec![1, 2, 3];
    let handle = std::thread::spawn(move || {
        println!("معالجة: {:?}", data); // data انتقلت (moved) لهذا الـ thread فقط
    });
    handle.join().unwrap();
    // data.push(4); // ❌ خطأ ترجمة: data لم تعد ملكك بعد النقل
}
```

الفرق الجوهري: Go تعطيك تزامنًا سهلًا وسريع الكتابة لكن بثمن Garbage Collector
(توقّفات صغيرة محتملة)، بينما Rust يمنع أخطاء "التعديل من مكانين معًا" وقت
**الترجمة نفسها** عبر نظام Ownership — لا GC إطلاقًا، لكن ثمنه تعلّم أعمق.

## جدول المقارنة

| الجانب | Go | Rust |
|--------|-----|------|
| سهولة التعلّم | سهلة | أصعب |
| الأداء | عالٍ | الأقصى |
| إدارة الذاكرة | تلقائية (GC) | يدوية آمنة (بلا GC، Ownership) |
| الأنسب لـ | الخوادم والسحابة | الأنظمة الحرجة |
| نموذج التزامن | Goroutines + Channels | Threads + فحص الملكية وقت الترجمة |
| سلامة الذاكرة | مضمونة وقت التشغيل (GC) | مضمونة وقت الترجمة (بلا تكلفة تشغيل) |

## خطأ شائع عند الاختيار

اختيار Rust "لأنها الأسرع" لمشروع لا يحتاج فعليًّا هذا المستوى من الأداء
يكلّفك وقت تطوير كبيرًا بلا فائدة حقيقية — منحنى تعلّم Ownership حقيقي
ويبطئ فريقًا كاملًا في البداية. إن كان مشروعك خدمة ويب أو أداة سحابية عادية،
Go عادةً الخيار الأذكى: سريعة كفاية، وأسرع بكثير في الإنتاجية.
