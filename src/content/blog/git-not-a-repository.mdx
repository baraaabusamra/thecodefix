تكتب `git status` أو `git add .` فيصفعك [Git](/learn/git) بالرسالة الشهيرة:

```
fatal: not a git repository (or any of the parent directories): .git
```

هذا أكثر أخطاء Git شيوعًا للمبتدئين، ومعناه بسيط جدًا بمجرد أن تفهم كيف
يبحث Git عن المستودع. وله ثلاث رسائل شقيقة تشبهه في الاسم وتختلف في السبب،
نفصلها كلها هنا.

## كيف يفكّر Git: مجلد .git هو المستودع

كل مستودع Git هو مجلد عادي يحتوي مجلدًا مخفيًّا اسمه **`.git`**، فيه كل التاريخ
والفروع والإعدادات. عندما تشغّل أي أمر Git، يبحث عن `.git` في:

1. المجلد الحالي.
2. ثم المجلد الأب، ثم أبيه… حتى جذر القرص.

لهذا يعمل `git status` من أي مجلد فرعي داخل مشروعك: من `src/deep` يصعد Git حتى
يجد `.git` في الجذر. وإن لم يجده في أي مستوى، ظهرت الرسالة. فهي لا تقول «شيء
مكسور»، بل: **«أنت واقف خارج أي مستودع»**.

## التشخيص في 10 ثوانٍ

```bash
pwd                               # أين أنا الآن؟
ls -a                             # هل يوجد .git هنا؟
git rev-parse --show-toplevel     # أين جذر المستودع الذي أنا داخله؟
```

```powershell
# Windows PowerShell
Get-Location
Get-ChildItem -Force              # يعرض المجلدات المخفية مثل .git
```

`git rev-parse --show-toplevel` يطبع مسار جذر المستودع إن كنت داخله (من أي مجلد
فرعي)، أو يعطيك نفس رسالة `not a git repository` إن كنت خارجه. أسرع سؤال
«نعم أو لا».

## الأسباب وحلولها

### 1) أنت في المجلد الخطأ (السبب الأول بفارق كبير)

فتحت طرفية جديدة فبدأت في مجلد المستخدم بدل مجلد المشروع:

```bash
cd path/to/my-project   # انتقل إلى مجلد مشروعك
git status              # يعمل الآن
```

> 💡 في VS Code افتح المجلد نفسه (File ← Open Folder) ثم الطرفية بـ Ctrl+`،
> فتُفتح في جذر المشروع مباشرة.

### 2) المشروع لم يُهيَّأ كمستودع بعد

مجلد أنشأته بنفسك لا يصبح مستودعًا تلقائيًّا:

```bash
cd my-project
git init                # ينشئ مجلد .git: المشروع صار مستودعًا
git add .
git commit -m "أول commit"
```

(شرح كامل في [درس git init وgit clone](/learn/git/07-init-clone).)

### 3) استنسخت ونسيت الدخول للمجلد

```bash
git clone https://github.com/user/repo.git
cd repo                 # git clone ينشئ مجلدًا جديدًا باسم المستودع
```

`git clone` لا يحوّل المجلد الحالي لمستودع، بل ينشئ مجلدًا جديدًا داخله. نسيان
`cd repo` بعده سبب كلاسيكي للخطأ.

### 4) مجلد .git حُذف أو لم يُنسخ

إن كان المشروع يعمل سابقًا وتوقّف فجأة، فتأكد بـ `ls -a`. أسباب اختفائه
الشائعة: نسخ المشروع بأداة تتجاهل الملفات المخفية، أو تنزيله كملف ZIP من
GitHub (الـ ZIP لا يحتوي `.git` أصلًا)، أو برنامج تنظيف.

- إن كان المشروع على GitHub: أسهل حل استنساخه من جديد، ثم نقل تعديلاتك إليه.
- إن كان محليًّا فقط: `git init` يبدأ تاريخًا جديدًا، والتاريخ القديم ضاع مع
  `.git` المحذوف. (وهذا أقوى سبب لرفع مشروعك إلى remote مبكرًا.)

ونفس الفكرة داخل **Docker وCI**: إن كان `.dockerignore` يستثني `.git` (وهذا
شائع وصحيح لتصغير الصورة)، فأي أمر `git` داخل البناء، مثل
`git rev-parse HEAD` لطباعة رقم الإصدار، سيفشل بنفس الرسالة. مرّر رقم الـ commit
كمتغير بناء من خارج الحاوية بدل قراءته من داخلها.

### 5) worktree أو submodule انقطع عن مستودعه

في الـ worktree والـ submodule، `.git` **ملف** لا مجلد، يشير لمكان المستودع
الحقيقي:

```
gitdir: /home/sara/proj/.git/worktrees/wt
```

جرّبنا نقل مجلد المستودع الأصلي لمكان آخر، فصار كل أمر داخل الـ worktree يعطي:

```
fatal: not a git repository: /home/sara/proj/.git/worktrees/wt
```

لاحظ الفرق: الرسالة هنا تذكر **مسارًا محددًا** لا «parent directories»، أي أن
Git وجد الإشارة لكن الهدف اختفى. أعد المستودع الأصلي لمكانه، أو أصلح الإشارة
من مكانه الجديد:

```bash
cd ~/new-place/proj
git worktree repair ../wt     # يحدّث الإشارات في الاتجاهين
```

جرّبناها: بعد `repair` عاد `git status` داخل الـ worktree يعمل فورًا. وإن كنت
حذفت الـ worktree نفسه، فنفّذ `git worktree prune` من المستودع الأصلي لتنظيف
سجلّه القديم.
(والـ submodules لها [درس مستقل](/learn/git/31-submodules).)

### 6) متغير `GIT_DIR` يشير لمكان خاطئ

```
fatal: not a git repository: '/nope'
```

مرة أخرى مسار محدد في الرسالة. متغير البيئة `GIT_DIR` يجبر Git على استخدام مسار
معيّن بدل البحث، وبعض السكربتات تضبطه وتنساه. تحقق بـ `echo $GIT_DIR`، واحذفه
بـ `unset GIT_DIR`.

## الرسائل الشقيقة: تشبهه ولا تعنيه

### `fatal: not in a git directory`

```bash
git config user.name "Sara"
# fatal: not in a git directory
```

جرّبناها: تظهر حين تكتب إعدادًا بـ `git config` **بلا `--global`** وأنت خارج أي
مستودع. بلا `--global`، يكتب Git الإعداد في `.git/config` للمستودع الحالي، ولا
يوجد مستودع. وهذا يحدث غالبًا أول يوم، أثناء ضبط الاسم والبريد:

```bash
git config --global user.name "Sara"
git config --global user.email "sara@example.com"
```

(إعداد Git لأول مرة بالتفصيل في [درس التثبيت والإعداد](/learn/git/06-install-config).)

### `fatal: 'origin' does not appear to be a git repository`

```
fatal: 'origin' does not appear to be a git repository
fatal: Could not read from remote repository.
```

جرّبنا `git push origin main` في مستودع بلا remote، وهذا ناتجه. **مجلدك سليم**،
والمشكلة في الـ remote: لا يوجد remote اسمه `origin`، أو رابطه خاطئ.

```bash
git remote -v                                         # ما الروابط الموجودة؟
git remote add origin https://github.com/user/repo.git
git remote set-url origin https://github.com/user/repo.git   # لتصحيح رابط موجود
```

وإن كان الـ remote صحيحًا والرفض من GitHub نفسه، فهذه قصة أخرى:
[حل git push rejected](/blog/git-push-rejected).

### `fatal: detected dubious ownership in repository`

```
fatal: detected dubious ownership in repository at '/path/to/repo'
To add an exception for this directory, call:

	git config --global --add safe.directory /path/to/repo
```

المستودع موجود، لكن **مالك المجلد مستخدم آخر** غيرك (مجلد نسخته من قرص خارجي، أو
أنشأته بـ `sudo`، أو مجلد مشترك داخل حاوية). Git يرفض العمل فيه حماية لك، لأن
إعدادات مستودع يملكه غيرك قد تشغّل أوامر باسمك. وبعض المحررات تعرض هذه الحالة
كأن المجلد «ليس مستودعًا».

الحل الأنظف أن تصحّح المالك (`sudo chown -R $USER path/to/repo` على Linux
وmacOS). وإن كان المجلد موثوقًا ومقصودًا أن يملكه غيرك، فأضفه كاستثناء بالأمر
الذي تقترحه الرسالة نفسها.

## جدول التمييز السريع

| الرسالة | المعنى | الحل |
| --- | --- | --- |
| `not a git repository (or any of the parent directories)` | لا `.git` من هنا حتى الجذر | `cd` أو `git init` أو `git clone` |
| `not a git repository: /path/...` | الإشارة موجودة والهدف مفقود | worktree أو submodule أو `GIT_DIR` |
| `not in a git directory` | `git config` بلا `--global` خارج مستودع | أضف `--global` |
| `'origin' does not appear to be a git repository` | الـ remote غير موجود أو خاطئ | `git remote -v` ثم `add` أو `set-url` |
| `detected dubious ownership` | المجلد يملكه مستخدم آخر | صحّح المالك أو `safe.directory` |

جرّبنا كل رسالة في الجدول على Git 2.43، وتحققنا من مصدر Git الحالي أن نص
`not in a git directory` ما زال يصدر من نفس الحالة.

## قائمة تحقّق سريعة

- `git rev-parse --show-toplevel`: هل أنا داخل مستودع؟ وأين جذره؟
- `ls -a` (أو `Get-ChildItem -Force`): هل يوجد `.git`؟
- نسيت `cd` بعد `git clone`؟ أو نزّلت المشروع ZIP؟
- مشروع جديد؟ ← `git init` مرة واحدة في جذره فقط.
- الرسالة فيها مسار محدد؟ ← worktree أو submodule أو `GIT_DIR`.
- `git config` بلا `--global`؟ ← هذه `not in a git directory`.
- `origin does not appear`؟ ← المشكلة في `git remote -v`، لا في مجلدك.

## الخلاصة

`fatal: not a git repository` تعني «لا يوجد `.git` من هنا حتى جذر القرص». أغلب
الحالات تُحل بـ `cd` إلى المجلد الصحيح، والباقي بـ `git init` لمشروع جديد أو
`git clone` لمشروع موجود. وإن كانت الرسالة شقيقة لها، فالجدول أعلاه يخبرك أين
تبحث.
