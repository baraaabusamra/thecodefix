سوق أدوات الذكاء الاصطناعي للمبرمجين شهد نموًا ملحوظًا خلال السنوات الأخيرة. هاد دليل عربي مرتّب لأهم الفئات والأدوات المتاحة حاليًا، استنادًا إلى وثائقها الرسمية، حتى تعرف وين تبلش بدون ما تضيع بين عشرات الخيارات.

## الفئة 1: أدوات مدمجة مع المحرّر ومنصّة التطوير

أدوات تعمل كإضافة داخل محرّر الكود الذي تستخدمه، مع تكامل مباشر مع المنصّات المحيطة بالكود:

- **GitHub Copilot** — بحسب وثائق GitHub الرسمية، يقدّم حاليًا إكمالًا تلقائيًا داخل المحرّر، ودردشة، ووضع Agent Mode داخل المحرّرات المدعومة، إضافةً إلى **Copilot Coding Agent** على GitHub.com الذي يعمل بشكل غير متزامن عبر تكليفه بـ @github-copilot على Issue لتنفيذ مهام ورفع Pull Requests.
- **Tabnine** — يركّز على الخصوصية وتشغيل نماذج محليّة.

**قد يناسب من:** يعمل بشكل مكثّف داخل بيئة GitHub ويريد تكاملًا طبيعيًا مع Issues و Pull Requests، أو يحتاج خيارًا يركّز على الخصوصية.

## الفئة 2: محرّرات مستقلّة مبنية حول الذكاء الاصطناعي

محرّرات كود مستقلة (غالبًا مبنية على أساس VS Code) صُمّمت بحيث يكون الذكاء الاصطناعي جزءًا أساسيًا من تجربة التحرير، لا مجرّد إضافة:

- **Cursor** — محرّر مستقل يوفّر وضع Agent ضمن تجربة التحرير.
- **Windsurf** — محرّر مستقل يندرج ضمن نفس الفئة.

**قد يناسب من:** يريد تجربة تحرير متّسقة حيث الذكاء الاصطناعي جزء من كل خطوة من خطوات التطوير، ويريد تنزيل محرّر جديد والاعتماد عليه.

## الفئة 3: وكلاء يعملون من سطر الأوامر أو الخلفية

أدوات تعمل من سطر الأوامر أو ضمن منصّة سحابية، وتستطيع تنفيذ مهام **كاملة** بشكل شبه مستقل (تخطيط، كتابة، تشغيل اختبارات، فتح Pull Requests):

- **Claude Code** — وكيل يعمل من Terminal، يدعم subagents متوازية لمهام مختلفة.
- **OpenAI Codex** (النسخة الوكيلية الحديثة) — ينفّذ مهام من Terminal كذلك.
- **GitHub Copilot Coding Agent** (خَلَف GitHub Copilot Workspace الذي أُغلق في مايو 2025 بحسب GitHub Changelog) — يعمل على GitHub.com.

**قد يناسب من:** لديه مهام طويلة ومعقّدة (تنفيذ ميزة كاملة، إصلاح باق كبير، refactor واسع) ويريد تفويضها لوكيل ينفّذها نيابة عنه.

## مصطلح جديد يستحق المعرفة: Vibe Coding

**Vibe Coding** مصطلح انتشر مؤخرًا، ويوصف أسلوب برمجة تعتمد فيه بشكل كبير على **وصف** ما تريده للذكاء الاصطناعي (بالحوار الطبيعي) بدل كتابة كل سطر يدويًا — يشتغل ممتاز للنماذج الأولية السريعة وتجربة الأفكار، لكن يحتاج مراجعة دقيقة وفهم حقيقي قبل أي استخدام بمشروع إنتاجي حقيقي.

## جدول اختيار سريع

| طبيعة المهمة | فئات الأدوات التي قد تناسب |
|-------------|-------------------|
| إكمال سطر أو دالة أثناء الكتابة | أدوات مدمجة مع المحرّر (Copilot، Tabnine) |
| بناء ميزة متوسطة بواجهة مرئية | محرّرات مستقلّة (Cursor، Windsurf) |
| مهمة كبيرة مستقلة (ميزة كاملة، باق معقّد) | وكلاء من سطر الأوامر أو سحابة (Claude Code، Copilot Coding Agent، Codex) |
| نموذج أولي سريع لفكرة | أيّ أداة تتيح أسلوب Vibe Coding |

> هذا الجدول مثال توجيهي وليس توصية مطلقة. الاختيار الفعلي يعتمد على بيئة عملك، المحرّر الذي تستخدمه، والأدوار التي تريد أن يقوم بها الوكيل.

## نصيحة أخيرة

**الأداة لا تغني عن فهم البرمجة.** كل هاي الأدوات تحتاج شخصًا يفهم أساسيات البرمجة ليوجّهها بشكل صحيح، ويراجع نتيجتها، ويتأكّد إنها آمنة وصحيحة. ابدأ دائمًا بتعلّم الأساسيات (راجع مسارات The Code Fix)، وبعدها استخدم هاي الأدوات لتسريع عملك، مو كبديل عن الفهم.
