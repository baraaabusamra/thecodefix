أنت زائر تتصفح، أو صاحب موقع صحيت الصبح على تنبيهات — وأمامك:

```
500 Internal Server Error
The server encountered an internal error and was unable to
complete your request.
```

أغمض رسالة في الويب: لا تفاصيل، لا سبب، لا اتجاه. لكن هذا **مقصود** —
والسبب الحقيقي مكتوب في مكان آخر تملكه أنت.

## أولًا: افهم موقعك من الخطأ

| أنت | ماذا تستطيع؟ |
|-----|---------------|
| زائر | لا شيء بيدك — العطل عند الموقع؛ أعد المحاولة لاحقًا |
| صاحب الموقع/المطور | كل شيء بيدك — والبداية دائمًا من السجلات |

عائلة 5xx كلها أعطال خادم: 500 عطل عام، 502/504 مشاكل بوابة ومهلات،
503 صيانة أو حمل زائد.

## القاعدة الذهبية: السجلات أولًا، لا التخمين

صفحة الـ 500 تخفي السبب عمدًا (حماية أمنية) — لكن الخادم كتبه كاملًا
بالسجل لحظة الانهيار:

```bash
# خوادم Nginx / Apache على لينكس
tail -50 /var/log/nginx/error.log
tail -50 /var/log/apache2/error.log

# تطبيقات Node/Python المستضافة سحابيًا
# (Vercel / Railway / Render…) → تبويب Logs في لوحة التحكم

# استضافة مشتركة (cPanel) → أيقونة Errors أو ملف error_log بمجلد الموقع
```

سطر الخطأ سيسمّي الملف والسبب حرفيًا — من هنا يبدأ كل حل حقيقي.

## الأسباب الخمسة الأشهر وعلاجها

### 1) Exception غير معالج في الكود (المطورون)

استعلام فشل، قيمة null فاجأت الكود، مكتبة رمت خطأ — أي استثناء يصعد بلا
معالجة يصبح 500. السجل يعطيك الـ stack trace كاملًا؛ عالج الحالة وأضف
معالجة أخطاء ترد بحالة مناسبة ورسالة آمنة.

### 2) متغير بيئة ناقص بعد النشر

يعمل محليًا وينهار في الإنتاج؟ الفرق الأول دائمًا: `.env` — مفتاح قاعدة
البيانات أو API غير مضبوط في بيئة الاستضافة. راجع إعدادات المتغيرات في
لوحة منصتك وقارنها بقائمة مشروعك.

### 3) قاعدة البيانات لا تستجيب

بيانات اتصال خاطئة، خادم قاعدة متوقف، أو حد اتصالات ممتلئ. علامة مميزة
بالسجل: `Connection refused` أو `Access denied` — والثانية دليلنا الكامل
فيها: [حل خطأ Access denied في MySQL](/blog/mysql-access-denied).

### 4) ووردبريس: الإضافة/الثيم/htaccess (أصحاب المواقع)

ثالوث الـ 500 في ووردبريس بعد أي تحديث:

- **الإضافات**: أعد تسمية مجلد `wp-content/plugins` مؤقتًا — رجع الموقع؟
  أعد الاسم وعطّل الإضافات واحدة واحدة حتى تجد الجانية.
- **`.htaccess` تالف**: أعد تسميته، وادخل الإعدادات → روابط دائمة → حفظ
  ليتولد نظيف.
- **حد الذاكرة**: ارفع `memory_limit` من استضافتك أو `wp-config.php`.

### 5) صلاحيات ملفات خاطئة على الخادم

رفعت ملفات بـ root أو عبثت أداة بالصلاحيات؟ المجلدات 755 والملفات 644 —
وقصة الصلاحيات كاملة في
[حل Permission denied في لينكس](/blog/linux-permission-denied).

## للمطور: لا تدع 500 يصل المستخدم أعمى

```js
// نمط Express — معالج أخطاء يسجل التفاصيل ويرد بأمان
app.use((err, req, res, next) => {
  console.error(err);                          // التفاصيل للسجل
  res.status(500).json({ error: "حدث خطأ — جرّب لاحقًا" }); // العموم بلا أسرار
});
```

والواجهة تتحقق من `res.ok` قبل قراءة الرد — وإلا انفجر عندك خطأ مضلل
ثانٍ فوق الأول: [Unexpected token in JSON](/blog/json-parse-unexpected-token).

## قائمة تحقّق سريعة

- افتح الـ error log قبل أي تخمين — السبب مكتوب فيه حرفيًا.
- يعمل محليًا لا إنتاجًا؟ → متغيرات البيئة أولًا.
- بعد تحديث ووردبريس؟ → الإضافات ثم .htaccess ثم الذاكرة.
- متقطع مع الضغط؟ → ذاكرة/اتصالات قاعدة البيانات.
- كمطور: معالج أخطاء يسجل بالتفصيل ويرد بالعموم.

## الخلاصة

خطأ 500 «صندوق أسود» للزائر فقط — أما لصاحبه فمفتوح بالكامل من السجلات.
اقرأ الـ log، سمِّ العطل، وعالج مصدره من القائمة أعلاه — ولا تشخّص من
شكل الصفحة أبدًا.

افهم بروتوكول الويب من جذوره في [مسار الشبكات وHTTP بالعربي](/learn/networking)
و[مسار Node.js](/learn/nodejs)، وأكمل سلسلة أخطاء الخوادم مع
[حل خطأ CORS](/blog/cors-error-fix) و[حل EADDRINUSE](/blog/port-already-in-use).
