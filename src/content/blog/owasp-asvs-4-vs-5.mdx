لو فريقك بنى مستند امتثال أو قائمة تحقق أمنية بالاعتماد على OWASP ASVS 4.0، عندك تحديث مهم يستاهل وقتًا فعليًا للمراجعة — مش مجرد "رقم إصدار جديد". OWASP أصدرت **ASVS 5.0** رسميًا في 30 مايو 2025 بمؤتمر Global AppSec EU ببرشلونة، وأعادت هيكلة المعيار بالكامل، لا مجرد إضافة بضعة بنود.

## الفصول: من 14 إلى 17

| # | نسخة 4.0 (2019 / 4.0.3: 2021) | # | نسخة 5.0 (مايو 2025) |
|---|---|---|---|
| V1 | Architecture | V1 | Encoding and Sanitization |
| V2 | Authentication | V2 | Validation and Business Logic |
| V3 | Session Management | V3 | Web Frontend Security |
| V4 | Access Control | V4 | API and Web Service |
| V5 | Input Validation | V5 | File Handling |
| V6 | Cryptography | V6 | Authentication |
| V7 | Logging | V7 | Session Management |
| V8 | Data Protection | V8 | Authorization |
| V9 | Communications | V9 | **Self-contained Tokens** (جديد كفصل مستقل) |
| V10 | Malicious Code | V10 | **OAuth and OIDC** (جديد كليًا) |
| V11 | Business Logic | V11 | Cryptography |
| V12 | Files & Resources | V12 | Secure Communication |
| V13 | API & Web Service | V13 | Configuration |
| V14 | Configuration | V14 | Data Protection |
| — | — | V15 | Secure Coding and Architecture |
| — | — | V16 | Security Logging and Error Handling |
| — | — | V17 | **WebRTC** (جديد كليًا) |

لاحظ العمود الأيمن مقابل الأيسر: هذا **مو إعادة تسمية بترتيب مطابق** — V1 بنسخة 4.0 كانت "المعمارية"، وV1 بنسخة 5.0 صارت "الترميز والتعقيم" (موضوع مختلف تمامًا). أي أداة أو سكريبت داخلي يفترض "V1 يعني كذا" بناءً على خبرة قديمة مع 4.0 سيعطي نتيجة خاطئة تمامًا مع 5.0.

## أهم 3 تغييرات فعلية (مو مجرد ترقيم)

### 1) Self-contained Tokens صار فصلاً مستقلاً

بنسخة 4.0، متطلبات JWT وأمان الرموز ذاتية الاحتواء كانت مبعثرة كبنود فرعية ضمن فصل المصادقة العام. بنسخة 5.0 صار لها **فصل V9 كامل** يغطي تحديدًا: التحقق من التوقيع، انتهاء الصلاحية، الخوارزميات المسموحة (رفض `alg: none`)، وتخزين الرمز بأمان بجهة العميل. لو مشروعك يعتمد على JWT كطريقة مصادقة رئيسية (شائع جدًا بالـ APIs)، هذا الفصل بمفرده يستحق مراجعة كاملة حتى لو كنت تظن أن فصل "المصادقة" العام بنسخة 4.0 كان يغطيه.

### 2) OAuth and OIDC فصل جديد بالكامل

لم يكن موجودًا كفصل مستقل بنسخة 4.0 إطلاقًا. بنسخة 5.0 (V10) صار يغطي تحديدًا مخاطر لا علاقة لها بمصادقة كلمة المرور التقليدية: التحقق من `redirect_uri` بدقة (لا تطابق جزئي)، إلزامية PKCE لتطبيقات العميل العامة (SPA وموبايل)، والتحقق من `state` لمنع CSRF بتدفق OAuth. مشروع يدمج تسجيل دخول عبر Google أو Microsoft ولا يملك بند تحقق مخصص لهذا الفصل كان عمليًا بلا تغطية رسمية له بنسخة 4.0.

### 3) WebRTC فصل جديد بالكامل

بنسخة 4.0 لم يكن اتصال الصوت/الفيديو المباشر (WebRTC) مغطى بأي فصل مخصص. فصل V17 الجديد يغطي أمان خوادم TURN، حماية الوسائط عبر DTLS/SRTP، وأمان قناة التفاوض (Signaling). ينطبق فقط لو تطبيقك يستخدم WebRTC فعليًا (مكالمات، مشاركة شاشة، بث مباشر) — لا داعي له لو لا علاقة لمشروعك بهذا.

## مثال ملموس: لماذا لا تنسخ رقم متطلب من 4.0 مباشرة

لو عندك سكريبت أو مستند سياسات داخلي يربط بند فحص بمعرّف ASVS كنص ثابت، انتقال النسخة يكسره بصمت لأن نفس الرقم صار يشير لشيء مختلف تمامًا:

```javascript
// قبل: يفترض هيكلة 4.0 (V2 = Authentication بالكامل)
const policyMap = {
  '2.1.1': 'HTTPS إلزامي على نماذج تسجيل الدخول',
};

// بعد الانتقال لـ 5.0: نفس المعرّف الحرفي "2.1.1" الآن يقع
// ضمن فصل مختلف تمامًا (V2 = Validation and Business Logic)
// -- الفحص القديم صار يشير لمتطلب لا علاقة له بالمصادقة إطلاقًا.
// الحل: لا تربط منطق التحقق برقم المتطلب وحده، اربطه بعنوانه
// النصي الكامل من نسخة 5.0 (متوفر بملف CSV الرسمي على GitHub)،
// وأعد بناء الخريطة يدويًا بعد أي ترقية إصدار كبرى.
const policyMapV5 = {
  '6.1.1': 'HTTPS إلزامي على نماذج تسجيل الدخول', // V6 = Authentication الآن
};
```

## هل تنتقل الآن؟

- **مشروع امتثال جديد يبدأ اليوم**: ابدأ بـ 5.0 مباشرة — لا سبب للبدء بنسخة لم تعد محور تطوير OWASP.
- **مشروع قائم مبني فعليًا على 4.0/4.0.3 مع مستندات تدقيق موقّعة**: لا تستعجل الترحيل الكامل قبل تخطيط فعلي؛ ابدأ بمراجعة الفصول الثلاثة الجديدة (V9، V10، V17) كإضافة فوق ما عندك، ثم خطط لإعادة ربط بقية الأرقام على مراحل بدل تحويل دفعة واحدة قد يُدخل أخطاء بمستند رسمي.
- **مشروع يعتمد على JWT أو تسجيل دخول عبر مزوّد خارجي (Google/Microsoft/Auth0)**: فصلا V9 وV10 يستحقان مراجعة فورية بغضّ النظر عن خطة الترحيل الكاملة، لأنهما يغطيان مخاطر لم تكن مفصّلة صراحة بنسخة 4.0.

> 💡 المستويات الثلاثة L1 (أساسي) وL2 (قياسي) وL3 (متقدم) بقيت كمفهوم كما هي — تراكمية، ونفس المنطق العام لاختيار المستوى المناسب حسب حساسية التطبيق. التغيير الحقيقي بالهيكلة والترقيم، لا بفلسفة المستويات نفسها.
