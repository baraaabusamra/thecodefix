عند اختيار لغة للواجهة الخلفية (Backend)، يبرز خياران شائعان: **PHP** و
**Python**. لنقارن.

## PHP — لغة الويب الكلاسيكية 🐘

[PHP](/learn/php) صُمّمت أصلًا للويب وتشغّل أكثر من ثلثي مواقع الإنترنت.

- ✅ مثالية للويب مباشرةً
- ✅ نظام بيئي ضخم (مع [Laravel](/learn/laravel) و WordPress)
- ✅ استضافة رخيصة ومنتشرة

## Python — العموميّة والذكاء الاصطناعي 🐍

[Python](/learn/python) لغة عامّة تتفوّق عندما تحتاج أكثر من مجرّد موقع.

- ✅ ممتازة للذكاء الاصطناعي وتحليل البيانات
- ✅ أطر قويّة مثل [Django](/learn/django)
- ✅ صياغة بسيطة وواضحة

## مثال عملي: استقبال طلب HTTP بسيط

**PHP** — تعمل مباشرةً خلف أي خادم ويب دون إعداد إضافي:

```php
<?php
$name = $_GET['name'] ?? 'زائر';
echo "مرحبًا, $name!";
```

**Python** — تحتاج إطارًا (هنا Flask) وخادم WSGI ليقوم بنفس الدور:

```python
from flask import Flask, request
app = Flask(__name__)

@app.route("/hello")
def hello():
    name = request.args.get("name", "زائر")
    return f"مرحبًا, {name}!"
```

هنا يظهر فرق فلسفي حقيقي: PHP صُمّمت من الأساس لتُعالج كل طلب HTTP كعملية
مستقلّة (يبدأ تنفيذ الملفّ من جديد مع كل طلب)، فلا حاجة لإدارة حالة الخادم
يدويًّا. Python تشغّل عملية واحدة طويلة العمر تدير كل الطلبات بنفسها عبر
الإطار — أقوى مرونةً، لكنها تتطلّب فهمًا إضافيًا (workers، threads) عند
النشر الفعلي.

## جدول المقارنة

| الجانب | PHP | Python |
|--------|-----|--------|
| التركيز | الويب أساسًا | عامّة |
| أشهر إطار | Laravel | Django |
| الذكاء الاصطناعي | محدود | الأقوى |
| الانتشار في الويب | ضخم جدًّا | متنامٍ |
| نموذج التنفيذ | عملية جديدة لكل طلب | عملية طويلة العمر (Workers) |
| سهولة النشر على استضافة مشتركة | مباشرة جدًّا | تحتاج إعداد WSGI/ASGI |

## خطأ شائع عند الاختيار

كثيرون يختارون Python بحجّة أنها "الأحدث" أو "الأذكى"، ثم يتفاجؤون أن نشرها
كموقع ويب تقليدي (استضافة، خادم WSGI) أعقد بكثير من رفع ملفّات PHP على أي
استضافة مشتركة رخيصة. إن كان مشروعك موقعًا عاديًا بلا حاجة فعلية للذكاء
الاصطناعي أو معالجة بيانات ثقيلة، لا تفترض أفضلية Python تلقائيًّا — قارن
تكلفة النشر والصيانة الفعلية لمشروعك، لا سمعة اللغة.
