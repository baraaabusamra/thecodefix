أوّل خطأ يقابل أي متعلّم [بايثون](/learn/python) تقريبًا هو
**`SyntaxError: invalid syntax`**. الخبر الجيد: هو أسهل الأخطاء حلًّا، لأن
بايثون يخبرك **بمكان المشكلة بالضبط**، وفي الإصدارات الحديثة يخبرك أيضًا
**بسببها**، إن عرفت كيف تقرأ الرسالة.

كل الرسائل في هذا المقال نسخناها من تشغيل فعلي على Python 3.13. الإصدارات من
3.10 وما بعدها تعطي رسائل مشابهة، أما 3.9 وما قبلها فتكتفي غالبًا بـ
`invalid syntax` العامة.

## كيف تقرأ رسالة الخطأ

```
  File "app.py", line 2
    if age > 18
               ^
SyntaxError: expected ':'
```

ثلاث معلومات في كل رسالة:

- **اسم الملف ورقم السطر** (`line 2`): أين توقّف بايثون.
- **السهم `^`**: النقطة التي فشل عندها فهم الجملة.
- **الوصف**: هنا `expected ':'`، أي «كنت أتوقع نقطتين في هذا المكان».

> 💡 `SyntaxError` يُكتشف **قبل تشغيل أي سطر** من برنامجك. لذلك لن تساعدك
> `print` في التشخيص: البرنامج لم يبدأ أصلًا، والمشكلة في الكتابة نفسها.

## جدول الرسائل: الرسالة ← السبب ← الحل

| الرسالة | السبب | الحل |
| --- | --- | --- |
| `expected ':'` | نسيت النقطتين بعد `if` أو `for` أو `def` أو `else` | أضف `:` في آخر السطر |
| `'(' was never closed` (أو `'['` أو `'{'`) | قوس فتحته ولم تغلقه | أغلقه في نفس السطر المشار إليه |
| `unmatched ')'` | قوس إغلاق زائد | احذفه |
| `unterminated string literal` | اقتباس لم يُغلق | أغلق النص بنفس علامة الاقتباس |
| `Maybe you meant '==' or ':=' instead of '='?` | `=` داخل شرط | `==` للمقارنة |
| `Perhaps you forgot a comma?` | عناصر بلا فواصل: `[1 2 3]` | `[1, 2, 3]` |
| `Missing parentheses in call to 'print'` | صيغة بايثون 2: `print "hi"` | `print("hi")` |
| `invalid character '“' (U+201C)` | علامة اقتباس ذكية منسوخة | استبدلها بـ `"` |
| `invalid character '،' (U+060C)` | فاصلة عربية | فاصلة إنجليزية `,` |
| `invalid non-printable character U+200F` | علامة اتجاه مخفية | احذف السطر وأعد كتابته |
| `invalid syntax` على `python app.py` | أمر طرفية داخل بايثون | اخرج من `>>>` أولًا |
| `f-string: expecting '}'` | قوس `{` غير مغلق داخل f-string | `f"{name}"` |
| `invalid syntax` على `class = "A"` | كلمة محجوزة كاسم متغيّر | اختر اسمًا آخر |

## الحلول خطوة بخطوة

### 1) نقطتان منسيّتان: السبب الأول بلا منازع

كل سطر يفتح كتلة جديدة في بايثون **يجب** أن ينتهي بنقطتين:

```python
if score >= 60:      # شرط
for i in range(10):  # حلقة
def greet(name):     # دالة
while True:          # حلقة
else:                # وأيضًا else وelif وtry وexcept وclass
```

ومنها `else if` المنقولة من لغات أخرى: بايثون يقرأ `else` ثم يتوقع `:` فورًا،
فيعطي `expected ':'`. الصحيح في بايثون كلمة واحدة: `elif`.
([درس الشروط](/learn/python/03-conditions))

### 2) `'(' was never closed`: القوس المفتوح

```
  File "app.py", line 1
    total = sum([1, 2, 3
                ^
SyntaxError: '[' was never closed
```

لاحظ أين يقف السهم: عند **القوس المفتوح نفسه** في السطر 1، لا عند السطر التالي.
هذا تحسّن من بايثون 3.10. في الإصدارات الأقدم كان الخطأ يظهر في السطر **الذي
بعده** بصيغة `invalid syntax`، فيحتار الجميع لأن ذلك السطر سليم. فإن كنت على
إصدار قديم، أو رأيت سهمًا على سطر يبدو سليمًا، فافحص **السطر الذي قبله**.

نصيحة عملية: المحررات الحديثة تلوّن الأقواس المتطابقة بنفس اللون. إن رأيت قوسًا
بلا شريك، فهذا هو.

### 3) الحروف العربية المنسوخة: فخّ يخص المتعلم العربي

نسخت كودًا من ملف Word، أو رسالة واتساب، أو موقع ينسّق النصوص، فظهر:

```
  File "app.py", line 1
    print(“مرحبا”)
          ^
SyntaxError: invalid character '“' (U+201C)
```

العلامتان `“ ”` **اقتباس ذكي** منحنٍ، وبايثون يقبل فقط `"` و`'` المستقيمتين.
ونفس الفخ مع:

- **الفاصلة العربية `،`** (U+060C) بدل `,`: `[1، 2]` ← `invalid character '،'`.
- **الأرقام العربية الهندية** `٣` بدل `3`: `invalid character '٣' (U+0663)`.
- **علامات الاتجاه المخفية** (U+200F) التي يضيفها التبديل بين العربية
  والإنجليزية: `invalid non-printable character U+200F`. لا تراها بعينك أصلًا؛
  احذف السطر كاملًا وأعد كتابته.

القاعدة: **النصوص العربية داخل علامات الاقتباس مسموحة تمامًا** (`print("مرحبا")`
سليمة)، أما الكود نفسه (الأقواس والفواصل والأرقام والاقتباسات) فيُكتب بلوحة
المفاتيح الإنجليزية. والرقم في الرسالة (`U+201C`) يخبرك بالحرف بالضبط إن لم
تجده بعينك.

### 4) أوامر الطرفية داخل بايثون

```
>>> python app.py
SyntaxError: invalid syntax
>>> pip install requests
SyntaxError: invalid syntax
```

العلامة `>>>` في أول السطر تعني أنك **داخل بايثون التفاعلي**، وكل ما تكتبه يُقرأ
ككود بايثون. أما `python app.py` و`pip install` فأوامر **للطرفية** نفسها. اخرج
أولًا بـ `exit()` أو Ctrl+D (أو Ctrl+Z ثم Enter على Windows)، ثم نفّذ الأمر.
(وإن فشل `pip` بعدها، فدليله هنا: [أخطاء pip install](/blog/python-pip-install-errors).)

### 5) IndentationError: قصة المسافات

بايثون يعتمد على المسافات البادئة لمعرفة أين تبدأ الكتلة وأين تنتهي، فلأخطائها
رسائل خاصة:

| الرسالة | المعنى |
| --- | --- |
| `expected an indented block after 'if' statement on line 1` | السطر بعد `:` غير مُزاح للداخل |
| `unexpected indent` | سطر مُزاح بلا سبب (لا `:` قبله) |
| `unindent does not match any outer indentation level` | الرجوع لمستوى إزاحة لم يوجد سابقًا (6 مسافات بين 4 و8) |
| `TabError: inconsistent use of tabs and spaces in indentation` | خلط Tab مع Space في نفس الكتلة |

```python
if logged_in:
    print("أهلًا!")   # 4 مسافات
```

قواعد الإزاحة:

- بعد أي سطر ينتهي بـ `:` يجب أن يكون السطر التالي **مُزاحًا للداخل**.
- استخدم **4 مسافات** دائمًا، ولا تخلط Tab مع Space أبدًا.
- في VS Code فعّل "Render Whitespace" لترى المسافات، واجعل المحرر يحوّل Tab
  إلى مسافات تلقائيًّا.

### 6) `=` إسناد و`==` مقارنة

```python
if x = 5:    # SyntaxError: ... Maybe you meant '==' or ':=' instead of '='?
if x == 5:   # مقارنة
```

لاحظ أن بايثون نفسه يقترح الحل في الرسالة. اقرأ الرسالة كاملة قبل البحث.

### 7) اقتباس لم يُغلق

```python
name = "أحمد      # SyntaxError: unterminated string literal (detected at line 1)
name = "أحمد"     # سليم
```

وانتبه: النص الذي يبدأ بـ `"` يجب أن ينتهي بـ `"`، لا بـ `'`. ونص متعدد الأسطر
بـ `"""` بلا إغلاق يعطي `unterminated triple-quoted string literal`.

## إن لم تجد السبب

1. اقرأ **الوصف** بعد `SyntaxError:` كاملًا. في الإصدارات الحديثة كثيرًا ما يقترح
   الحل حرفيًّا.
2. افحص السطر المشار إليه **والسطر الذي قبله**.
3. علّق نصف الملف (`#`) وشغّل: إن اختفى الخطأ فهو في النصف المعلَّق. كرّر حتى
   تصل للسطر.
4. اعرف إصدارك بـ `python --version`. على 3.9 أو أقدم، الرسائل عامة، والترقية
   تعطيك وصفًا أدق.

## قائمة تحقّق سريعة

- السطر الذي يفتح كتلة ينتهي بـ `:`؟ (وتذكّر `elif` لا `else if`)
- كل `(` و`[` و`{` و`"` له إغلاق؟
- الكود منسوخ من Word أو واتساب؟ ← اقتباسات ذكية، أو فاصلة عربية، أو حروف مخفية.
- السطر يبدأ بـ `>>>`؟ ← اخرج قبل أوامر الطرفية.
- `==` للمقارنة داخل الشروط؟
- الإزاحة 4 مسافات متسقة في كل الملف؟
- كلمة محجوزة (`class` أو `def` أو `if`…) اسمًا لمتغيّر؟

## الخلاصة

`SyntaxError` ليس عدوًّا، بل مصحح إملائي يوقفك قبل تشغيل كود مكسور. اقرأ رقم
السطر، وانظر للسهم `^`، واقرأ الوصف: غالبًا يخبرك بالسبب حرفيًّا. وإن كان المتعلم
عربيًّا، فاشكّ أولًا في الحروف المنسوخة.

أساسيات كتابة الكود نفسها في [درس الصيغة والتعليقات](/learn/python/07-syntax-comments)،
والأخطاء التي تظهر **أثناء** التشغيل (لا قبله) في [درس الاستثناءات](/learn/python/20-exceptions)
و[أخطاء بايثون الشائعة](/blog/python-common-errors) و
[IndexError وKeyError](/blog/python-indexerror-keyerror).
