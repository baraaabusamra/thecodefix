بدل إنشاء موارد AWS يدويًا بالنقر، يتيح لك CloudFormation وصفها **كرمز**. يبني هذا الدرس على مفهوم [البنية التحتية كرمز في DevOps](/learn/devops/12-iac).

## ما هو CloudFormation؟

CloudFormation هو خدمة **البنية التحتية كرمز (IaC) الأصلية في AWS**. تصف الموارد المطلوبة في **قالب (Template)** تصريحي بصيغة YAML أو JSON، فينشئها AWS ويديرها مطابقةً لوصفك.

هذا يجسّد مبادئ IaC التي رأيناها: التصريحية (تصف *ماذا تريد*)، قابلية إعادة الإنتاج، والتتبّع عبر التحكّم بالإصدارات.

## قالب بسيط

```yaml
AWSTemplateFormatVersion: "2010-09-09"
Resources:
  MyBucket:
    Type: AWS::S3::Bucket
    Properties:
      BucketName: my-example-bucket
```

هذا القالب يصف حاوية S3 واحدة. عند تطبيقه، ينشئها AWS نيابةً عنك.

## المفهوم المحوري: الـ Stack

عند تطبيق قالب، ينشئ CloudFormation **Stack** — وهو مجموعة الموارد المُدارة كوحدة واحدة. مزايا ذلك:

- **إدارة موحّدة**: تحدّث الموارد أو تحذفها كمجموعة.
- **تنظيف نظيف**: حذف الـ Stack يزيل كل موارده، فلا تترك موارد يتيمة تكلّفك.
- **التغييرات الآمنة**: يمكن معاينة أثر التعديل قبل تطبيقه.

## CloudFormation مقابل Terraform

كلاهما أداة IaC تصريحية، لكن:

- **CloudFormation**: أصلي في AWS، متكامل بعمق معه، لكنّه **خاصّ بـ AWS فقط**.
- **Terraform**: **متعدّد المزوّدين** (AWS و Azure و Google Cloud وغيرها) بلغة ونمط موحّدين.

القاعدة: إن كنت داخل AWS حصريًا، فقد يناسبك CloudFormation؛ وإن أردت أداةً واحدة عبر عدّة سحابات، فـ Terraform خيار قويّ.
