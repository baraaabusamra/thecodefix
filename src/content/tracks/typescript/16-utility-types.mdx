## ما الأنواع المساعدة؟

أنواع جاهزة من TypeScript تحوّل نوعًا موجودًا إلى نوع جديد دون إعادة
كتابته. لنفترض هذا النوع:

```ts
interface User {
  id: number;
  name: string;
  email: string;
}
```

## Partial — كل الخصائص اختيارية

```ts
function updateUser(id: number, changes: Partial<User>) {
  // changes قد يحتوي بعض حقول User فقط
}
updateUser(1, { name: "اسم جديد" });   // صحيح
```

## Required — كل الخصائص مطلوبة

عكس Partial — يجعل الاختياري إلزاميًّا.

## Pick — اختيار حقول محدّدة

```ts
type UserPreview = Pick<User, "id" | "name">;
// { id: number; name: string }
```

## Omit — استبعاد حقول

```ts
type UserWithoutEmail = Omit<User, "email">;
// { id: number; name: string }
```

## Readonly — منع التعديل

```ts
const u: Readonly<User> = { id: 1, name: "علي", email: "a@b.com" };
u.name = "آخر";   // خطأ! readonly
```

## Record — كائن بمفاتيح وقيم محدّدة النوع

```ts
type Roles = Record<string, boolean>;
const perms: Roles = { admin: true, editor: false };

// أو بمفاتيح محدّدة
type Page = "home" | "about";
const titles: Record<Page, string> = {
  home: "الرئيسية",
  about: "من نحن",
};
```

## المعامل keyof

ينتج اتحاد مفاتيح نوع ما:

```ts
type UserKeys = keyof User;   // "id" | "name" | "email"

function getField(user: User, key: keyof User) {
  return user[key];
}
```

هذه الدالة تمنع المفاتيح غير الموجودة (`getField(u, "age")` خطأ ترجمة)، لكن نوع ما تُرجعه هو `number | string` دائمًا، لأن TypeScript لا يعرف أي مفتاح بالضبط مُرِّر. مع Generic يصبح النوع دقيقًا لكل مفتاح:

```ts
function getField<K extends keyof User>(user: User, key: K): User[K] {
  return user[key];
}

const u: User = { id: 1, name: "علي", email: "a@b.com" };
const id = getField(u, "id");       // number
const name = getField(u, "name");   // string
```

`User[K]` اسمه **نوع الوصول بالفهرس** (indexed access type): "نوع الخاصية K في User".

### `keyof typeof` لكائن موجود

`keyof` يعمل على **الأنواع** فقط، لا على القيم. لتأخذ مفاتيح كائن حقيقي، حوّله لنوع أولًا بـ `typeof`:

```ts
const colors = { primary: "#7c5cff", danger: "#e11d48" };

type ColorName = keyof typeof colors;   // "primary" | "danger"
// type Bad = keyof colors;             // خطأ: colors قيمة لا نوع
```

> ⚠️ مع نوع فيه index signature نصّي مثل `{ [key: string]: number }`، ينتج `keyof` النوع `string | number`، لأن JavaScript تحوّل المفاتيح الرقمية لنصوص.

## جدول سريع

| النوع | الوظيفة |
|------|---------|
| `Partial<T>` | كل الحقول اختيارية |
| `Required<T>` | كل الحقول مطلوبة |
| `Pick<T, K>` | حقول محدّدة فقط |
| `Omit<T, K>` | كل الحقول عدا المحدّدة |
| `Readonly<T>` | منع التعديل |
| `Record<K, V>` | كائن بمفاتيح/قيم منمَّطة |

## أخطاء شائعة

- إعادة كتابة نوع معدّل يدويًّا بدل استخدام `Partial`/`Omit`.
- الخلط بين `Pick` (يبقي) و`Omit` (يستبعد).
- الخلط بين `keyof` (يعمل على الأنواع وقت الترجمة) و`typeof` في JavaScript (يفحص نوع قيمة وقت التشغيل).
