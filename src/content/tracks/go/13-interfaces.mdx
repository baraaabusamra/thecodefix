## ما هي الواجهة؟

الواجهة تصف **سلوكًا**: قائمة methods. أي نوع يملك هذه الـ methods **يحقّق** الواجهة تلقائيًا، بلا كلمة `implements`:

```go
type Shape interface {
    Area() float64
}

type Circle struct{ R float64 }
func (c Circle) Area() float64 { return math.Pi * c.R * c.R }

type Square struct{ Side float64 }
func (s Square) Area() float64 { return s.Side * s.Side }

func printArea(s Shape) {
    fmt.Printf("%.2f\n", s.Area())
}

func main() {
    printArea(Circle{R: 1})      // 3.14
    printArea(Square{Side: 4})   // 16.00
}
```

`printArea` لا تعرف ولا تهتمّ ما النوع الحقيقي؛ تهتمّ فقط أنه يملك `Area()`.

## لماذا التنفيذ الضمني مهمّ؟

في Java يجب أن يعلن الكلاس مسبقًا `implements Shape`. في Go **المستخدم** يعرّف الواجهة التي يحتاجها، وأي نوع موجود (حتى من مكتبة لم تسمع بواجهتك) يحقّقها إذا كانت عنده الـ methods.

الأثر العملي: واجهات Go **صغيرة**، غالبًا method واحدة. أشهرها في المكتبة القياسية:

```go
type Reader interface { Read(p []byte) (n int, err error) }   // io.Reader
type Writer interface { Write(p []byte) (n int, err error) }  // io.Writer
type Stringer interface { String() string }                   // fmt.Stringer
```

لأن الملف والاتصال الشبكي و`bytes.Buffer` و`strings.Builder` كلها تملك `Write`، فكل دالة تقبل `io.Writer` تعمل معها جميعًا:

```go
func report(w io.Writer, name string) {
    fmt.Fprintf(w, "تقرير: %s\n", name)
}

func main() {
    report(os.Stdout, "الشاشة")       // إلى الشاشة
    var sb strings.Builder
    report(&sb, "الذاكرة")            // إلى نص في الذاكرة
    fmt.Print(sb.String())
}
```

هذا يجعل الاختبار سهلًا: في الإنتاج تمرّر ملفًا، وفي الاختبار تمرّر `strings.Builder` وتفحص ما كُتب.

## المُستقبِل بالمؤشّر والواجهات

إذا عرّفت method بمُستقبِل **مؤشّر**، فالمؤشّر وحده يحقّق الواجهة:

```go
type Counter struct{ n int }
func (c *Counter) String() string { return fmt.Sprint(c.n) }

func main() {
    c := Counter{n: 3}
    var s fmt.Stringer = &c   // ✅
    // var s2 fmt.Stringer = c   // ❌ Counter does not implement fmt.Stringer
    fmt.Println(s)
}
```

هذا سبب رسالة الخطأ المحيّرة "does not implement (method has pointer receiver)": مرّر `&c` بدل `c`.

## any: الواجهة الفارغة

`interface{}`، أو اسمها المختصر `any` منذ Go 1.18، واجهة بلا methods، فيحقّقها **كل** نوع:

```go
func describe(v any) {
    fmt.Printf("%T: %v\n", v, v)
}

func main() {
    describe(42)       // int: 42
    describe("نص")     // string: نص
}
```

مفيدة حين لا تعرف النوع فعلًا (مثل `fmt.Println` أو JSON ديناميكي). لكنها تُفقدك فحص المترجم، فلا تستخدمها بدل التصميم؛ للدوال التي تعمل مع عدّة أنواع بنفس المنطق هناك [الأنواع العامة (Generics)](/learn/go/25-generics).

## تأكيد النوع و type switch

لاسترجاع النوع الحقيقي من واجهة:

```go
var v any = "مرحبًا"

s, ok := v.(string)    // s = "مرحبًا", ok = true
n, ok2 := v.(int)      // n = 0, ok2 = false: بلا panic
fmt.Println(s, ok, n, ok2)

switch x := v.(type) {
case int:
    fmt.Println("عدد", x+1)
case string:
    fmt.Println("نص بطول", len(x))
default:
    fmt.Println("نوع آخر")
}
```

استخدم دائمًا الصيغة بـ `ok`: الصيغة القصيرة `v.(int)` بلا `ok` تسبّب `panic` إذا كان النوع مختلفًا.

## فخّ nil داخل الواجهة

قيمة الواجهة تحمل شيئين: **النوع** و**القيمة**. وهي `nil` فقط إذا كان الاثنان فارغين:

```go
type MyErr struct{}
func (*MyErr) Error() string { return "خطأ" }

func mayFail(fail bool) error {
    var e *MyErr = nil
    if fail {
        e = &MyErr{}
    }
    return e   // ❌ واجهة نوعها *MyErr وقيمتها nil: ليست nil!
}

func main() {
    err := mayFail(false)
    fmt.Println(err == nil)   // false!
}
```

القاعدة: في الدوال التي تُرجع `error`، اكتب `return nil` صراحة في مسار النجاح، ولا تُرجع متغيّر مؤشّر قد يكون `nil`.

## أخطاء شائعة

- **واجهات كبيرة "تحسّبًا":** عرّف الواجهة الصغيرة حيث **تُستخدم**، بالـ methods التي تحتاجها فعلًا.
- **`v.(T)` بلا `ok`:** `panic` إذا كان النوع مختلفًا.
- **تمرير قيمة والـ methods بمُستقبِل مؤشّر:** مرّر `&v`.
- **إرجاع مؤشّر nil كـ `error`:** `err != nil` تصبح صحيحة. أرجع `nil` صراحة.
- **`any` في كل مكان:** تخسر فحص الأنواع؛ فكّر في واجهة محدّدة أو generics.
