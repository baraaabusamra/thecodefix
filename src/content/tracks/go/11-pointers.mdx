## ما هو المؤشّر؟

كل متغيّر يعيش في مكان في الذاكرة له **عنوان**. المؤشّر متغيّر قيمته هذا العنوان:

```go
x := 10
p := &x           // p يحمل عنوان x، ونوعه *int
fmt.Println(*p)   // 10: القيمة في ذلك العنوان
*p = 20           // تعديل x عبر المؤشّر
fmt.Println(x)    // 20
```

- `&x` تعني "**عنوان** x".
- `*p` تعني "**القيمة** التي يشير إليها p".
- `*int` في النوع تعني "مؤشّر إلى `int`".

## لماذا المؤشّرات؟

Go تمرّر **كل شيء بالقيمة**: الدالة تستلم **نسخة** من المعامل. لتعديل متغيّر المستدعي، مرّر عنوانه:

```go
func noEffect(n int) { n = n * 2 }   // تعدّل النسخة فقط
func double(n *int)  { *n = *n * 2 } // تعدّل الأصل

func main() {
    x := 5
    noEffect(x)
    fmt.Println(x)   // 5
    double(&x)
    fmt.Println(x)   // 10
}
```

السبب الثاني: **تجنّب نسخ بيانات كبيرة**. تمرير struct فيه عشرات الحقول ينسخها كلها، أما المؤشّر فـ 8 بايتات فقط.

## المؤشّرات مع البِنى

```go
type User struct{ Name string }

func rename(u *User) {
    u.Name = "جديد"    // اختصار لـ (*u).Name
}

func main() {
    user := User{Name: "قديم"}
    rename(&user)
    fmt.Println(user.Name)   // جديد
}
```

Go تفكّ المؤشّر تلقائيًا عند الوصول للحقول، فلا تحتاج `(*u).Name`. ونمط شائع: إنشاء struct وإرجاع مؤشّر إليه مباشرة بـ `&User{...}`.

## إرجاع عنوان متغيّر محلّي: آمن في Go

```go
func newCounter() *int {
    c := 0
    return &c   // ✅ في C هذا خطأ خطير، في Go آمن تمامًا
}

func main() {
    p := newCounter()
    *p++
    fmt.Println(*p)   // 1
}
```

المترجم يلاحظ أن `c` يُستخدم بعد انتهاء الدالة، فيضعه في الكومة (heap) بدل المكدّس (يسمّى escape analysis)، وجامع النفايات يحرّره حين لا يعود أحد يشير إليه. لا `malloc` ولا `free`.

## new

```go
p := new(int)    // يحجز int بقيمته الصفرية ويُرجع مؤشّرًا إليه
*p = 42
fmt.Println(*p)  // 42
```

في الواقع `new` نادرة؛ `&T{...}` للبِنى أوضح وأكثر استخدامًا.

## nil: المؤشّر الذي لا يشير لشيء

```go
var p *int          // القيمة الصفرية: nil
fmt.Println(p == nil)   // true
// fmt.Println(*p)  // ❌ panic: invalid memory address or nil pointer dereference
```

قراءة مؤشّر `nil` توقف البرنامج. افحص قبل الاستخدام حين قد يكون المؤشّر فارغًا (نتيجة بحث لم تجد شيئًا مثلًا):

```go
func findUser(id int) *User {
    if id == 1 {
        return &User{Name: "براء"}
    }
    return nil   // لم يوجد
}

func main() {
    if u := findUser(2); u != nil {
        fmt.Println(u.Name)
    } else {
        fmt.Println("لا يوجد مستخدم")
    }
}
```

## متى لا تحتاج مؤشّرًا؟

- **الشرائح والخرائط والقنوات** تحمل مرجعًا داخليًا لبياناتها أصلًا؛ الدالة تعدّل محتواها بلا مؤشّر (إلا إذا أردت تغيير طول الشريحة نفسها عند المستدعي بـ `append`).
- **الأنواع الصغيرة** (`int` و`bool` وstruct من حقلين) للقراءة فقط: النسخ أرخص وأوضح.
- **لا يوجد حساب مؤشّرات** في Go: لا `p + 1` كما في C. هذا يلغي فئة كاملة من أخطاء الذاكرة.

## أخطاء شائعة

- **قراءة مؤشّر nil:** `panic`. افحص `p != nil` حين قد يكون فارغًا.
- **توقّع أن الدالة تعدّل الأصل بلا مؤشّر:** Go تمرّر نسخًا دائمًا.
- **مؤشّر لمتغيّر الحلقة قبل Go 1.22:** في الإصدارات القديمة كانت كل الدورات تشترك في متغيّر واحد، فكل المؤشّرات تشير لآخر قيمة. منذ Go 1.22 كل دورة لها متغيّرها الخاص.
- **استخدام المؤشّرات في كل مكان "للسرعة":** النسخ الصغير سريع، والمؤشّرات تضيف احتمال `nil` وتعديلًا غير متوقّع من مكان آخر.
