## المشكلة: تمرير نفس التبعية في كل دالة

تخيّل دوالًا كثيرة تحتاج جميعها الوصول لنفس الشيء — اتصال قاعدة بيانات، جلسة مستخدم حالية، إعدادات تسجيل. الحل التقليدي تمرير هذه التبعية كمعامل صريح لكل دالة:

```kotlin
fun loadProfile(db: AppDatabase, userId: String): Profile {
    return db.profiles.find(userId)
}

fun saveProfile(db: AppDatabase, profile: Profile) {
    db.profiles.save(profile)
}
```

كل دالة تكرّر `db: AppDatabase`، وكل نداء يكرّر تمريرها. مع نمو المشروع يصبح هذا تكرارًا مزعجًا وعرضة للخطأ (تمرير الكائن الخطأ بالغلط).

## الحل: `context(...)` 🌟

**معاملات السياق** ميزة استقرّت رسميًا في **Kotlin 2.4.0** (يوليو 2026، لا حاجة بعدها لأي علم ترجمة تجريبي) تسمح بتعريف تبعية "ضمنية" مرة واحدة، تتوفّر تلقائيًا لأي دالة تُعلن حاجتها لها:

```kotlin
context(db: AppDatabase)
fun loadProfile(userId: String): Profile {
    return db.profiles.find(userId)   // db متاحة مباشرة، بلا تمريرها كمعامل عادي
}

context(db: AppDatabase)
fun saveProfile(profile: Profile) {
    db.profiles.save(profile)
}
```

عند الاستدعاء، يجب توفّر `AppDatabase` في السياق (عادة عبر دالة أخرى تحمل نفس `context`، أو كتلة `context(...)`):

```kotlin
context(db: AppDatabase)
fun syncEverything(userId: String) {
    val profile = loadProfile(userId)   // db تنتقل ضمنيًا، بلا تكرار كتابتها
    saveProfile(profile)
}
```

> 💡 لاحظ الاسم `db:` قبل النوع في `context(db: AppDatabase)` — هذا ما يميّز معاملات السياق عن ميزة "context receivers" التجريبية القديمة: هنا لكل سياق **اسم صريح** تستخدمه للإشارة إليه (`db.profiles`)، بعكس `this` الضمنية القديمة التي كانت تسبّب لبسًا عند وجود أكثر من سياق واحد.

## أكثر من سياق واحد

يمكن الجمع بين عدّة سياقات بفاصلة:

```kotlin
context(session: UserSession, db: AppDatabase)
fun currentUserProfile(): Profile {
    return db.profiles.find(session.userId)
}
```

## متى تستخدمها؟

- **حقن تبعيات خفيف** بدون إطار عمل خارجي (Dagger/Koin) لحالات بسيطة.
- **دوال مساعدة (utility)** تحتاج دائمًا نفس الموارد (اتصال شبكة، تسجيل، إعدادات) عبر طبقة كاملة من الكود.
- **مكتبات DSL** حيث تريد إتاحة عمليات معيّنة فقط داخل نطاق محدّد.

## أخطاء شائعة

- **❌ استخدامها لكل تبعية بلا تمييز** → إن كانت الدالة تُستدعى من مكان واحد فقط، معامل عادي أوضح؛ معاملات السياق تفيد فعليًا عند تكرار نفس التبعية عبر **عدّة** دوال.
- **❌ نسيان أن الاستدعاء يتطلّب توفّر نفس السياق** → لا يمكن استدعاء دالة `context(db: AppDatabase)` من مكان لا يملك `AppDatabase` في سياقه الحالي؛ ستحصل على خطأ ترجمة، لا خطأ وقت التشغيل.
- **❌ الخلط مع context receivers القديمة (`context(Type)` بلا اسم)** → تلك كانت تجريبية وتُستبدَل تدريجيًا بمعاملات السياق المستقرّة ذات الاسم الصريح.

## خلاصة

معاملات السياق (`context(name: Type)`) ميزة Kotlin 2.4 المستقرّة لتمرير تبعيات متكرّرة ضمنيًا بين الدوال، باسم صريح يوضّح مصدرها بعكس `this` الضمنية بالنسخة التجريبية القديمة. مفيدة لتقليل التكرار في طبقات كاملة من الكود تعتمد على نفس المورد، لا كبديل عام لكل معامل دالة.
