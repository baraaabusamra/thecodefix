## الواجهة (Interface)

عقد من الطرق التي يجب تنفيذها (يمكن أن تحوي تنفيذًا افتراضيًّا):

```kotlin
interface Clickable {
    fun click()
    fun showOff() = println("قابل للنقر")   // افتراضي
}

class Button : Clickable {
    override fun click() = println("نُقر الزرّ")
}
```

الواجهة تقدر تحتوي **دوالًا بتنفيذ افتراضي** (مثل `showOff` أعلاه)، فالأصناف التي تطبّقها لا تحتاج كتابتها إلا إذا أرادت سلوكًا مختلفًا. وتقدر تحتوي خصائص، لكن بدون قيمة مخزّنة: الصنف المنفّذ هو من يخزّنها.

```kotlin
interface Named {
    val name: String              // كل صنف منفّذ يجب أن يوفّرها
    fun hello() = "أهلًا $name"   // يستخدمها في تنفيذ افتراضي
}

class User(override val name: String) : Named

println(User("سارة").hello())   // أهلًا سارة
```

## تنفيذ عدّة واجهات

```kotlin
interface Focusable { fun focus() }

class Input : Clickable, Focusable {
    override fun click() {}
    override fun focus() {}
}
```

### تعارض نفس الدالة من واجهتين

إذا كانت واجهتان تحتويان دالة بنفس الاسم وتنفيذ افتراضي، يجب على الصنف أن يحسم أي واحدة يقصد:

```kotlin
interface A { fun hello() = "من A" }
interface B { fun hello() = "من B" }

class C : A, B {
    override fun hello() = super<A>.hello() + " و " + super<B>.hello()
}

println(C().hello())   // من A و من B
```

بدون `override` هنا، المترجم يرفض الصنف لأنه لا يعرف أي `hello` تقصد.

## الصنف المجرّد (Abstract)

```kotlin
abstract class Shape {
    abstract fun area(): Double      // بلا تنفيذ
    fun describe() = "مساحة: ${area()}"
}

class Circle(val r: Double) : Shape() {
    override fun area() = 3.14 * r * r
}
```

## الفرق

- **interface:** سلوك مشترك، عدّة واجهات، بلا حالة (state) محفوظة.
- **abstract class:** قالب جزئي بحالة وبانٍ، وراثة واحدة فقط.

### متى أختار أيهما؟

| السؤال | الجواب |
| --- | --- |
| هل تحتاج تخزين قيم مشتركة (حقول) أو بانيًا بمعاملات؟ | صنف مجرّد |
| هل يحتاج الصنف أن يحمل أكثر من "قدرة" (قابل للنقر **و** للتركيز)؟ | واجهات |
| هل الأصناف المنفّذة لا يجمعها أصل واحد، فقط سلوك مشترك؟ | واجهة |

القاعدة العملية: ابدأ بواجهة، وانتقل لصنف مجرّد فقط حين تحتاج فعلًا حالة مشتركة أو بانيًا.

لاحظ أيضًا: الصنف المجرّد و`abstract fun` مفتوحان للوراثة والتجاوز تلقائيًا، فلا تكتب لهما `open`.

## أخطاء شائعة

- **محاولة إنشاء كائن من واجهة أو صنف مجرّد:** `Shape()` خطأ ترجمة؛ أنشئ من صنف ملموس مثل `Circle(2.0)`.
- **خاصية بقيمة داخل واجهة:** `val x = 5` في واجهة غير مسموح؛ الواجهة لا تخزّن حالة.
- **نسيان `()` بعد اسم الصنف المجرّد عند الوراثة:** `: Shape()` لأنه صنف له باني، بينما الواجهة تُكتب بلا أقواس `: Clickable`.
