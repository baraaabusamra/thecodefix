## المشكلة التي يحلّها

في Java، أي متغيّر من نوع كائن قد يكون `null`، والمترجم لا يحذّرك. تستدعي `name.length()` على `null` فيتوقّف البرنامج وقت التشغيل بـ `NullPointerException`. هذا من أكثر الأخطاء شيوعًا في البرامج، ولذلك سمّاه مخترع `null` نفسه "خطأ المليار دولار".

Kotlin تنقل هذا الفحص لوقت **الترجمة**: النوع نفسه يقول هل القيمة قد تكون `null` أم لا، والمترجم يرفض أي كود قد ينهار.

## الأنواع القابلة لـ null

افتراضيًّا لا يقبل المتغيّر `null`؛ أضِف `?` للسماح:

```kotlin
var name: String = "براء"
// name = null            // خطأ ترجمة
var nick: String? = null  // مسموح
```

`String` و`String?` نوعان مختلفان. على `String?` لا تقدر تستدعي `nick.length` مباشرة:

```kotlin
// println(nick.length)   // خطأ ترجمة: nick قد يكون null
```

فكيف تصل للقيمة؟ بإحدى الطرق التالية.

## الفحص العادي بـ if

بعد أن تتحقّق أن القيمة ليست `null`، يعاملها المترجم كأنها من النوع العادي داخل ذلك الفرع (smart cast):

```kotlin
if (nick != null) {
    println(nick.length)   // ✅ هنا nick من نوع String
}
```

## الاستدعاء الآمن ?.

```kotlin
val length = nick?.length   // null إن كان nick فارغًا (لا تعطّل)
```

النتيجة نفسها من نوع `Int?`. وتقدر تسلسلها: إذا كانت أي حلقة `null` توقّفت السلسلة وأعطت `null`:

```kotlin
val city: String? = user?.address?.city
```

## عامل إلفيس ?:

قيمة بديلة عند null:

```kotlin
val len = nick?.length ?: 0   // 0 إن كان null
```

وأقوى استخدام له: الخروج المبكر من الدالة إذا غابت قيمة ضرورية.

```kotlin
fun greet(name: String?) {
    val n = name ?: return        // لا اسم؟ اخرج من الدالة
    println("أهلًا $n")           // n هنا من نوع String
}
```

## let للقيم غير الفارغة

```kotlin
nick?.let {
    println("الطول: ${it.length}")   // ينفّذ فقط إن لم يكن null
}
```

## التأكيد !! (بحذر)

```kotlin
val len = nick!!.length   // يرمي استثناء إن كان null — تجنّبه قدر الإمكان
```

`!!` تعني "أنا متأكد أنها ليست null، وإن كنت مخطئًا فليتوقّف البرنامج". هي عمليًا رجوع لسلوك Java. كل `!!` في كودك مكان محتمل لانهيار، فاستخدمها فقط حين يكون `null` مستحيلًا فعلًا وفشل البرنامج أفضل من الاستمرار بقيمة خاطئة.

## lateinit: "سأعطيها قيمة لاحقًا"

أحيانًا لا تستطيع إعطاء قيمة لحظة إنشاء الكائن (مثلًا في أندرويد تُجهَّز الواجهة لاحقًا في دالة منفصلة)، لكنك لا تريد جعل النوع `?` وفحصه في كل مكان:

```kotlin
class Screen {
    lateinit var title: String

    fun setup() {
        title = "الرئيسية"
    }
}
```

إذا قرأت `title` قبل استدعاء `setup()` يرمي البرنامج `UninitializedPropertyAccessException`. `lateinit` تعمل مع `var` فقط، ومع الأنواع غير البدائية (لا تعمل مع `Int` أو `Boolean`).

## القيم القادمة من Java

دوال Java لا تقول للمترجم هل تُرجع `null` أم لا، فيعاملها Kotlin كنوع "غير معروف" (platform type) ولا يحذّرك. عند استدعاء مكتبة Java، صرّح بالنوع بنفسك:

```kotlin
val value: String? = javaObject.getValue()   // تعامل معها كأنها قد تكون null
```

## أخطاء شائعة

- **`!!` في كل مكان لإسكات المترجم:** تُرجع مشكلة `NullPointerException` نفسها التي جاءت Kotlin لحلّها.
- **جعل كل شيء `?` احتياطًا:** يملأ الكود بفحوص لا داعي لها. اجعل النوع `?` فقط إذا كان غياب القيمة حالة حقيقية.
- **الثقة بقيم Java:** المترجم لا يفحصها، فقد تنهار رغم أن كود Kotlin يبدو آمنًا.
