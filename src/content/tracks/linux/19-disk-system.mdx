## "No space left on device"

أشهر سبب لتوقّف خادم فجأة: امتلاء القرص. قاعدة البيانات لا تكتب، والسجلّات تتوقّف، والتطبيق ينهار. الأدوات في هذا الدرس تجيب بالترتيب: **هل** امتلأ؟ ثم **أين** المساحة؟ ثم **ماذا** أحذف؟

## df: المساحة لكل قسم

```bash
df -h
# Filesystem      Size  Used Avail Use% Mounted on
# /dev/sda1        40G   38G  2.0G  95% /
# /dev/sdb1       100G   12G   88G  12% /data
```

`-h` أحجام مقروءة (G وM). انظر لعمود `Use%` و`Mounted on`: هنا القرص الرئيسي `/` شبه ممتلئ، بينما `/data` فارغ تقريبًا.

```bash
df -i      # inodes: عدد الملفات لا حجمها
```

إذا ظهر "No space left" و`df -h` يقول إن هناك مساحة، فافحص `df -i`: ملايين الملفات الصغيرة (جلسات أو ملفات مؤقتة) قد تستهلك كل الـ inodes، وكل ملف يحتاج واحدًا مهما صغر.

## du: من يستهلك المساحة؟

```bash
du -sh /var/log              # الحجم الكلّي لمجلّد
du -sh /var/* | sort -h      # حجم كل عنصر في /var مرتّبًا
du -h --max-depth=1 / 2>/dev/null | sort -h | tail -5   # أكبر 5 في الجذر
```

اتّبع الأكبر نزولًا مستوى مستوى: `/` ثم `/var` ثم `/var/log`، حتى تجد الملف أو المجلّد المسؤول. والمتّهمون المعتادون: السجلّات (`/var/log`)، وصور Docker القديمة (`docker system df`)، وملفات `node_modules` المنسية، والنسخ الاحتياطية في نفس القرص. وإذا كانت أداة `ncdu` مثبّتة، فهي نفس الفكرة بواجهة تفاعلية.

### المساحة لم تعد بعد الحذف؟

حذفت ملف سجلّ ضخمًا وما زال `df` يقول إن القرص ممتلئ؟ برنامج ما زال يفتح الملف، والنظام لا يحرّر المساحة حتى يُغلق:

```bash
sudo lsof +L1 | head          # ملفات محذوفة ما زالت مفتوحة
```

أعد تشغيل البرنامج صاحب الملف، أو الأفضل: لا تحذف سجلًّا مفتوحًا بل أفرغه: `: > /var/log/app.log`.

## free: الذاكرة

```bash
free -h
#               total   used   free  shared  buff/cache  available
# Mem:          3.8Gi  1.2Gi  300Mi   10Mi       2.3Gi      2.4Gi
# Swap:         1.0Gi     0B  1.0Gi
```

لا تقلق من `free` الصغيرة: Linux يستخدم الذاكرة غير المستغلّة كمخزن مؤقت للقرص (`buff/cache`)، ويعيدها فورًا لأي برنامج يحتاجها. **الرقم المهمّ هو `available`**. وحين ينفد هذا فعلًا، يبدأ النظام باستخدام Swap (بطيء جدًّا)، ثم يقتل أكبر عملية (OOM killer). تجد أثر ذلك في `sudo dmesg | grep -i "killed process"`.

## معلومات النظام

```bash
uname -r              # إصدار النواة
cat /etc/os-release   # التوزيعة وإصدارها
uptime                # منذ متى يعمل، ومتوسّط الحِمل
nproc                 # عدد أنوية المعالج
lscpu | head          # تفاصيل المعالج
```

## الأقراص والأقسام: lsblk و mount

```bash
lsblk
# NAME   SIZE TYPE MOUNTPOINTS
# sda     40G disk
# └─sda1  40G part /
# sdb    100G disk
# └─sdb1 100G part /data
```

`lsblk` تُظهر الأقراص الفعلية وأقسامها وأين رُبط كل قسم. ربط قرص جديد:

```bash
sudo mkdir -p /mnt/usb
sudo mount /dev/sdc1 /mnt/usb      # اربط
sudo umount /mnt/usb               # افصل (أغلق كل ما يستخدمه أولًا)
```

الربط بـ `mount` مؤقت ويختفي بعد إعادة الإقلاع. للربط الدائم يُضاف سطر إلى `/etc/fstab`، وخطأ فيه قد يمنع الإقلاع، فجرّبه بـ `sudo mount -a` قبل إعادة التشغيل.

## أخطاء شائعة

- **حذف سجلّ مفتوح:** المساحة لا تعود. أفرغه بـ `: > file` بدل حذفه.
- **الحكم على الذاكرة من عمود `free`:** انظر إلى `available`.
- **`du` على `/` بلا `2>/dev/null`:** آلاف رسائل الصلاحيات تُخفي النتيجة.
- **`umount` يقول "target is busy":** طرفية أو برنامج داخل المجلّد. اخرج منه (`cd ~`)، أو اعرف من يستخدمه بـ `lsof +D /mnt/usb`.
- **تجاهل `df -i`:** القرص "ممتلئ" بالملفات لا بالحجم.
