## المجاري الثلاثة

كل برنامج يبدأ ومعه ثلاث "قنوات" مفتوحة:

| الرقم | الاسم | افتراضيًا |
| --- | --- | --- |
| `0` | stdin: المدخل | لوحة المفاتيح |
| `1` | stdout: المخرج العادي | الشاشة |
| `2` | stderr: رسائل الأخطاء | الشاشة أيضًا |

المخرج والأخطاء يظهران معًا على الشاشة، لكنهما **قناتان منفصلتان**. وهذا الفصل هو ما يجعل الأنابيب وإعادة التوجيه مفيدة: تستطيع توجيه كل قناة لمكان مختلف.

## إعادة توجيه المخرج: `>` و `>>`

```bash
echo "الإصدار 1" > notes.txt     # > : أنشئ أو **امسح** ثم اكتب
echo "الإصدار 2" >> notes.txt    # >> : أضف في النهاية
cat notes.txt
ls /etc > files.txt              # مخرج أي أمر إلى ملف
```

`>` تمسح محتوى الملف **قبل** تشغيل الأمر. لذلك `sort data.txt > data.txt` تُفرغ الملف ثم ترتّب ملفًا فارغًا. اكتب الناتج لملف آخر ثم انقله، أو استخدم `sort -o data.txt data.txt`.

## إعادة توجيه الأخطاء: `2>`

```bash
ls /etc /nonexistent > out.txt 2> err.txt   # المخرج لملف والأخطاء لآخر
find / -name "*.conf" 2>/dev/null            # تجاهل رسائل "Permission denied"
cmd > all.log 2>&1                           # المخرج والأخطاء معًا في ملف واحد
cmd &> all.log                               # نفس الشيء، اختصار Bash
```

`/dev/null` "ثقب أسود": أي شيء يُكتب فيه يختفي. و`2>&1` تعني "وجّه القناة 2 إلى حيث تذهب القناة 1 **الآن**".

### الترتيب مهمّ

```bash
ls /nonexistent > out.txt 2>&1   # ✅ الاثنان في الملف
ls /nonexistent 2>&1 > out.txt   # ❌ الخطأ ما زال على الشاشة
```

في السطر الثاني: `2>&1` نفّذت أولًا حين كانت القناة 1 ما زالت الشاشة، فذهبت الأخطاء للشاشة، ثم وُجّهت القناة 1 وحدها للملف. القاعدة: `> file` أولًا، ثم `2>&1`.

## إعادة توجيه المدخل: `<`

```bash
sort < names.txt              # البرنامج يقرأ من الملف بدل لوحة المفاتيح
wc -l < names.txt             # العدد بلا اسم الملف
mysql mydb < backup.sql       # استعادة قاعدة بيانات من ملف
```

### Here-document

```bash
cat > config.ini <<'EOF'
[server]
port = 8080
EOF
```

`<<'EOF'` تمرّر الأسطر التالية حتى `EOF` كمدخل. طريقة مريحة لإنشاء ملف إعداد من داخل سكربت. وعلامات التنصيص حول `'EOF'` تمنع توسيع المتغيّرات داخله.

## الأنبوب `|`: مخرج أمر إلى مدخل آخر

```bash
ls -l /etc | wc -l                   # كم ملفًا في /etc؟
ps aux | grep nginx                  # هل nginx يعمل؟
history | grep ssh | tail -5         # آخر 5 أوامر ssh كتبتها
du -sh * | sort -h | tail -3         # أكبر 3 عناصر في المجلّد
```

الأنبوب يربط stdout للأول بـ stdin للثاني، والأمران يعملان **معًا** في نفس الوقت: لا ينتظر الثاني انتهاء الأول، ولا تُكتب ملفات وسيطة. لاحظ أن الأنبوب يمرّر stdout فقط؛ رسائل الأخطاء تبقى على الشاشة إلا إذا أضفت `2>&1` قبل `|`.

## tee: اعرض واحفظ معًا

```bash
make 2>&1 | tee build.log            # ترى المخرجات حيًّا وتُحفظ في الملف
echo "nameserver 1.1.1.1" | sudo tee -a /etc/resolv.conf
```

السطر الثاني يحلّ فخًّا مشهورًا: `sudo echo "x" >> /etc/file` **لا يعمل**، لأن إعادة التوجيه `>>` ينفّذها الـ Shell الخاص بك (كمستخدم عادي) قبل `sudo`. أما `sudo tee -a` فيفتح الملف بصلاحيات root.

## أخطاء شائعة

- **`> file` لملف تقرأ منه في نفس الأمر:** يُمسح قبل القراءة.
- **`>` بدل `>>`:** تمسح السجلّ القديم.
- **`2>&1` قبل `>`:** الأخطاء لا تذهب للملف.
- **`sudo echo ... > /etc/file`:** "Permission denied"؛ استخدم `| sudo tee`.
- **`grep` في مخرجات `ps` يُظهر نفسه:** `ps aux | grep nginx` تُظهر سطر `grep nginx` أيضًا. استخدم `pgrep -a nginx`.
