## خادمك يُهاجم الآن

أي خادم بعنوان IP عام يتلقّى محاولات دخول آلية خلال دقائق من تشغيله: برامج تجرّب كلمات سر شائعة على منفذ SSH بلا توقّف. افتح `/var/log/auth.log` على أي خادم جديد وسترى ذلك بعينك. الخطوات في هذا الدرس هي الحدّ الأدنى لأي خادم.

## 1. مفاتيح SSH بدل كلمات السر

```bash
# على جهازك أنت (لا الخادم):
ssh-keygen -t ed25519 -C "baraa@laptop"   # ينشئ ~/.ssh/id_ed25519 و id_ed25519.pub
ssh-copy-id baraa@server                  # ينسخ المفتاح العام للخادم
ssh baraa@server                          # الدخول الآن بلا كلمة سر
```

زوج المفاتيح: **الخاص** (`id_ed25519`) يبقى على جهازك ولا يغادره أبدًا، و**العام** (`.pub`) تنسخه لأي خادم. الخادم يتحقّق أنك تملك المفتاح الخاص دون أن يُرسل عبر الشبكة. لا يمكن تخمينه كما تُخمَّن كلمة سر، وضع عبارة مرور عليه عند السؤال فلا يُستخدم إن سُرق جهازك.

## 2. أغلق الدخول بكلمة السر ودخول root

بعد أن **تتأكّد** أن الدخول بالمفتاح يعمل، عدّل `/etc/ssh/sshd_config`:

```text
PasswordAuthentication no
PermitRootLogin no
```

```bash
sudo sshd -t && sudo systemctl reload ssh   # افحص الإعداد ثم طبّقه
```

**أبقِ جلستك الحالية مفتوحة** وجرّب الدخول من طرفية ثانية قبل أن تغلقها. خطأ هنا يقفل الخادم عليك، وعلى خادم سحابي قد تحتاج لوحة تحكّم المزوّد لاستعادته. واسم خدمة SSH هو `ssh` على Ubuntu وDebian، و`sshd` على Fedora وRHEL.

## 3. الجدار الناري: افتح ما تحتاجه فقط

```bash
sudo ufw default deny incoming     # ارفض كل الوارد افتراضيًا
sudo ufw default allow outgoing
sudo ufw allow OpenSSH             # ⚠️ قبل التفعيل! وإلا قطعت اتصالك
sudo ufw allow 80,443/tcp          # الويب
sudo ufw enable
sudo ufw status verbose
```

قاعدة "ارفض كل شيء ثم افتح المطلوب" أأمن من العكس. قاعدة البيانات مثلًا لا تُفتح للإنترنت أبدًا: تطبيقك يصل إليها محلّيًا. و`ufw` واجهة مبسّطة لـ Ubuntu؛ على Fedora وRHEL تستخدم `firewalld`. والمزوّدون السحابيون (AWS وغيرها) لهم جدار إضافي (Security Groups) فوق هذا.

## 4. التحديثات

```bash
sudo apt update && sudo apt upgrade
sudo apt install unattended-upgrades   # تحديثات الأمان تلقائيًا (Ubuntu/Debian)
```

معظم الاختراقات الحقيقية تستغلّ ثغرات **معروفة ولها إصلاح** لم يُثبَّت بعد.

## 5. أقلّ صلاحية

- **كل تطبيق بحسابه المحدود**، لا كـ root ([درس المستخدمين](/learn/linux/08-users-groups)).
- **صلاحيات محكمة للأسرار:** `chmod 600 .env` و`chmod 700 ~/.ssh` ([درس الصلاحيات](/learn/linux/02-permissions)).
- **لا `chmod 777`** لحلّ مشكلة.
- **لا خدمات غير مستخدمة:** كل منفذ مفتوح وبرنامج يعمل باب إضافي. افحص بـ `sudo ss -tlnp`.

## 6. راقب وأبطئ المهاجمين

```bash
sudo grep "Failed password" /var/log/auth.log | tail
sudo apt install fail2ban    # يحظر تلقائيًا العناوين التي تكرّر الفشل
```

`fail2ban` تقرأ السجلّات، وتحظر مؤقتًا أي عنوان يفشل في الدخول مرات متتالية.

## قائمة الخادم الجديد

1. مستخدم عادي مع `sudo`.
2. مفتاح SSH يعمل، ثم تعطيل كلمات السر ودخول root.
3. `ufw`: SSH أولًا، ثم المنافذ المطلوبة، ثم التفعيل.
4. تحديث كامل وتحديثات أمان تلقائية.
5. `fail2ban`.

## أخطاء شائعة

- **`ufw enable` قبل `allow OpenSSH`:** تقفل نفسك خارج الخادم.
- **تعطيل كلمات السر قبل التأكّد من المفتاح:** نفس النتيجة. جرّب من جلسة ثانية.
- **مشاركة المفتاح الخاص أو رفعه لـ Git:** أنشئ مفتاحًا جديدًا فورًا، واحذف العام القديم من `~/.ssh/authorized_keys` على كل خادم.
- **قاعدة بيانات مفتوحة للإنترنت:** اجعلها تستمع على `127.0.0.1` فقط.
- **"سأؤمّنه لاحقًا":** الهجمات تبدأ خلال دقائق. أمّنه قبل أن تضع عليه أي بيانات.
