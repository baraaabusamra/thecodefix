## find: البحث اللحظي بشروط

`find` يمشي في الشجرة **الآن** ويفحص كل ملف بالشروط التي تعطيها:

```bash
find . -name "*.txt"            # بالاسم (من المجلّد الحالي فما تحت)
find . -iname "readme*"         # بلا حساسية لحالة الأحرف
find /var/log -type f           # ملفات فقط (d مجلّدات، l روابط)
find . -size +100M              # أكبر من 100 ميغابايت
find . -mtime -7                # عُدّلت خلال آخر 7 أيام
find . -mmin -30                # خلال آخر 30 دقيقة
find . -empty                   # ملفات ومجلّدات فارغة
find . -name "*.js" -not -path "*/node_modules/*"   # استبعد مسارًا
```

ضع النمط **بين علامات تنصيص** دائمًا: `-name "*.txt"`. بدونها يوسّع الـ Shell النجمة أولًا إلى أسماء الملفات في المجلّد الحالي، فيبحث `find` عن شيء آخر تمامًا.

### دمج الشروط

```bash
find . -type f -name "*.log" -size +10M         # كلها معًا (AND افتراضيًا)
find . \( -name "*.jpg" -o -name "*.png" \)     # -o = OR، والأقواس مهرّبة
find /tmp -type f -mtime +7                     # أقدم من 7 أيام
```

## تنفيذ أمر على النتائج

```bash
find . -name "*.tmp" -delete                   # حذف مباشر
find . -name "*.sh" -exec chmod +x {} \;       # أمر لكل ملف: {} = اسم الملف
find . -name "*.log" -exec gzip {} +           # + : مرّر الكل في استدعاء واحد (أسرع)
```

### جرّب قبل أن تحذف

`-delete` بلا تراجع، ومكانها في الأمر مهمّ: `find . -delete -name "*.tmp"` تحذف **كل شيء** لأن `-delete` تُنفَّذ قبل الشرط. الطريقة الآمنة دائمًا:

```bash
find /tmp/myapp -type f -mtime +7                 # 1. شاهد القائمة
find /tmp/myapp -type f -mtime +7 -delete         # 2. نفس الأمر + -delete في الآخر
```

## مثال: أين ذهبت مساحة القرص؟

```bash
find / -xdev -type f -size +500M 2>/dev/null -exec ls -lh {} + | sort -k5 -h | tail
```

كل الملفات الأكبر من 500 ميغا على القرص الرئيسي (`-xdev`: لا تعبر لأقراص أخرى)، مع إخفاء رسائل "Permission denied"، مرتّبة بالحجم. للصورة العامة أولًا، استخدم `du` ([درس القرص والنظام](/learn/linux/19-disk-system)).

## locate: بحث فوري من فهرس

```bash
sudo updatedb          # حدّث الفهرس (يعمل تلقائيًا يوميًا عادة)
locate nginx.conf      # فوري حتى على أقراص ضخمة
```

`locate` لا يمشي في القرص: يبحث في قاعدة بيانات أسماء مبنية مسبقًا، لذلك هو أسرع بكثير لكنه **لا يرى** الملفات التي أُنشئت بعد آخر تحديث للفهرس. وقد يحتاج تثبيتًا (`sudo apt install plocate`).

| | `find` | `locate` |
| --- | --- | --- |
| السرعة | أبطأ (يمشي الآن) | فوري |
| الحداثة | دائمًا دقيق | حسب آخر `updatedb` |
| الشروط | حجم، تاريخ، نوع، صلاحيات... | الاسم فقط تقريبًا |

## أين البرنامج؟ which و type

```bash
which python3          # /usr/bin/python3 : أول نسخة في PATH
type -a python3        # كل النسخ، والـ aliases أيضًا
```

حين يعمل أمر "بإصدار خاطئ"، فغالبًا في `PATH` نسختان، و`type -a` تكشفهما.

## أخطاء شائعة

- **نمط بلا علامات تنصيص:** `find . -name *.txt` تتصرّف بشكل غريب إذا وُجد ملف txt في المجلّد الحالي.
- **`-delete` قبل الشروط:** تحذف كل شيء. ضعها في **آخر** الأمر، وجرّب بدونها أولًا.
- **البحث من `/` بلا `2>/dev/null`:** آلاف رسائل "Permission denied" تُخفي النتائج.
- **`find | xargs rm` مع أسماء فيها مسافات:** ينكسر. استخدم `-delete` أو `-exec ... +` أو `-print0 | xargs -0`.
- **`locate` لا يجد ملفًا أنشأته للتو:** الفهرس قديم؛ `sudo updatedb` أو استخدم `find`.
