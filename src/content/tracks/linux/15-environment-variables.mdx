## ما هي متغيّرات البيئة؟

قيم نصية بأسماء، يحملها كل برنامج معه من لحظة تشغيله، ويرثها أي برنامج يشغّله. هي الطريقة القياسية لإعطاء البرامج إعدادات دون تعديل الكود: أين تجد البرامج (`PATH`)، ومن المستخدم (`USER`)، وما اللغة (`LANG`)، وفي التطبيقات: رابط قاعدة البيانات، والمفاتيح السرّية، وهل نحن في وضع التطوير أم الإنتاج.

```bash
echo $HOME           # /home/baraa
echo $USER           # baraa
echo $PATH           # /usr/local/bin:/usr/bin:/bin:...
printenv             # كل متغيّرات البيئة
printenv LANG        # متغيّر واحد
```

## متغيّر Shell أم متغيّر بيئة؟

```bash
NAME="Baraa"                 # متغيّر Shell: في هذه الجلسة فقط
bash -c 'echo "[$NAME]"'     # []: البرنامج الفرعي لا يراه

export NAME="Baraa"          # متغيّر بيئة: يُورَّث للبرامج التي تشغّلها
bash -c 'echo "[$NAME]"'     # [Baraa]
```

بدون `export` يبقى المتغيّر داخل الـ Shell الحالي فقط. ومعها يُنسخ لكل برنامج تشغّله بعدها. وانتبه: **نسخ لا مشاركة**: إذا غيّر برنامج فرعي القيمة، لا يتغيّر شيء عند الأب.

### لأمر واحد فقط

```bash
PORT=4000 node server.js     # PORT موجود لهذا الأمر وحده
LANG=C sort names.txt        # ترتيب بالبايتات بدل قواعد اللغة
```

مفيد جدًّا لتجربة إعداد دون تغيير الجلسة كلها.

## PATH: كيف يجد الـ Shell الأوامر؟

حين تكتب `python3`، يبحث الـ Shell في مجلّدات `PATH` **بالترتيب** من اليسار، ويشغّل أول ملف بهذا الاسم يجده:

```bash
echo "$PATH" | tr ':' '\n'      # كل مجلّد في سطر
which python3                   # أي نسخة ستعمل فعلًا
export PATH="$HOME/.local/bin:$PATH"   # أضف مجلّدًا في البداية (له الأولوية)
export PATH="$PATH:/opt/tool/bin"      # أو في النهاية
```

"command not found" بعد تثبيت أداة تعني غالبًا أن مجلّدها ليس في `PATH`. وأكبر خطأ: `export PATH="/opt/tool/bin"` بلا `$PATH`، فتستبدل القائمة كلها، وتختفي `ls` و`cat` نفسها من الجلسة.

## اجعلها دائمة

المتغيّرات التي تكتبها في الطرفية تختفي حين تغلقها. لتبقى، أضفها لملف يُقرأ عند بداية كل جلسة:

| الملف | متى يُقرأ |
| --- | --- |
| `~/.bashrc` | كل طرفية Bash تفاعلية جديدة (الأشيع) |
| `~/.zshrc` | نفس الشيء لـ Zsh (macOS) |
| `~/.profile` | عند تسجيل الدخول (مثل SSH) |
| `/etc/environment` | لكل المستخدمين على النظام |

```bash
echo 'export EDITOR=nano' >> ~/.bashrc
source ~/.bashrc         # طبّق الآن دون فتح طرفية جديدة
```

## في التطبيقات: ملف .env

```bash
cat > .env <<'EOF'
DATABASE_URL=postgres://localhost/app
API_KEY=change-me
EOF

set -a; source .env; set +a      # صدّر كل ما في الملف للجلسة
echo "$DATABASE_URL"
```

تطبيقات Node وPython وغيرها تقرأ الإعدادات من البيئة، وفي التطوير تُحمَّل غالبًا من ملف `.env`. القاعدتان الذهبيتان:

- **أضف `.env` إلى `.gitignore` دائمًا.** المفاتيح السرّية في Git تبقى في التاريخ حتى لو حذفتها لاحقًا.
- **صلاحياته `600`**: لا يقرؤه غيرك ([درس الصلاحيات](/learn/linux/02-permissions)).

## أخطاء شائعة

- **مسافات حول `=`:** `NAME = "x"` يعني "شغّل أمرًا اسمه NAME". اكتب `NAME="x"`.
- **نسيان `export`:** المتغيّر لا يصل للبرنامج الذي تشغّله.
- **`PATH=...` بلا `$PATH`:** تمسح كل المسارات. افتح طرفية جديدة لاستعادتها.
- **تعديل `.bashrc` وانتظار التطبيق فورًا:** نفّذ `source ~/.bashrc`.
- **أسرار في `.env` داخل Git:** غيّر المفاتيح فورًا (اعتبرها مسرّبة)، ثم أضف الملف لـ `.gitignore`.
