## ميزة جديدة تبني على Cache Components

من Next.js 16.3 (إصدار مستقر من 3 أغسطس 2026)، فيه ميزة اسمها **Instant
Navigations** تبني مباشرة على `'use cache'` اللي تعلّمته بالدرس السابق.
الهدف: يصير التنقّل بين صفحات تطبيقك بنفس سرعة تطبيق صفحة واحدة (SPA) —
بدون ما تفقد فوائد التصيير على الخادم.

> 💡 الميزة اختيارية بالكامل (opt-in) بـ 16.3. فريق Next.js يخطط تصير
> الافتراضي بإصدار رئيسي قادم، بس حاليًا لازم تفعّلها صراحة.

## تفعيلها

فعّلها بـ `next.config.ts` — تحتاج `cacheComponents` (اللي تعرفه من الدرس
السابق) مع خيار جديد `partialPrefetching`:

```tsx
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  cacheComponents: true,
  partialPrefetching: true,
};

export default nextConfig;
```

## ثلاث طرق للتعامل مع كل مسار

لكل مسار بتطبيقك، عندك ثلاث خيارات تتحكّم فيها بسلوك التنقّل إليه:

### 1. Stream — هيكل تحميل فوري

لو المسار فيه `<Suspense>`، المستخدم يشوف هيكل التحميل (loading shell)
فورًا عند الضغط، والمحتوى الفعلي يتدفّق (stream) بعده — نفس فكرة
`loading.tsx` اللي تعرفها من درس التحميل والأخطاء.

### 2. Cache — تصيير مخزَّن يظهر فورًا

لو المسار (أو جزء منه) عليه `'use cache'`، Next.js يقدر يعرض النسخة
المخزَّنة فورًا بدون انتظار الخادم — لأن `'use cache'` صار يمتد الآن
لجهة العميل، مو بس للخادم متل ما تعلّمت بالدرس السابق.

### 3. Block — تعطيل التنقّل الفوري لمسار معيّن

لو ما تريد فرض التنقّل الفوري لمسار معيّن (مثلًا صفحة ما لازم أبدًا تعرض
حالة تحميل)، عطّله صراحة بتصدير `instant`:

```tsx
// app/blog/[slug]/page.tsx
export const instant = false;
```

> 💡 هذا مفيد جدًا أثناء الترحيل التدريجي: فعّل الميزة عالمستوى التطبيق
> كامل، وحط `instant = false` بس على المسارات اللي لسا ما جهّزتها
> (`'use cache'` أو `<Suspense>`) — وحوّلها وحدة وحدة بدون ما توقف باقي
> المشروع.

## Partial Prefetching: هيكل واحد لكل مسار

قبل هذي الميزة، الـ prefetch كان كل أو ولا شي: إما تجلب الصفحة كاملة
مسبقًا أو تعطّل الجلب المسبق نهائيًا. Partial Prefetching يحل هذا:
Next.js يستخرج هيكل تحميل (shell) قابل لإعادة الاستخدام من كل مسار،
ويخزّنه على العميل — مرّة وحدة بس.

مثال: لو عندك 20 رابط `<Link>` كلها تشاور على مسار ديناميكي زي
`/chat/[id]`، Next.js يجلب هيكل الصفحة مسبقًا **مرّة وحدة فقط** — مو 20
مرّة — ويعرضه فورًا عند الضغط على أي رابط منها، بينما المحتوى الفعلي
يتدفّق بعده.

## أداة فحص التنقّل (Navigation Inspector)

صار فيه أداة جديدة بـ Next.js DevTools تقدر توقف عندها أي عملية تنقّل
عند مرحلة الـ shell، وتشوف بالضبط شو انجلب مسبقًا لأي مسار — مفيدة
لتشخيص ليش مسار معيّن ما يتصرّف "فوري" متل ما توقّعت.

## الفلسفة وراء الميزة

هذا الاتجاه جزء من هدف أشمل لفريق Next.js: يرجّعوا الإطار لجذوره —
**ديناميكي افتراضيًا، بدون تخزين مؤقّت ضمني أو مخفي**. أنت تحدّد صراحةً
(بـ `'use cache'` و`<Suspense>` و`instant`) شو يُخزَّن وشو يبقى
ديناميكيًا، بدل ما Next.js يخمّن نيابة عنك.

## ملخّص سريع

| المفهوم | الوظيفة |
|---|---|
| `cacheComponents: true` | يفعّل نموذج التخزين الجديد (تعلّمته بالدرس السابق) |
| `partialPrefetching: true` | يفعّل Instant Navigations وPartial Prefetching |
| `<Suspense>` (Stream) | هيكل تحميل فوري، محتوى يتدفّق بعده |
| `'use cache'` (Cache) | تصيير مخزَّن يظهر فورًا من أول ضغطة |
| `export const instant = false` (Block) | تعطيل التنقّل الفوري لمسار معيّن |
