## المصفوفة في الذاكرة

**المصفوفة (Array)** عناصر محفوظة **متجاورة** في الذاكرة، خانة بعد خانة. هذه الحقيقة البسيطة تفسّر كل خصائصها:

```text
العنوان:  1000   1008   1016   1024   1032
القيمة:  [ 10 ] [ 20 ] [ 30 ] [ 40 ] [ 50 ]
الفهرس:    0      1      2      3      4
```

لتصل للعنصر رقم `i`، لا يحتاج الحاسوب البحث: يحسب عنوانه مباشرة `البداية + i × حجم العنصر`. `arr[3]` = 1000 + 3 × 8 = 1024. عملية حسابية واحدة مهما كان طول المصفوفة، لهذا **الوصول بالفهرس `O(1)`**. (لتذكير معنى `O(1)` و`O(n)`، راجع [درس تعقيد الخوارزميات](/learn/dsa/04-complexity-bigo).)

## تكلفة كل عملية

| العملية | التعقيد | لماذا |
| --- | --- | --- |
| قراءة أو تعديل `arr[i]` | `O(1)` | حساب عنوان |
| الإضافة في النهاية | `O(1)` غالبًا | خانة فارغة جاهزة (انظر أدناه) |
| الحذف من النهاية | `O(1)` | لا شيء يتحرّك |
| الإدراج أو الحذف في البداية أو الوسط | `O(n)` | كل ما بعده يُزاح خانة |
| البحث عن قيمة (غير مرتّبة) | `O(n)` | فحص عنصر عنصر |
| البحث في مصفوفة مرتّبة | `O(log n)` | [البحث الثنائي](/learn/dsa/18-searching) |

الإدراج في البداية هو الفخّ: لتضع `5` في الموضع 0، يجب أن ينتقل كل عنصر خانة لليمين أولًا. مع مليون عنصر، مليون نقلة.

```python
import timeit

setup = "arr = list(range(100_000))"
end = timeit.timeit("arr.append(1); arr.pop()", setup=setup, number=1000)
start = timeit.timeit("arr.insert(0, 1); arr.pop(0)", setup=setup, number=1000)
print(f"في النهاية: {end:.5f}s   في البداية: {start:.5f}s   (أبطأ ~{start / end:.0f} مرة)")
```

على قائمة بمئة ألف عنصر، الإدراج في البداية أبطأ بمئات المرات من النهاية، والفرق يكبر مع الحجم.

## المصفوفة الديناميكية

المصفوفة "الحقيقية" حجمها ثابت يُحجز مرة واحدة. لكن `list` في بايثون و`ArrayList` في جافا و`vector` في C++ تكبر كلما أضفت. كيف؟

```python
import sys

arr = []
last = sys.getsizeof(arr)
for i in range(30):
    arr.append(i)
    size = sys.getsizeof(arr)
    if size != last:
        print(f"عند العنصر رقم {len(arr):2}: {size} بايت")
        last = size
```

الحجم لا يزيد مع كل `append`، بل **بقفزات**: حين تمتلئ الخانات المحجوزة، تُحجز مساحة أكبر (أكبر بنسبة ثابتة تقريبًا)، ويُنسخ كل شيء إليها، ثم تبقى خانات فارغة لما يأتي بعدها. النسخ يكلّف `O(n)`، لكنه نادر ويتباعد كلما كبرت المصفوفة، فيكون متوسط تكلفة الإضافة عبر سلسلة طويلة `O(1)`. هذا ما يُسمّى **التكلفة المُطفأة (Amortized)**.

## أنماط تتكرّر في المسائل

### المجموع التراكمي (Prefix Sum)

سؤال: "ما مجموع العناصر من الموضع `i` إلى `j`؟" عشرات المرات على نفس المصفوفة.

```python
nums = [3, 1, 4, 1, 5, 9, 2, 6]

prefix = [0]
for x in nums:
    prefix.append(prefix[-1] + x)      # prefix[k] = مجموع أول k عناصر

def range_sum(i, j):                   # من i إلى j شاملًا
    return prefix[j + 1] - prefix[i]

print(range_sum(2, 5))                 # 4 + 1 + 5 + 9 = 19
```

حساب `prefix` مرة واحدة `O(n)`، ثم كل سؤال `O(1)` بدل `O(n)`. أنت تدفع ذاكرة إضافية لتشتري سرعة، وهذه المقايضة ستراها في كل مكان.

### العكس في المكان

```python
def reverse_in_place(arr):
    left, right = 0, len(arr) - 1
    while left < right:
        arr[left], arr[right] = arr[right], arr[left]
        left += 1
        right -= 1

data = [1, 2, 3, 4, 5]
reverse_in_place(data)
print(data)                            # [5, 4, 3, 2, 1]
```

مؤشّران من الطرفين يتقاربان: `O(n)` وقتًا و`O(1)` ذاكرة إضافية. هذه تقنية [المؤشّرين](/learn/dsa/19-two-pointers-sliding-window) التي تحلّ عائلة كاملة من المسائل.

## المصفوفة أم القائمة المترابطة؟

| تحتاج... | الأنسب |
| --- | --- |
| وصولًا سريعًا بالموضع (`arr[i]`) | مصفوفة |
| مرورًا متكرّرًا على كل العناصر (أسرع فعليًّا بفضل تجاور الذاكرة) | مصفوفة |
| إدراجًا وحذفًا متكرّرًا في البداية | [قائمة مترابطة](/learn/dsa/06-linked-lists) أو `deque` |
| حجمًا معروفًا مسبقًا وذاكرة محدودة | مصفوفة |

في الواقع العملي، المصفوفة الديناميكية هي الخيار الافتراضي في كل اللغات تقريبًا، لأن تجاور العناصر يجعل المعالج يقرؤها بسرعة كبيرة. القائمة المترابطة تفوز في حالات محدّدة، لا كبديل عام.

## أخطاء شائعة

- **`insert(0, x)` أو `pop(0)` داخل حلقة:** كل واحدة `O(n)`، فتصبح الحلقة `O(n²)`. للإضافة والحذف من البداية استخدم `collections.deque`.
- **`x in list` داخل حلقة على بيانات كبيرة:** بحث خطّي في كل دورة. حوّلها إلى `set` مرة واحدة.
- **الخطأ بواحد:** آخر فهرس `len(arr) - 1`، و`arr[len(arr)]` يرمي `IndexError`.
- **`[[0] * m] * n` لجدول ثنائي الأبعاد:** صفوف مشتركة؛ تعديل واحد يغيّرها كلها. استخدم `[[0] * m for _ in range(n)]`.
- **افتراض أن كل `append` `O(1)` حرفيًّا:** بعضها `O(n)`. المتوسط هو الثابت.
