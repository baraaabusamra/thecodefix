## نموذج الرفع

يحتاج `enctype="multipart/form-data"`:

```blade
<form method="POST" action="/upload" enctype="multipart/form-data">
  @csrf
  <input type="file" name="photo">
  <button type="submit">رفع</button>
</form>
```

## استقبال الملف والتحقّق

```php
<?php
public function upload(Request $request)
{
    $request->validate([
        'photo' => 'required|image|max:2048',   // صورة، أقصى 2MB
    ]);

    // تخزين في storage/app/public/photos
    $path = $request->file('photo')->store('photos', 'public');

    return back()->with('status', "تمّ الرفع: $path");
}
```

> ⚠️ تحقّق دائمًا من **النوع والحجم** (`image`, `max`) قبل القبول — رفع
> الملفّات بلا تحقّق ثغرة أمنية خطيرة.

## قواعد تحقّق الملفّات

| القاعدة | المعنى |
|---------|--------|
| `file` | ملف صالح |
| `image` | صورة (jpg/png/gif...) |
| `mimes:pdf,docx` | امتدادات محدّدة |
| `max:2048` | الحجم بالكيلوبايت |

## اسم مخصّص للملف

```php
<?php
$path = $request->file('photo')->storeAs(
    'photos',
    time() . '.' . $request->file('photo')->extension(),
    'public'
);
```

## الوصول العام للملفّات

اربط مجلّد التخزين بالعام مرّة واحدة:

```bash
php artisan storage:link
```

ثم اعرض الملف:

```blade
<img src="{{ asset('storage/' . $post->image) }}">
```

## حذف ملف

```php
<?php
use Illuminate\Support\Facades\Storage;

Storage::disk('public')->delete($path);
```

## الانتقال بين أقراص تخزين: قرص Read-Through 🌟

تخيّل مشروعًا يخزّن آلاف الملفّات على مزوّد قديم (Storage الخاص بخادم، أو خدمة تخزين قديمة)، وتريد الانتقال لمزوّد جديد (مثل Cloudflare R2) **دون توقّف الموقع ودون نقل كل الملفّات دفعة واحدة يدويًا**. قبل **Laravel 13.26** لم يكن هناك حل جاهز لهذه المشكلة الشائعة تحديدًا داخل الإطار نفسه.

قرص **read-through** يجمع بين قرصين — أساسي واحتياطي — بإعداد واحد في `config/filesystems.php`:

```php
<?php
'disks' => [
    // ... الأقراص المعتادة (local, public, s3...)

    'assets' => [
        'driver' => 'read-through',
        'primary' => 'r2',        // القرص الجديد
        'fallback' => 'legacy',   // القرص القديم يحتوي الملفّات الحالية
    ],
],
```

بعدها تتعامل مع القرص `assets` بنفس أوامر `Storage` المعتادة تمامًا — لا تغيير بالكود:

```php
<?php
use Illuminate\Support\Facades\Storage;

// لو الملف موجود فقط على legacy: Laravel يقرأه من هناك،
// وينسخه تلقائيًّا إلى r2 لأي طلب قادم لاحقًا
$contents = Storage::disk('assets')->get('photos/avatar.jpg');
```

- **القراءة:** تبحث بالقرص الأساسي أولًا؛ إن لم يوجد الملف هناك، تُقرأ من الاحتياطي وتُنسَخ تلقائيًّا للأساسي (ترقية كسولة/lazy) لتكون القراءة التالية من الأساسي مباشرة.
- **الكتابة والحذف وقوائم المجلّدات:** تستهدف القرص الأساسي دائمًا، لا الاحتياطي.
- **`throw_on_promotion_failure`:** افتراضيًا، فشل نسخ الملف للقرص الأساسي (مهلة شبكة، صلاحيات...) لا يوقف الطلب — يُرجع الملف من الاحتياطي بصمت. لتفعيل رمي استثناء صريح بدل هذا السلوك الصامت، أضف `'throw_on_promotion_failure' => true` لإعداد القرص.

> 💡 النتيجة: ملفّاتك "تهاجر بنفسها" تدريجيًا مع كل طلب فعلي يصل إليها، بلا سكربت هجرة ضخم يعمل مرّة واحدة ويخاطر بتوقف الخدمة.

## أخطاء شائعة

- نسيان `enctype="multipart/form-data"` فلا يصل الملف.
- نسيان `php artisan storage:link` فلا تظهر الصور.
- قبول الملفّات دون التحقّق من النوع والحجم.
- **افتراض أن قرص read-through يبقى دائمًا** → هو حل انتقالي مؤقت؛ بعد اكتمال الهجرة (كل الملفّات نُسخت للأساسي)، بدّل الإعداد ليشير مباشرة للقرص الجديد واحذف الاحتياطي.

> 🎯 التالي: المصادقة (Authentication).
