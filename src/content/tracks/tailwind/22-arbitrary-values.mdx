## ما هي؟

حين لا يوجد صنف جاهز للقيمة التي تحتاجها، اكتبها بين قوسين مربّعين:

```html
<div class="w-[347px]">عرض دقيق</div>
<div class="top-[117px]">موضع محدّد</div>
<p class="text-[15px]">حجم خطّ مخصّص</p>
<div class="bg-[#1da1f2]">لون علامة تجارية</div>
<div class="grid-cols-[200px_1fr_100px] grid">أعمدة مخصّصة</div>
```

Tailwind يولّد صنفًا لهذه القيمة بالضبط، بنفس آلية الأصناف العادية: يعمل مع كل البادئات (`hover:bg-[#1da1f2]` و`md:w-[347px]`)، ولا يُضاف إلى CSS إلا إذا استخدمته.

## قواعد الكتابة

- **لا مسافات داخل الصنف.** المسافة تفصل الأصناف، فـ `grid-cols-[200px 1fr]` صنفان مكسوران. استخدم **الشرطة السفلية** `_` مكان المسافة: `grid-cols-[200px_1fr]`.
- **الفواصل بلا مسافات:** `grid-cols-[repeat(auto-fill,minmax(16rem,1fr))]`.
- **شرطة سفلية حقيقية؟** هرّبها: `content-['a\_b']`.

### حين يكون النوع غامضًا

```html
<p class="text-[22px]">حجم خط (بكسل)</p>
<p class="text-[#ff5733]">لون</p>
<p class="text-(length:--my-size)">متغيّر غامض النوع: حدّد أنه طول</p>
```

`text-` تعني الحجم واللون معًا، وTailwind يستنتج من القيمة. وحين لا يستطيع (متغيّر CSS لا يعرف محتواه)، تخبره بالنوع صراحة.

## متغيّرات CSS: الأقواس العادية

```html
<div class="bg-(--brand-color) w-(--sidebar-width)">قيم من متغيّرات</div>
```

في v4، `bg-(--brand-color)` اختصار لـ `bg-[var(--brand-color)]`. مفيد حين تأتي القيمة من JavaScript أثناء التشغيل:

```html
<div style="--progress: 72%" class="h-2 w-(--progress) rounded-full bg-green-500"></div>
```

هذا هو الحل الصحيح للقيم **الديناميكية** (نسبة تقدّم، لون يختاره المستخدم). لا تحاول بناء `w-[${percent}%]` في الكود: Tailwind يقرأ الأصناف من الملفات قبل التشغيل، فلا يرى القيمة أبدًا.

## خصائص لا يغطّيها Tailwind

```html
<div class="[mask-type:luminance]">خاصية CSS كاملة</div>
<div class="[writing-mode:vertical-rl]">نص عمودي</div>
<div class="hover:[transform:rotateY(180deg)]">مع بادئة</div>
```

`[خاصية:قيمة]` تكتب أي CSS. للخصائص النادرة جدًّا التي لا يوجد لها صنف.

## محدّدات مخصّصة

```html
<ul class="[&>li]:py-2 [&>li:not(:last-child)]:border-b">
  <li>عنصر</li>
  <li>عنصر</li>
</ul>
```

`[&>li]:` تطبّق الصنف على كل `<li>` ابن مباشر. أداة قوية، لكن إذا احتجتها كثيرًا فالأوضح غالبًا وضع الأصناف على العناصر نفسها، أو `divide-y` ([درس الحدود](/learn/tailwind/10-borders)).

## متى تستخدمها، ومتى لا؟

استخدمها لـ:

- قيمة **فريدة** لا تتكرّر: موضع دقيق لعنصر زخرفي، أو أبعاد يفرضها تصميم خارجي (إعلان بمقاس محدّد).
- خاصية CSS لا يغطّيها Tailwind.
- قيمة ديناميكية عبر متغيّر CSS.

ولا تستخدمها حين:

- **تتكرّر القيمة:** `bg-[#b026ff]` في عشرين مكانًا يجب أن تصبح `--color-brand` في `@theme` ([درس التخصيص](/learn/tailwind/19-customization)).
- **توجد قيمة قريبة في المقياس:** `p-[15px]` بدل `p-4` (16px) تكسر إيقاع المسافات المتناسق دون فرق تلاحظه العين.

القيم الاعتباطية الكثيرة في مشروع علامة على أن الثيم يحتاج إعدادًا، أو أن التصميم لا يتبع نظامًا.

## أخطاء شائعة

- **مسافات داخل القوسين:** الصنف ينكسر بصمت. استخدم `_`.
- **بناء القيمة في JavaScript** (`` `w-[${x}px]` ``): لا تُولَّد. استخدم متغيّر CSS في `style`.
- **نفس اللون الاعتباطي في كل مكان:** عرّفه في `@theme`.
- **`p-[15px]` بدل `p-4`:** فرق لا يُرى، واتّساق يضيع.
- **`bg-[var(--x)]` الطويلة في v4:** الصيغة المختصرة `bg-(--x)` أوضح.
