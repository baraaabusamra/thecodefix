## البادئة dark:

```html
<div class="bg-white text-gray-900 dark:bg-gray-900 dark:text-gray-100">
  يتكيّف مع الوضع
</div>
```

`dark:` مثل أي بادئة حالة: الصنف ينطبق فقط في الوضع الداكن. تكتب ألوان الوضع الفاتح كالعادة، وتضيف بجوار كل لون نظيره الداكن.

## متى يكون "داكنًا"؟ طريقتان

### 1. حسب إعداد الجهاز (الافتراضي)

بلا أي إعداد، `dark:` تتبع تفضيل نظام التشغيل (`prefers-color-scheme: dark`). إذا كان هاتف الزائر على الوضع الداكن، يصبح موقعك داكنًا تلقائيًا.

### 2. زرّ تبديل يدوي

إذا أردت زرًّا يختار فيه المستخدم بنفسه، اجعل `dark:` تعتمد على صنف `dark` في `<html>` بدل إعداد النظام:

```css
@import "tailwindcss";

@custom-variant dark (&:where(.dark, .dark *));
```

```js
// عند الضغط على زرّ التبديل
const isDark = document.documentElement.classList.toggle("dark");
localStorage.setItem("theme", isDark ? "dark" : "light");
```

في Tailwind v3 كان هذا الإعداد `darkMode: "class"` في `tailwind.config.js`. في v4 صار سطر `@custom-variant` في CSS.

### منع الوميض الأبيض

إذا طبّقت الوضع المحفوظ بعد تحميل الصفحة، يرى الزائر وميضًا أبيض لجزء من الثانية قبل أن تصبح داكنة. الحل سكربت صغير في `<head>` **قبل** أي محتوى:

```html
<script>
  try {
    const saved = localStorage.getItem("theme");
    const prefersDark = matchMedia("(prefers-color-scheme: dark)").matches;
    if (saved === "dark" || (!saved && prefersDark)) {
      document.documentElement.classList.add("dark");
    }
  } catch (e) {}
</script>
```

يعمل قبل رسم الصفحة، فتظهر بالوضع الصحيح من البداية. و`try` تحمي من المتصفّحات التي تمنع `localStorage` (التصفّح الخاص مثلًا). وفي Next.js، مكتبة `next-themes` تتولّى كل هذا.

## ألوان الوضع الداكن: ليست مجرّد عكس

```html
<article class="rounded-xl border border-gray-200 bg-white p-6 text-gray-900
                dark:border-gray-700 dark:bg-gray-800 dark:text-gray-100">
  <h2 class="font-bold">بطاقة</h2>
  <p class="text-gray-600 dark:text-gray-400">نص ثانوي</p>
  <a class="text-purple-700 dark:text-purple-300" href="#">رابط</a>
</article>
```

قواعد تجعل الوضع الداكن مريحًا لا مُتعِبًا:

- **ليس أسود خالصًا:** `gray-900` أو `gray-950` للخلفية، لا `black`. والأبيض الخالص على الأسود الخالص يُبهر العين ويجعل النص "يرتجف".
- **الارتفاع بالتفتيح لا بالظل:** في الوضع الفاتح البطاقة تبرز بالظل. في الداكن الظل لا يُرى، فاجعل العنصر الأعلى **أفتح** قليلًا (الصفحة `gray-900`، والبطاقة `gray-800`).
- **الألوان الزاهية أفتح درجة:** `purple-700` مقروء على الأبيض، لكنه باهت على الداكن، فاستخدم `purple-300` أو `400`.
- **راجع الصور والشعارات:** شعار أسود بخلفية شفّافة يختفي على خلفية داكنة.

### متغيّرات بدل التكرار

```css
@theme {
  --color-surface: var(--surface);
  --color-ink: var(--ink);
}
:root { --surface: #ffffff; --ink: #111827; }
.dark { --surface: #111827; --ink: #f3f4f6; }
```

```html
<div class="bg-surface text-ink">يتغيّر تلقائيًا بلا dark: في كل مكان</div>
```

في مشروع كبير، كتابة `dark:` بجوار كل لون تتكرّر كثيرًا. تعريف ألوان "دلالية" (`surface` و`ink`) تتغيّر قيمتها مع الوضع يجعل القوالب أنظف.

## أخطاء شائعة

- **إعداد v3 (`darkMode: "class"`) في مشروع v4:** لا يحدث شيء. استخدم `@custom-variant`.
- **وميض أبيض عند التحميل:** طبّق الصنف بسكربت في `<head>`.
- **`bg-black` و`text-white`:** تباين حادّ متعب. استخدم الرماديات الداكنة والفاتحة.
- **نسيان الحدود والنصوص الثانوية:** الخلفية تتغيّر ويبقى `border-gray-200` ساطعًا.
- **عدم اختبار الوضعين:** افتح أدوات المطوّر، وحاكِ `prefers-color-scheme` من لوحة Rendering.
