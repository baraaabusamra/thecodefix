## سؤالان لكل متغيّر

صنف التخزين يجيب عن سؤالين:

1. **العمر (lifetime):** متى يُنشأ المتغيّر ومتى يختفي؟
2. **الرؤية (linkage):** من يستطيع الوصول إليه: هذه الكتلة فقط، أم هذا الملف، أم كل ملفات البرنامج؟

| التعريف | العمر | الرؤية |
| --- | --- | --- |
| متغيّر محلّي عادي | حتى نهاية الكتلة | داخل الكتلة |
| `static` داخل دالة | كل عمر البرنامج | داخل الدالة فقط |
| متغيّر عام عادي | كل عمر البرنامج | كل الملفات (عبر `extern`) |
| `static` على مستوى الملف | كل عمر البرنامج | هذا الملف فقط |

## الثوابت

```c
const double PI = 3.14159;   // متغيّر لا يمكن تعديله، له نوع
#define MAX 100              // استبدال نصّي قبل الترجمة
```

الفرق بينهما مشروح في درس أنواع البيانات؛ والخلاصة: فضّل `const` لأن له نوعًا يفحصه المترجم.

## static داخل الدالة

يحفظ قيمة المتغيّر بين الاستدعاءات، ويُهيّأ **مرة واحدة** فقط (وبصفر إن لم تهيّئه):

```c
void counter(void) {
    static int count = 0;   // يُهيّأ مرّة واحدة
    count++;
    printf("%d\n", count);  // 1 ثم 2 ثم 3...
}

int main(void) {
    counter();
    counter();
    counter();
    return 0;
}
```

استخدامات حقيقية: عدّاد استدعاءات، أو حساب نتيجة مكلفة مرة واحدة وحفظها. لكن انتبه: دالة فيها `static` تحمل **حالة مخفية**، فنتيجتها تعتمد على كم مرة استُدعيت، وهذا يصعّب اختبارها ولا يصلح مع الخيوط المتعدّدة (threads) بلا حماية.

## static على مستوى الملف: "خاص بهذا الملف"

نفس الكلمة بمعنى مختلف تمامًا. أمام دالة أو متغيّر عام، `static` تعني: **لا يراه أي ملف آخر**:

```c
static int cache_hits = 0;            // لا يصل إليه إلا هذا الملف

static int helper(int x) {            // دالة داخلية
    return x * 2;
}

int public_api(int x) {               // تراها الملفات الأخرى
    cache_hits++;
    return helper(x);
}
```

هذه طريقة C لعمل "private": اجعل كل دالة مساعدة `static`، واترك بدونها فقط ما يجب أن تستدعيه الملفات الأخرى. هذا يمنع تصادم الأسماء حين يكون لملفّين دالة `helper` كلٌّ منهما.

## extern: تصريح لا تعريف

في برنامج من عدّة ملفات، المتغيّر العام **يُعرَّف** (تُحجز ذاكرته) في ملف `.c` واحد فقط، وباقي الملفات **تصرّح** بوجوده بـ `extern`:

```c
// config.h — يُضمَّن في كل الملفات
extern int debug_level;      // تصريح: "موجود في مكان ما"

// config.c — ملف واحد فقط
int debug_level = 0;         // تعريف: الذاكرة هنا
```

لو وضعت `int debug_level = 0;` في ملف الرأس نفسه، فكل ملف يضمّنه سيعرّفه من جديد، ويرفض الرابط البرنامج بخطأ "multiple definition". (منذ GCC 10 يحدث هذا أيضًا مع `int debug_level;` بلا قيمة، لأن الخيار `-fno-common` صار افتراضيًا.) التفاصيل الكاملة لتقسيم البرنامج في [درس تنظيم البرنامج عبر ملفات متعددة](/learn/c/24-multi-file-programs).

## register و auto

- **`register`:** تلميح قديم لتخزين المتغيّر في سجلّ المعالج. المترجمات الحديثة تقرّر هذا أفضل منك وتتجاهله غالبًا، والأثر الوحيد المضمون أنك لا تستطيع أخذ عنوانه بـ `&`. لا تستخدمه.
- **`auto`:** تاريخيًا تعني "متغيّر محلّي عادي"، وهو الافتراضي أصلًا فلم يكتبها أحد. في معيار C23 صار لها معنى جديد: **استنتاج النوع** من القيمة، مثل `auto x = 5;` (يصبح `int`)، ويحتاج مترجمًا يدعم C23 (مثل `gcc -std=c2x` في GCC 13).

## أخطاء شائعة

- **تعريف متغيّر (لا تصريحه) في ملف `.h`:** خطأ "multiple definition" عند الربط. ضع `extern` في الرأس والتعريف في `.c` واحد.
- **ظنّ أن `static` المحلّي يُعاد تهيئته في كل استدعاء:** التهيئة تحدث مرة واحدة فقط.
- **نسيان `static` للدوال المساعدة:** أسماؤها تصبح عامة وقد تتصادم مع ملفات أو مكتبات أخرى.
- **تعديل متغيّر `const` عبر مؤشّر بإزالة const بالتحويل:** سلوك غير معرّف، حتى لو بدا أنه يعمل.
- **الاعتماد على المتغيّرات العامة لتمرير البيانات بين الدوال:** مرّرها كمعاملات؛ الحالة العامة تجعل كل دالة قادرة على تغيير كل شيء.
