## التضمين والربط

```c
#include <math.h>
```

على Linux توجد دوال الرياضيات في مكتبة منفصلة (`libm`)، فتحتاج غالبًا إضافة `-lm` **في آخر** أمر الترجمة:

```bash
gcc file.c -o app -lm
```

بدونها قد ترى خطأ ربط مثل `undefined reference to 'sqrt'`. وقد يعمل كودك أحيانًا بدونها لأن المترجم يحسب `sqrt(25)` الثابتة بنفسه وقت الترجمة، ثم يفشل حين تمرّر متغيّرًا. أضف `-lm` دائمًا حين تستخدم `math.h`.

## دوال شائعة

كلها تأخذ `double` وتُرجع `double`:

```c
printf("%.2f\n", sqrt(25));    // 5.00  الجذر التربيعي
printf("%.2f\n", pow(2, 10));  // 1024.00  الأُس
printf("%.2f\n", ceil(4.1));   // 5.00  للأعلى
printf("%.2f\n", floor(4.9));  // 4.00  للأسفل
printf("%.2f\n", round(4.5));  // 5.00  لأقرب عدد صحيح
printf("%.2f\n", fabs(-7.5));  // 7.50  القيمة المطلقة للعشري
printf("%d\n", abs(-7));       // 7     للأعداد الصحيحة (stdlib.h)
printf("%.2f\n", fmod(10, 3)); // 1.00  باقي القسمة للعشري
```

ودوال أخرى: `sin` و`cos` و`tan` (بالراديان لا بالدرجات)، و`log` (اللوغاريتم الطبيعي)، و`log10`، و`exp`.

### مثال عملي: المسافة بين نقطتين

```c
double distance(double x1, double y1, double x2, double y2) {
    double dx = x2 - x1, dy = y2 - y1;
    return sqrt(dx * dx + dy * dy);
}

const double PI = 3.14159265358979323846;

int main(void) {
    printf("%.2f\n", distance(0, 0, 3, 4));   // 5.00

    double deg = 30;
    double rad = deg * PI / 180.0;     // الدوال المثلّثية تأخذ راديان
    printf("%.2f\n", sin(rad));        // 0.50
    return 0;
}
```

عرّفنا `PI` بأنفسنا لأن الثابت الشائع `M_PI` ليس جزءًا من معيار C: يعمل مع الإعدادات الافتراضية لـ gcc وclang، لكنه يختفي مع خيار صارم مثل `-std=c17`، وعلى MSVC يحتاج تعريف `_USE_MATH_DEFINES` قبل التضمين.

## مقارنة الكسور بهامش

كما رأيت في درس أنواع البيانات، `0.1 + 0.2 == 0.3` خطأ. قارن الفرق بهامش صغير (epsilon):

```c
double a = 0.1 + 0.2, b = 0.3;
printf("%d\n", a == b);                    // 0
printf("%d\n", fabs(a - b) < 1e-9);        // 1
```

اختر الهامش حسب حجم أرقامك: `1e-9` مناسب لقيم قريبة من الواحد، أما مع أرقام بالملايين فتحتاج هامشًا نسبيًا.

## القسمة على صفر: صحيح أم عشري؟

النتيجة مختلفة تمامًا حسب النوع:

```c
double z = 0.0;
printf("%f %f\n", 1.0 / z, 0.0 / z);   // inf -nan (أو nan)
printf("%d %d\n", isinf(1.0 / z) != 0, isnan(0.0 / z) != 0);   // 1 1
```

- **مع الكسور:** النتيجة قيمة خاصة: `inf` (لا نهاية) أو `nan` (ليس رقمًا)، والبرنامج يكمل. افحصها بـ `isinf` و`isnan`.
- **مع الأعداد الصحيحة:** `5 / 0` **سلوك غير معرّف**، وعلى معظم الأنظمة ينهار البرنامج فورًا. افحص المقسوم عليه قبل القسمة.

## أخطاء شائعة

- **نسيان `-lm`:** خطأ `undefined reference` عند الربط.
- **`abs` مع كسر:** `abs(-7.5)` تحوّل القيمة لعدد صحيح فتُرجع `7`. استخدم `fabs`. gcc يحذّرك بـ `-Wabsolute-value` ضمن `-Wextra`.
- **طباعة نتيجة `pow` بـ `%d`:** `pow` تُرجع `double`؛ استخدم `%f`، أو حوّل صراحة. ولأس صحيح صغير، الضرب بحلقة أدقّ وأسرع.
- **الدرجات بدل الراديان** في `sin` و`cos`.
- **`(int)x` للتقريب:** يقتطع نحو الصفر (`(int)2.9` = 2). للتقريب الحقيقي استخدم `round` أو `lround`.
