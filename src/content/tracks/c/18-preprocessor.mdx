## ما هو المعالج المسبق؟

قبل أن يرى المترجم كودك، يمرّ عليه **المعالج المسبق** (preprocessor) وينفّذ كل سطر يبدأ بـ `#`. عمله **نصّي بحت**: ينسخ ملفات، ويستبدل كلمات بكلمات، ويحذف مقاطع. لا يعرف شيئًا عن الأنواع أو الدوال أو قواعد C. هذا مصدر قوّته ومصدر كل فخاخه.

لترى ناتجه بنفسك:

```bash
gcc -E program.c | tail -20
```

## include

```c
#include <stdio.h>      // مكتبة قياسية: يبحث في مجلّدات النظام
#include "myheader.h"   // ملف من مشروعك: يبحث في مجلّد الملف أولًا
```

`#include` تنسخ محتوى الملف **حرفيًا** مكان السطر. لهذا يحتوي ملف الرأس تصريحات فقط (نماذج دوال، أنواع، `extern`)، لا تعريفات.

## define: الثوابت والماكرو

```c
#define PI 3.14159
#define SQUARE(x) ((x) * (x))   // ماكرو بمعامل

printf("%d\n", SQUARE(4));      // 16
```

الماكرو ليس دالة: `SQUARE(4)` تُستبدل نصيًا بـ `((4) * (4))` قبل الترجمة.

### فخ الأقواس

لماذا كل هذه الأقواس؟ انظر ماذا يحدث بدونها:

```c
#define BAD_SQUARE(x) x * x
#define DOUBLE(x) (x) + (x)

printf("%d\n", BAD_SQUARE(1 + 2));   // 5 لا 9: تصبح 1 + 2 * 1 + 2
printf("%d\n", 10 * DOUBLE(3));      // 33 لا 60: تصبح 10 * (3) + (3)
```

القاعدتان: ضع **كل معامل** بين أقواس، وضع **الماكرو كله** بين أقواس.

### فخ الآثار الجانبية

حتى مع الأقواس، المعامل يُنسخ **مرّتين**:

```c
int i = 3;
// int r = SQUARE(i++);   // تصبح ((i++) * (i++)): زيادتان، وسلوك غير معرّف
```

لا تمرّر للماكرو تعبيرًا يغيّر شيئًا (`i++` أو استدعاء دالة لها أثر). وهذا سبب وجيه لتفضيل البديل الحديث:

```c
static inline int square(int x) { return x * x; }   // دالة حقيقية: نوع مفحوص، تقييم مرة واحدة
```

مع `-O2` يُدمج كود الدالة `inline` في مكان الاستدعاء غالبًا، فلا تخسر سرعة. القاعدة العملية: `const` للثوابت و`static inline` للعمليات، والماكرو فقط لما لا تقدر عليه الدوال (مثل الترجمة الشرطية أو `__FILE__` و`__LINE__`).

### ماكرو بعدّة أوامر: do ... while (0)

```c
#define LOG_ERROR(msg) do { \
    fprintf(stderr, "[%s:%d] %s\n", __FILE__, __LINE__, msg); \
} while (0)

int ok = 0;
if (!ok)
    LOG_ERROR("فشل الاتصال");
else
    printf("تمّ\n");
```

غلاف `do { ... } while (0)` يجعل الماكرو يتصرّف كجملة واحدة، فيعمل بأمان بعد `if` بلا أقواس. والشرطة العكسية `\` في آخر السطر تكمل الماكرو على السطر التالي. `__FILE__` و`__LINE__` يُستبدلان باسم الملف ورقم السطر، وهذا ما لا تستطيعه دالة عادية.

## الترجمة الشرطية

تضمّن كودًا أو تحذفه **قبل** الترجمة، حسب نظام التشغيل أو وضع البناء:

```c
#ifdef DEBUG
    printf("وضع التصحيح مفعّل\n");
#endif

#ifdef _WIN32
    printf("Windows\n");
#else
    printf("ليس Windows\n");
#endif
```

يمكنك تعريف `DEBUG` من سطر الأوامر دون تعديل الكود: `gcc -DDEBUG program.c`.

### `#ifdef` أم `#if`؟

- `#ifdef DEBUG` تسأل: هل الاسم **معرّف** أصلًا؟ فحتى `#define DEBUG 0` تجعلها صحيحة!
- `#if DEBUG` تسأل عن **القيمة**. والاسم غير المعرّف يُعامل كأنه `0` بصمت، فخطأ إملائي مثل `#if DEBGU` لا يعطيك أي خطأ.

اختر أسلوبًا واحدًا في مشروعك والتزم به. `-Wundef` في gcc يحذّرك من الأسماء غير المعرّفة في `#if`.

## حماية ملفات الرأس

إذا ضُمّن ملف الرأس مرّتين (مباشرة أو عبر رأس آخر)، تتكرّر تعريفات الأنواع فيه ويفشل البرنامج. الحماية:

```c
#ifndef MYHEADER_H
#define MYHEADER_H

typedef struct { int x, y; } Point;

#endif
```

في المرة الأولى `MYHEADER_H` غير معرّف، فيُعرَّف ويُضمَّن المحتوى. في المرة الثانية يُتخطّى كله. البديل المختصر `#pragma once` في أول الملف، وتدعمه كل المترجمات الشائعة (gcc وclang وMSVC) رغم أنه ليس جزءًا من المعيار رسميًا.

## أخطاء شائعة

- **ماكرو بلا أقواس:** `#define DOUBLE(x) x + x` تعطي نتائج خاطئة داخل تعابير أكبر.
- **فاصلة منقوطة في آخر `#define`:** `#define MAX 100;` تكسر `int a[MAX];`.
- **تمرير `i++` لماكرو:** يُقيَّم مرّتين.
- **مسافة بين اسم الماكرو والقوس:** `#define SQ (x) ...` تعرّف ثابتًا اسمه `SQ` قيمته `(x) ...`، لا ماكرو بمعامل.
- **رأس بلا حماية:** أخطاء "redefinition" حين يكبر المشروع.
