## ما هي المصفوفة؟

المصفوفة مجموعة عناصر **من نفس النوع** مخزّنة **متجاورة** في الذاكرة. بدل خمسة متغيّرات `mark1` و`mark2` و...، تعرّف اسمًا واحدًا وتصل لكل عنصر برقمه (الفهرس):

```c
int numbers[5] = {10, 20, 30, 40, 50};
printf("%d\n", numbers[0]);   // 10  (الفهرسة تبدأ من 0)
numbers[2] = 99;              // تعديل عنصر
```

حجم المصفوفة **ثابت** يُحدَّد عند تعريفها ولا يتغيّر. إذا احتجت حجمًا يُعرَف أثناء التشغيل أو يكبر، فهذا عمل الذاكرة الديناميكية (`malloc`) في درس لاحق.

## طرق التهيئة

```c
int a[5] = {1, 2};          // {1, 2, 0, 0, 0}: الباقي أصفار
int b[5] = {0};             // كلها أصفار: الطريقة المعتادة للتصفير
int c[] = {4, 5, 6};        // الحجم يُستنتج: 3
```

انتبه: مصفوفة محلّية **بلا تهيئة** إطلاقًا (`int d[5];`) تحتوي قيمًا عشوائية متبقّية في الذاكرة، لا أصفارًا.

## المرور على المصفوفة وحساب الطول

C لا تحفظ طول المصفوفة في أي مكان. داخل نفس النطاق الذي عُرّفت فيه، تحسبه بـ `sizeof`:

```c
int n[] = {3, 8, 1, 9};
size_t len = sizeof(n) / sizeof(n[0]);   // الحجم الكلّي ÷ حجم عنصر = 4

int sum = 0, max = n[0];
for (size_t i = 0; i < len; i++) {
    sum += n[i];
    if (n[i] > max) max = n[i];
}
printf("المجموع %d، الأكبر %d\n", sum, max);   // 21، 9
```

## C لا تفحص الحدود

هذه أهمّ نقطة في الدرس. إذا كتبت `numbers[5]` لمصفوفة من 5 عناصر، **لن** تحصل على رسالة خطأ واضحة كما في Python أو Java. البرنامج يقرأ أو يكتب في الذاكرة التي بعد المصفوفة، وهذا **سلوك غير معرّف**: قد يعمل بالصدفة، أو يعطي قيمًا غريبة، أو يُفسد متغيّرًا آخر، أو ينهار بعد ساعات في مكان لا علاقة له.

هذا النوع من الأخطاء (buffer overflow) أصل عدد كبير من الثغرات الأمنية في برامج C الحقيقية. لاكتشافه أثناء التطوير، ترجم مع فاحص العناوين:

```bash
gcc -g -fsanitize=address program.c -o program
```

فيتوقّف البرنامج عند أول وصول خارج الحدود ويخبرك بالسطر بالضبط.

## تمرير مصفوفة لدالة

حين تمرّر مصفوفة لدالة، **لا تُنسخ**: الدالة تستلم مؤشّرًا لأول عنصر فقط. لذلك:

1. أي تعديل داخل الدالة يغيّر المصفوفة الأصلية.
2. الدالة لا تعرف الطول، فـ `sizeof` بداخلها يعطي حجم **المؤشّر** (8 بايت عادة)، لا المصفوفة.

الحل المعتاد: مرّر الطول كمعامل منفصل.

```c
double average(const int arr[], size_t len) {
    // sizeof(arr) هنا = حجم مؤشّر، لا تستخدمه
    int sum = 0;
    for (size_t i = 0; i < len; i++) sum += arr[i];
    return (double)sum / len;
}

int main(void) {
    int marks[] = {80, 90, 70};
    size_t len = sizeof(marks) / sizeof(marks[0]);   // هنا يعمل: 3
    printf("%.1f\n", average(marks, len));           // 80.0
    return 0;
}
```

كلمة `const` في المعامل تعد المستدعي بأن الدالة لن تعدّل المصفوفة، والمترجم يمنعها إن حاولت.

## مصفوفة ثنائية الأبعاد

```c
int grid[2][3] = {
    {1, 2, 3},
    {4, 5, 6}
};
printf("%d\n", grid[1][2]);   // 6

for (int r = 0; r < 2; r++) {
    for (int c = 0; c < 3; c++) {
        printf("%d ", grid[r][c]);
    }
    printf("\n");
}
```

الصفوف مخزّنة متتالية في الذاكرة (الصف الأول ثم الثاني). لذلك المرور صفًّا صفًّا كما في المثال أسرع من المرور عمودًا عمودًا مع المصفوفات الكبيرة.

## أخطاء شائعة

- **`i <= len` بدل `i < len`:** دورة إضافية تقرأ عنصرًا غير موجود.
- **`sizeof(arr)` داخل دالة:** يعطي حجم مؤشّر. gcc يحذّرك بـ `-Wsizeof-array-argument`؛ مرّر الطول.
- **نسخ مصفوفة بالإسناد:** `b = a;` خطأ ترجمة. انسخ بحلقة أو بـ `memcpy(b, a, sizeof(a))`.
- **مقارنة مصفوفتين بـ `==`:** يقارن العنوانين لا المحتوى. قارن عنصرًا عنصرًا أو بـ `memcmp`.
- **إرجاع مصفوفة محلّية من دالة:** تختفي عند انتهاء الدالة. سترى البديل في درسي المؤشّرات وإدارة الذاكرة.
