## المكدّس والكومة

المتغيّرات المحلّية تعيش في **المكدّس** (stack): تُحجز تلقائيًا عند دخول الدالة وتُحرَّر تلقائيًا عند خروجها، وحجمها يجب أن يُعرَف مسبقًا. هذا سريع ومريح، لكنه لا يكفي حين:

- لا تعرف الحجم إلا أثناء التشغيل (عدد طلاب يُدخله المستخدم، ملف بحجم غير معروف).
- تحتاج البيانات أن تبقى **بعد** انتهاء الدالة التي أنشأتها.
- البيانات كبيرة جدًّا على المكدّس (حجمه محدود، غالبًا بضعة ميغابايتات).

هنا تحجز من **الكومة** (heap) بنفسك، وتحرّرها بنفسك. C لا تملك جامع نفايات (garbage collector) كما في Java أو Python.

## malloc و free

```c
#include <stdlib.h>

size_t n = 5;
int *arr = malloc(n * sizeof *arr);   // حجز مكان لـ 5 أعداد
if (arr == NULL) {
    fprintf(stderr, "فشل حجز الذاكرة\n");
    return 1;
}

for (size_t i = 0; i < n; i++) arr[i] = (int)i * 10;
printf("%d\n", arr[4]);   // 40

free(arr);    // أعِد الذاكرة عند الانتهاء
arr = NULL;   // حتى لا يبقى مؤشّرًا معلّقًا
```

ثلاث تفاصيل في هذا المثال:

- `sizeof *arr` تعني "حجم العنصر الذي يشير إليه arr". إذا غيّرت النوع لاحقًا إلى `double` يبقى السطر صحيحًا تلقائيًا.
- `malloc` تُرجع `NULL` إذا فشل الحجز. **افحص دائمًا** قبل الاستخدام.
- في C لا داعي لكتابة `(int *)` قبل `malloc`؛ التحويل من `void *` تلقائي.

## مثال حقيقي: دالة تُرجع مصفوفة

مصفوفة محلّية تختفي بانتهاء الدالة، أما المحجوزة بـ `malloc` فتبقى حتى تحرّرها. لذلك هذه هي الطريقة الصحيحة لدالة تُنشئ مصفوفة وتُرجعها:

```c
int *make_squares(size_t n) {
    int *a = malloc(n * sizeof *a);
    if (a == NULL) return NULL;
    for (size_t i = 0; i < n; i++) a[i] = (int)(i * i);
    return a;                     // المستدعي مسؤول عن free
}

int main(void) {
    int *sq = make_squares(4);
    if (sq == NULL) return 1;
    printf("%d %d\n", sq[2], sq[3]);   // 4 9
    free(sq);
    return 0;
}
```

حين تكتب دالة تحجز ذاكرة، **وثّق من يحرّرها**. هذه "الملكية" هي أهم قرار في تصميم برامج C.

## calloc و realloc

```c
int *a = calloc(5, sizeof *a);     // مثل malloc لكن يصفّر الذاكرة
```

`malloc` لا تهيّئ الذاكرة (فيها بقايا عشوائية)، و`calloc` تملؤها أصفارًا.

`realloc` تغيّر حجم كتلة محجوزة، وقد **تنقلها** لمكان جديد. وإذا فشلت تُرجع `NULL` **وتبقى الكتلة القديمة كما هي**، لذلك لا تكتب النتيجة فوق المؤشّر الأصلي مباشرة:

```c
int *a = calloc(5, sizeof *a);
if (a == NULL) return 1;

// ❌ a = realloc(a, ...);  إذا فشلت فقدت a القديمة: تسرّب
int *tmp = realloc(a, 10 * sizeof *a);
if (tmp == NULL) {
    free(a);                // القديمة ما زالت صالحة، حرّرها
    return 1;
}
a = tmp;                    // ✅ نجحت: استخدم العنوان الجديد
a[9] = 99;
printf("%d %d\n", a[0], a[9]);   // 0 99
free(a);
```

## القاعدة الذهبية

كل `malloc` أو `calloc` أو `realloc` ناجحة يقابلها `free` **واحد بالضبط**:

- **نسيان `free`** = تسرّب ذاكرة (memory leak). في برنامج قصير لا يظهر، أما في خادم يعمل أسابيع فيأكل الذاكرة حتى ينهار.
- **`free` مرّتين** للمؤشّر نفسه (double free) = سلوك غير معرّف، وثغرة أمنية معروفة.
- **الاستخدام بعد `free`** (use-after-free) = تقرأ أو تكتب في ذاكرة قد تكون أُعطيت لشيء آخر. من أخطر أنواع الثغرات.

`free(NULL)` آمنة ولا تفعل شيئًا، ولهذا نضع `NULL` في المؤشّر بعد تحريره: أي `free` ثانية بالخطأ تصبح بلا ضرر.

## اكتشاف الأخطاء: AddressSanitizer

هذه الأخطاء صامتة غالبًا: البرنامج يعمل اليوم وينهار غدًا. لا تعتمد على عينك، بل ترجم أثناء التطوير مع الفاحص:

```bash
gcc -g -fsanitize=address program.c -o program
./program
```

عند أول use-after-free أو تجاوز حدود أو double free يتوقّف البرنامج ويطبع السطر الذي حدث فيه الخطأ والسطر الذي حُجزت فيه الذاكرة، وعند الخروج يبلّغ عن أي تسرّب. على Linux يوجد أيضًا `valgrind` الذي يفحص البرنامج دون إعادة ترجمة (درس أفضل الممارسات).

## أخطاء شائعة

- **عدم فحص `NULL`** بعد `malloc`: انهيار عند أول استخدام إذا فشل الحجز.
- **`malloc(n)` بدل `malloc(n * sizeof *a)`:** تحجز `n` بايت لا `n` عددًا.
- **`a = realloc(a, ...)` مباشرة:** تسرّب إذا فشلت.
- **تحرير مؤشّر لم يأتِ من `malloc`** (مصفوفة محلّية أو عنوان في منتصف كتلة): سلوك غير معرّف.
- **نسيان أن `sizeof` على مؤشّر لا يعطي حجم الكتلة:** احتفظ بالحجم في متغيّر بنفسك.
