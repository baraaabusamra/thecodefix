## لماذا الهياكل؟

تخيّل برنامجًا لإدارة طلاب: لكل طالب اسم وعمر ومعدّل. بدون هياكل تحتاج ثلاث مصفوفات منفصلة (`names` و`ages` و`gpas`) وتحرص يدويًا أن يبقى العنصر رقم 5 في الثلاث لنفس الطالب. الهيكل يجمع البيانات المترابطة في **نوع جديد واحد**، فيتحرّك الطالب ككتلة واحدة:

```c
struct Person {
    char name[50];
    int age;
};

struct Person p1;
strcpy(p1.name, "Baraa");
p1.age = 25;
printf("%s - %d\n", p1.name, p1.age);
```

`struct Person` الآن نوع مثل `int`، والنقطة `.` تصل للحقول.

## التهيئة

```c
struct Person p2 = {"Sara", 22};                 // بالترتيب
struct Person p3 = {.age = 30, .name = "Ali"};   // بأسماء الحقول (C99)
```

التهيئة **بأسماء الحقول** أوضح وأأمن: إذا أُضيف حقل جديد أو تغيّر الترتيب لاحقًا يبقى الكود صحيحًا، والحقول غير المذكورة تصبح أصفارًا.

## typedef لاسم أقصر

```c
typedef struct {
    char name[50];
    int age;
} Person;

Person p4 = {"Ali", 30};   // بلا كلمة struct
```

## مصفوفة هياكل

```c
Person team[2] = {{"A", 20}, {"B", 25}};
printf("%s\n", team[1].name);   // B
```

## الوصول عبر مؤشّر: السهم `->`

```c
Person *ptr = &p4;
printf("%d\n", ptr->age);   // نفس (*ptr).age
ptr->age = 31;              // يعدّل p4 نفسه
```

## تمرير هيكل لدالة

الهيكل يُمرَّر **بالقيمة** كأي متغيّر: الدالة تستلم **نسخة كاملة**. هذا يعني أمرين:

1. تعديل النسخة لا يغيّر الأصل.
2. مع هيكل كبير، النسخ يكلّف وقتًا وذاكرة في كل استدعاء.

لذلك المعتاد تمرير **مؤشّر**: `const` للقراءة فقط، وبدونها للتعديل:

```c
typedef struct {
    char name[50];
    double grades[10];
    int count;
} Student;

double average(const Student *s) {        // قراءة فقط، بلا نسخ
    double sum = 0;
    for (int i = 0; i < s->count; i++) sum += s->grades[i];
    return s->count ? sum / s->count : 0;
}

void add_grade(Student *s, double g) {    // يعدّل الأصل
    if (s->count < 10) s->grades[s->count++] = g;
}

int main(void) {
    Student s = {.name = "Lina"};
    add_grade(&s, 90);
    add_grade(&s, 80);
    printf("%s: %.1f\n", s.name, average(&s));   // Lina: 85.0
    return 0;
}
```

## النسخ سطحي

إسناد هيكل لآخر (`b = a;`) ينسخ كل الحقول بايتًا بايتًا. المصفوفات **داخل** الهيكل تُنسخ فعلًا، لكن المؤشّرات تُنسخ **كعناوين**: يصبح الهيكلان يشيران للذاكرة نفسها:

```c
typedef struct { char *tag; } Item;

char buf[] = "old";
Item a = {buf};
Item b = a;          // b.tag يشير لنفس buf
b.tag[0] = 'N';
printf("%s\n", a.tag);   // Nld: تغيّر a أيضًا
```

إذا كان الهيكل يملك ذاكرة محجوزة بـ `malloc`، فالنسخ ثم `free` على النسختين = double free. اكتب دالة نسخ خاصة تحجز ذاكرة جديدة.

## الحجم ليس مجموع الحقول: الحشو

المعالج يقرأ البيانات أسرع حين تبدأ في عناوين "محاذية" (مثلًا `int` على مضاعفات 4)، فيضيف المترجم بايتات فارغة بين الحقول (padding):

```c
struct A { char c; int i; char d; };   // غالبًا 12 بايت لا 6
struct B { int i; char c; char d; };   // غالبًا 8 بايت
printf("%zu %zu\n", sizeof(struct A), sizeof(struct B));
```

ترتيب الحقول من الأكبر للأصغر يقلّل الحشو، وهذا يهمّ مع ملايين العناصر. ولا تكتب هيكلًا كما هو في ملف أو عبر الشبكة متوقّعًا نفس الحجم على كل جهاز؛ الحشو يختلف بين الأنظمة.

## أخطاء شائعة

- **مقارنة هيكلين بـ `==`:** خطأ ترجمة. قارن الحقول واحدًا واحدًا (`memcmp` غير آمنة بسبب بايتات الحشو).
- **`.` مع مؤشّر أو `->` مع هيكل:** `ptr.age` و`p.age` خطأ. السهم للمؤشّرات، والنقطة للهيكل نفسه.
- **تمرير هيكل كبير بالقيمة** في حلقة ساخنة: مرّر `const T *`.
- **إسناد نص لحقل مصفوفة:** `p.name = "Ali";` خطأ؛ استخدم `snprintf(p.name, sizeof p.name, "%s", "Ali")`.
- **نسيان الفاصلة المنقوطة بعد `}`** في تعريف الهيكل: رسالة خطأ مربكة في السطر التالي.
