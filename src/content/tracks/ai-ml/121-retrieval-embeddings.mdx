بعد [درس 82: Embeddings في NLP](/learn/ai-ml/82-nlp-embeddings) و[درس 120: RAG Overview](/learn/ai-ml/120-rag-overview)، نركّز على embeddings **خصيصًا لمهام الاسترجاع**. ليست نفس فكرة "أي embedding يمثّل النصّ" — الاسترجاع له متطلبات مختلفة.

## ما يميّز retrieval embeddings؟

في [درس 82](/learn/ai-ml/82-nlp-embeddings) تعلّمنا أن embedding هو **متجه رقمي** يقيس التشابه الدلالي. للاسترجاع:

```text
نحتاج أن نقيس:
  - "هل هذا المستند يجيب عن هذا السؤال؟"

وليس فقط:
  - "هل هاتان العبارتان تقولان الشيء نفسه؟"
```

هذا فرق دقيق لكنه مهم. نماذج retrieval المتخصّصة تُدرَّب خصيصًا على (سؤال، مستند ذو صلة) بدلًا من (جملة، جملة مشابهة).

## Bi-encoder و Asymmetric Retrieval

النمط الشائع لاسترجاع embedding يُسمّى **bi-encoder**:

```text
Query   →  embed_query(q)   →  vec_q
Doc    →  embed_doc(d)     →  vec_d

similarity(q, d) = cosine(vec_q, vec_d)
```

- **embed_query**: يمثّل السؤال.
- **embed_doc**: يمثّل المستند.

قد يستخدم النموذج **preprocessing مختلف** لكل جانب (prompt مختلف) لجعل المتجهات أكثر تميّزًا. هذا يُسمّى **asymmetric retrieval**.

## كيف يعمل Asymmetric Retrieval

ليست كل النماذج تفرّق بين الجانبين. عندما يدعم النموذج ذلك، يصرّح عن prompts مختلفة لكل دور:

```python
from sentence_transformers import SentenceTransformer

# Bi-encoder لاسترجاع غير متماثل (تحقّق من بطاقة النموذج على HuggingFace
# لمعرفة الـ API الصحيح للطراز الذي تستخدمه).
model = SentenceTransformer("intfloat/multilingual-e5-small")

# نماذج e5 تتطلّب بادئات نصّية حرفيّة "query: " و "passage: " — هذه البادئات
# جزء من بطاقة النموذج (model card). نضيفها نحن صراحة هنا ولا نعتمد على
# encode_query / encode_document لإضافتها تلقائيًا لهذا الطراز.
documents = ["passage: التعلّم العميق فرع من تعلّم الآلة يستخدم شبكات عصبية عميقة."]
query     = "query: ما هو التعلّم العميق؟"

doc_vec   = model.encode_document(documents, normalize_embeddings=True)
query_vec = model.encode_query(query, normalize_embeddings=True)

# التشابه
similarity = model.similarity(query_vec, doc_vec)
```

> **ملاحظة دقيقة عن الـ API**: في مكتبة `sentence-transformers` الحالية (v3+) `SentenceTransformer` يعرض `model.encode_query(...)` و`model.encode_document(...)` كطرق موصى بها للاسترجاع غير المتماثل. هذه الطرق تقرأ prompts أو routing معرَّفة في إعدادات النموذج عند توفّرها — لكنها ليست متّفقًا عالميًا لإضافة بادئات نصّية لطرازات retrieval كلها.
>
> - `intfloat/multilingual-e5-small`: يتطلّب بادئات حرفيّة `"query: "` و `"passage: "` في النصّ نفسه (لا يُضاف داخليًا). أضفها أنت.
> - طرازات ColBERT-style (`ColBERT`، `ColPali`) أو `MultiVectorEncoder`: صيغ مختلفة تمامًا (multi-vector).
> - طرازات أحدث (مثل بعض إصدارات BGE) قد تعرّف prompts داخل النموذج فيُطبَّق تلقائيًا.
>
> **القاعدة العملية**: اقرأ قسم "usage" في بطاقة أي نموذج retrieval قبل أن تكتب كودًا يفترض صيغة معيّنة. لا تفترض أن `encode_query` تضيف `"query: "` لك.

## لماذا prompts مختلفة؟

```text
المستندات: نصّ طويل، كامل، وصفي.
الأسئلة:  قصيرة، محدّدة، قد تحتوي كلمات استفهام.

إذا استخدمنا نفس الـ prompt للجانبين، النموذج
قد يُنتج متجهات "متوسطة" لا تُميّز بين سؤال ومستند.
```

## تشابه الاسترجاع (Cosine Similarity)

في retrieval، التشابه القياسي هو **cosine** بين المتجهات. راجع [درس 82](/learn/ai-ml/82-nlp-embeddings) للصيغة.

```python
from sentence_transformers import SentenceTransformer, util

model = SentenceTransformer("intfloat/multilingual-e5-small")

# Bilingual-e5 يتطلّب بادئات نصّية حرفيّة — نضيفها صراحة.
q = model.encode_query("query: ما هو RAG؟", normalize_embeddings=True)
d = model.encode_document(
    "passage: RAG retrieval-augmented generation يحسّن إجابات LLM.",
    normalize_embeddings=True,
)

# الطريقة المفضّلة حاليًا
score = model.similarity(q, d)
# tensor([[0.88]])

# الطريقة القديمة (لا تزال تعمل)
score2 = util.cos_sim(q, d)
```

### تطبيع المتجهات

```python
# normalized_embeddings: بضرب كل متجه في ثابت يجعل طوله = 1
# عندها cosine similarity = dot product
emb = model.encode(sentences, normalize_embeddings=True)
```

**لماذا نطبّع؟**

```text
- يبسّط المقارنة (cosine = dot product).
- يحسّن الأداء في بعض قواعد المتجهات.
- لكن: ليس دائمًا ضروريًا. جرّب بدون تطبيع أولًا.
```

## أبعاد المتجه (Embedding Dimensions)

كل نموذج embedding له **بُعد ثابت** يُحدَّد عند التدريب:

```text
all-MiniLM-L6-v2            →  384 بُعد
multilingual-e5-small       →  384 بُعد
multilingual-e5-base        →  768 بُعد
bge-m3                      →  1024 بُعد
text-embedding-3-small      →  1536 بُعد (OpenAI)
```

**قاعدة صارمة**: يجب أن يكون بُعد عمود الـ vector store = بُعد النموذج بالضبط.

## قاعدة الاتساق

```text
✅ نموذج واحد لكل شيء:
  - الـ index يحوي متجهات من نموذج X.
  - الاستعلام يُولَّد بنفس النموذج X.
  - المقارنة صحيحة.

❌ خلط النماذج:
  - الـ index يحوي متجهات من نموذج X.
  - الاستعلام من نموذج Y.
  - المتجهات في فضاءين مختلفين. المقارنة لا معنى لها.
```

> **تحذير**: إذا غيّرت النموذج لاحقًا، **يجب إعادة embedding لكل المستندات المخزّنة**. لا تحاول المقارنة بين متجهات نموذجين مختلفين.

## استرجاع عملي بـ NumPy

بدون قاعدة بيانات، يمكنك استرجاع المستندات الأكثر شبهاً بـ NumPy فقط:

```python
import numpy as np
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("intfloat/multilingual-e5-small")

documents = [
    "RAG يحسّن دقة LLM.",
    "PostgreSQL قاعدة بيانات علائقية.",
    "البحث الدلالي يعتمد على التشابه بين المتجهات.",
]

# نُضيف بادئات e5 الحرفيّة صراحةً قبل تمرير النصّ إلى encode_document —
# multilingual-e5-small يتطلّبها في النصّ نفسه حسب بطاقة النموذج.
doc_vecs = model.encode_document(
    [f"passage: {d}" for d in documents],
    normalize_embeddings=True,
)

def top_k(query: str, doc_vecs: np.ndarray, docs: list[str], k: int = 3):
    # نفس القاعدة: نضيف "query: " صراحةً، وليس تلقائيًا.
    q_vec = model.encode_query(f"query: {query}", normalize_embeddings=True)
    # cosine = dot product عند normalized
    scores = doc_vecs @ q_vec
    idx = np.argsort(-scores)[:k]
    return [(docs[i], float(scores[i])) for i in idx]

for text, score in top_k("كيف يجد النظام فقرات مشابهة للسؤال؟", doc_vecs, documents):
    print(f"{score:.3f}  {text}")
```

## متى تختار نموذج retrieval معيّن؟

```text
⚠️ لا يوجد نموذج "أفضل عالميًا".
الاختيار يعتمد على:

- اللغة (بعض النماذج أحادي اللغة).
- طول النصّ (نماذج تدعم 512 token، نماذج أحدث تدعم 8k+).
- متطلبات السرعة/الذاكرة.
- متطلبات الدقة في مجالك.
```

> لا تثق في "أفضل نموذج لاسترجاع" بدون اختبار على بياناتك.

## أخطاء شائعة

- **"embedding يحلّ كل شيء"**: لا. retrieval embeddings مخصّصة للاسترجاع. مهام أخرى تحتاج نماذج أخرى.
- **"خلط النماذج آمن"**: لا. متجهات من نموذجين مختلفين = فضاءان مختلفان.
- **"cosine > 0.8 = ذات صلة"**: لا توجد عتبة عالمية. يعتمد على النموذج والمهمة.
- **"أكبر بُعد = أفضل"**: لا. بُعد كبير مع بيانات قليلة → overfitting وبطء.
- **"تطبيع دائمًا أفضل"**: يعتمد على النموذج والـ distance operator المستخدم.
