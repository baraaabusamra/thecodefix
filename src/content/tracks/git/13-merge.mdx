## الدمج الأساسي

ادمج فرع ميزة في `main`:

```bash
git switch main
git merge feature-login
```

## fast-forward

إذا لم يتغيّر `main` منذ إنشاء الفرع، يحرّك Git المؤشّر للأمام فقط بلا commit دمج إضافي.

## commit الدمج

إذا تقدّم الفرعان معًا، ينشئ Git **commit دمج** يجمع التاريخين، وتظهر رسالة مثل:

```text
Merge made by the 'ort' strategy.
```

```bash
git merge --no-ff feature-login   # أنشئ commit دمج دائمًا
```

`--no-ff` يحافظ على commit دمج حتى لو كان fast-forward ممكنًا، فيبقى واضحًا في السجلّ أن هذه التغييرات جاءت من فرع ميزة منفصل.

## إذا ظهر تعارض

لو عدّل الفرعان نفس الأسطر، يتوقّف الدمج ويطلب منك الحلّ (الدرس القادم). وقتها:

```bash
git status          # يسرد الملفات التي فيها تعارض
git merge --abort   # أو: ألغِ الدمج وارجع للحالة قبل البدء
```

## merge أم rebase؟

`merge` لا يعدّل أي commit موجود، يضيف فقط commit دمج جديد. لذلك هو الآمن على الفروع التي رفعتها ويعمل عليها غيرك. أمّا `rebase` فيعيد كتابة الـ commits (درس لاحق).

## بعد الدمج

```bash
git branch -d feature-login   # احذف الفرع المدموج
```

## أخطاء شائعة

- الدمج وأنت على الفرع الخطأ — تأكّد أنك على الفرع **المستقبِل** (`main`) قبل `git merge`.
- تجاهل التعارض والمتابعة كأن شيئًا لم يكن، فتبقى علامات مثل `<<<<<<<` و`>>>>>>>` داخل الكود ويتعطّل البرنامج.
