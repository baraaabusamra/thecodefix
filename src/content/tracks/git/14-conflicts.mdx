## التعارض ليس خطأ

يدمج Git معظم التغييرات تلقائيًّا: أنت عدّلت أول الملف وزميلك آخره، فيأخذ الاثنين. يتوقّف فقط حين **يعدّل الفرعان نفس الأسطر** بطريقتين مختلفتين، لأن الاختيار هنا قرار يخصّ معنى الكود، لا شيئًا يستطيع برنامج تخمينه. التعارض يعني "Git يسألك"، لا أن شيئًا انكسر.

## مثال كامل

على `main` رفعت السعر إلى 15، وزميلك على `feature` رفعه إلى 12، من نفس الأصل `price = 10`:

```bash
git switch main
git merge feature
```

```text
Auto-merging config.txt
CONFLICT (content): Merge conflict in config.txt
Automatic merge failed; fix conflicts and then commit the result.
```

الدمج **توقّف في المنتصف**. ما دُمج تلقائيًّا جاهز، وما تعارض ينتظرك.

### الخطوة 1: اعرف ما المتعارض

```bash
git status
```

```text
On branch main
You have unmerged paths.
  (fix conflicts and run "git commit")
  (use "git merge --abort" to abort the merge)

Unmerged paths:
  (use "git add <file>..." to mark resolution)
	both modified:   config.txt
```

`both modified` تعني أن الطرفين عدّلا الملف. مع ملفات كثيرة، هذه قائمة عملك.

### الخطوة 2: اقرأ العلامات

```text
title = "متجر"
<<<<<<< HEAD
price = 15
=======
price = 12
>>>>>>> feature
```

| الجزء | المعنى |
| --- | --- |
| من `<<<<<<< HEAD` إلى `=======` | نسختك: الفرع الذي تقف عليه (`main`) |
| من `=======` إلى `>>>>>>> feature` | النسخة القادمة من الفرع الذي تدمجه |
| ما خارج العلامات | دُمج بلا مشاكل (`title`) |

### الخطوة 3: قرّر واكتب النتيجة

افتح الملف واكتبه **كما يجب أن يكون**، واحذف العلامات الثلاث كلها:

```text
title = "متجر"
price = 15
```

الخيارات ثلاثة: نسختك، أو نسختهم، أو **مزيج** يجمع الاثنين، وهو الشائع في الكود الحقيقي (أنت أضفت حقلًا وزميلك أضاف آخر، فتبقي الحقلين). إن لم تعرف لماذا غيّر زميلك السطر، اسأله قبل أن تحذف عمله.

### الخطوة 4: علّم الحلّ وأكمل

```bash
git add config.txt          # "حللت هذا الملف"
git commit                  # يكمل الدمج برسالة جاهزة
```

`git add` هنا لا تعني "جهّز تعديلًا جديدًا" بل "انتهى تعارض هذا الملف". وحين لا يبقى ملف في `Unmerged paths`، يُنشئ `git commit` commit الدمج.

## اعرف الأصل: zdiff3

العلامات الافتراضية تعرض الطرفين فقط. هل كان الأصل 10، وأحدكما غيّره والآخر أيضًا؟ أم أن أحدكما لم يلمسه؟ هذا الإعداد يضيف الأصل المشترك:

```bash
git config --global merge.conflictStyle zdiff3
```

```text
<<<<<<< HEAD
price = 15
||||||| cfc5498
price = 10
=======
price = 12
>>>>>>> feature
```

بين `|||||||` و`=======` ما كان عليه السطر قبل أن يتفرّع الطرفان. رؤية الأصل تجعل نيّة كل تغيير واضحة، والقرار أسهل بكثير. (`zdiff3` متاحة منذ Git 2.35؛ في الإصدارات الأقدم استخدم `diff3`.)

## اختيار ملف كامل

حين تعرف أن نسخة واحدة صحيحة للملف كله (ملف مولَّد، أو صورة):

```bash
git checkout --ours config.txt      # نسختي كما هي
git checkout --theirs config.txt    # نسختهم كما هي
git add config.txt
```

> ⚠️ أثناء **`rebase`** ينعكس المعنى: `--ours` هو الفرع الذي تعيد البناء **فوقه** (`main`)، و`--theirs` هو commits فرعك أنت. السبب أن rebase يعيد تطبيق commits فرعك واحدًا تلو الآخر فوق الآخر ([درس rebase](/learn/git/17-rebase)). تحقّق من المحتوى بعد الأمر دائمًا.

## التراجع عن الدمج كله

```bash
git merge --abort
```

يعيد كل شيء كما كان قبل `git merge`، كأنك لم تبدأ. مفيد حين يتّضح أن التعارضات أكبر من أن تحلّها الآن، أو أنك دمجت الفرع الخطأ. وفي rebase: `git rebase --abort`، وفي cherry-pick: `git cherry-pick --abort`.

## لا تنسَ علامة

علامة `<<<<<<<` منسيّة في ملف JavaScript تكسر البناء، وفي ملف إعدادات قد لا تُكتشف حتى الإنتاج. قبل `git commit`:

```bash
git diff --cached --check
```

```text
config.txt:1: leftover conflict marker
config.txt:3: leftover conflict marker
config.txt:5: leftover conflict marker
```

لا ناتج يعني لا علامات منسيّة.

## أدوات مساعدة

محرّرات مثل VS Code تلوّن الطرفين وتعرض فوق كل تعارض أزرار **Accept Current Change** (نسختك) و**Accept Incoming Change** (القادمة) و**Accept Both Changes**. مريحة، لكن "Accept Both" تضع السطرين تحت بعضهما حرفيًّا: `price = 15` ثم `price = 12`، وهذا نادرًا ما يكون الصحيح. اقرأ النتيجة دائمًا.

## تقليل التعارضات

- **ادمج `main` في فرعك كثيرًا** (أو rebase): عشرة تعارضات صغيرة كل يوم أسهل من مئة في آخر الأسبوع.
- **فروع قصيرة العمر وPull Requests صغيرة.**
- **لا تخلط إعادة التنسيق بالتغييرات:** تشغيل أداة تنسيق على ملف كامل في نفس فرع ميزة يجعل كل سطر "متغيّرًا" ويتعارض مع أي شخص آخر. نسّق في commit أو PR مستقل.
- **تواصل:** إن كنت ستعيد هيكلة ملف يعمل عليه زميلك، أخبره.

## أخطاء شائعة

- **commit مع علامات منسيّة:** افحص بـ `git diff --cached --check`.
- **حذف كود زميلك لتختفي العلامات:** اختر النتيجة الصحيحة، لا الأسرع.
- **"Accept Both" بلا مراجعة:** سطران متناقضان في الملف.
- **`--ours`/`--theirs` بنفس المعنى في rebase:** معكوسان.
- **الذعر:** `git merge --abort` يعيدك لنقطة البداية دائمًا.
