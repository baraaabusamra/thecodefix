## الموقف

أنت في منتصف نموذج تسجيل الدخول على فرع `feature/login`، والكود لا يعمل بعد. يصلك: "الموقع معطّل، أصلحه الآن". تحتاج الانتقال إلى `main` فورًا، لكن:

- commit لكود مكسور يلوّث التاريخ برسالة مثل "WIP".
- `git switch main` قد يرفض لأن تعديلاتك تتعارض ([درس الفروع](/learn/git/02-branches))، أو ينقلها معك إلى `main`، وهذا أسوأ.

**`git stash`** يأخذ تعديلاتك غير المحفوظة، يضعها جانبًا في "رفّ" خاص، ويعيد مجلّد العمل نظيفًا كآخر commit.

## الدورة الأساسية

```bash
git stash push -m "login form half done"
```

```text
Saved working directory and index state On main: login form half done
```

```bash
git switch main
# ... أصلح الخطأ، commit، push ...
git switch feature/login
git stash pop                    # أعد تعديلاتك وأزلها من الرفّ
```

`-m` اختيارية، لكن بعد ثلاثة مخبّآت بلا وصف لن تعرف أيّها ماذا. (`git stash save "..."` صيغة قديمة مهجورة (deprecated) لصالح `push -m`.)

## ما الذي يُخبَّأ؟

افتراضيًّا: التعديلات على الملفات **المتتبَّعة**، المجهّزة وغير المجهّزة. أما **الملفات الجديدة** (`??`) فتبقى في مكانها:

```bash
git stash push -m "only tracked"
git status -s
# ?? draft.txt         ← لم يُخبَّأ!
```

لتشملها:

```bash
git stash push -u -m "with new files"     # -u = include untracked
```

نسيان `-u` هو أشهر مفاجآت stash: تنتقل لفرع آخر والملف الجديد ما زال معك.

## عدّة مخبّآت

الرفّ كومة: الأحدث في الأعلى برقم `0`.

```bash
git stash list
```

```text
stash@{0}: On main: with new files
stash@{1}: On main: login form half done
```

```bash
git stash show stash@{1}          # أي ملفات فيه
git stash show -p stash@{1}       # التغييرات كاملة
git stash apply stash@{1}         # طبّق مخبّأً محدّدًا
```

## pop أم apply؟

| | `pop` | `apply` |
| --- | --- | --- |
| يطبّق التعديلات | نعم | نعم |
| يحذفها من الرفّ | نعم، إن نجح التطبيق | لا |
| متى | الاستخدام العادي | تريد تطبيق نفس التعديلات على أكثر من فرع، أو لست متأكّدًا |

إن حدث **تعارض** أثناء `pop` (عدّلت نفس الأسطر بعد التخبئة)، يبقى المخبّأ في الرفّ ولا يُحذف. حلّ التعارض كأي دمج ([درس التعارضات](/learn/git/14-conflicts))، ثم احذفه يدويًّا بـ `git stash drop`.

## تخبئة جزء فقط

```bash
git stash push -m "only css" styles.css     # ملف محدّد
git stash push -p                           # اختر الأجزاء قطعة قطعة
```

مفيد حين تريد اختبار جزء من تعديلاتك وحده: خبّئ الباقي، اختبر، ثم أعده.

## من مخبّأ إلى فرع

```bash
git stash branch feature/experiment stash@{0}
```

ينشئ فرعًا جديدًا من الـ commit الذي كنت عليه **لحظة التخبئة**، ويطبّق المخبّأ فيه، ثم يحذفه من الرفّ. هذا هو الحل حين يتعارض `pop` لأن الفرع تقدّم كثيرًا، أو حين تكتشف أن "التعديل المؤقّت" صار عملًا حقيقيًّا يستحق فرعًا.

## التنظيف

```bash
git stash drop stash@{1}      # احذف مخبّأً واحدًا
git stash clear               # احذف الكل (لا تراجع بسهولة)
```

## stash ليس مكان تخزين

المخبّآت **محلية**: لا تُرفع مع `git push`، ولا يراها زملاؤك، وتضيع إن ضاع جهازك. ومع الوقت يتراكم `stash@{7}` لا يذكر أحد ما فيه. القاعدة: stash لدقائق أو ساعات. لأي شيء أطول، commit على فرع مؤقّت (يمكنك دائمًا تعديله لاحقًا بـ `--amend` أو [rebase التفاعلي](/learn/git/29-interactive-rebase)).

## أخطاء شائعة

- **نسيان `-u`:** الملفات الجديدة لا تُخبَّأ وتتبعك للفرع الآخر.
- **مخبّآت بلا وصف:** `stash@{4}` لا يقول شيئًا. استخدم `-m`.
- **`pop` على فرع خاطئ:** تُطبَّق التعديلات حيث أنت. تأكّد من `git branch` أولًا.
- **تراكم المخبّآت لأسابيع:** حوّلها إلى فروع أو احذفها.
- **`git stash clear` بلا مراجعة:** راجع `git stash list` أولًا.
