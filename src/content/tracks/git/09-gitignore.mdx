## ما الذي لا يدخل Git؟

ليس كل ما في مجلّد المشروع جزءًا من المشروع:

| النوع | أمثلة | لماذا لا يُرفع |
| --- | --- | --- |
| الاعتماديات | `node_modules/`، `vendor/`، `.venv/` | ضخمة، ويعيد أي شخص تثبيتها بأمر واحد من `package.json` |
| مخرجات البناء | `dist/`، `build/`، `*.class` | تُولَّد من الكود، ونسخها يسبّب تعارضات بلا معنى |
| الأسرار | `.env`، `*.pem`، `credentials.json` | كلمات مرور ومفاتيح: رفعها حادثة أمنية |
| ملفات النظام والمحرّر | `.DS_Store`، `Thumbs.db`، `.idea/` | تخصّ جهازك لا المشروع |
| السجلّات والمؤقّت | `*.log`، `tmp/` | تتغيّر باستمرار ولا قيمة لها في التاريخ |

ملف **`.gitignore`** في جذر المشروع يخبر Git أن يتصرّف كأن هذه الملفات غير موجودة: لا تظهر في `git status`، ولا يضيفها `git add .`.

## مثال لمشروع ويب

```text
# الاعتماديات
node_modules/

# الأسرار ومتغيّرات البيئة
.env
.env.*
!.env.example

# البناء
dist/
build/

# السجلّات
*.log

# النظام والمحرّر
.DS_Store
.vscode/
```

`.env.example` نسخة من ملف البيئة **بلا قيم حقيقية** (`DATABASE_URL=`)، تُرفع ليعرف زملاؤك أي متغيّرات يحتاجها المشروع. السطر `!.env.example` يستثنيها من قاعدة `.env.*`.

لا تبدأ من الصفر: مستودع [github/gitignore](https://github.com/github/gitignore) فيه قوالب جاهزة لكل لغة وإطار تقريبًا، وGitHub يعرض اختيار أحدها عند إنشاء مستودع جديد.

## قواعد الأنماط

| النمط | يتجاهل |
| --- | --- |
| `*.log` | كل ملف ينتهي بـ `.log` في أي مجلّد |
| `build/` | أي **مجلّد** اسمه `build` في أي مستوى |
| `/build` | `build` في **الجذر فقط**، لا `src/build` |
| `**/temp` | `temp` في أي عمق: `temp` و`docs/temp` و`a/b/temp` |
| `doc/*.txt` | ملفات `txt` مباشرة داخل `doc/` فقط |
| `!keep.log` | استثناء: لا تتجاهل هذا الملف رغم قاعدة سابقة |
| `# نص` | تعليق |

وتُقرأ القواعد من الأعلى للأسفل، والأخيرة المطابقة تفوز. لهذا يأتي الاستثناء `!` **بعد** القاعدة التي يستثني منها.

### فخّ الاستثناء داخل مجلّد متجاهَل

```text
logs/
!logs/keep.log      ← لا يعمل!
```

حين يُتجاهَل **المجلّد** كله، لا يدخله Git أصلًا ليرى ما بداخله، فلا يمكن استثناء ملف منه. الحل أن تتجاهل **المحتوى** لا المجلّد:

```text
logs/*
!logs/keep.log
```

## ما سبب تجاهل هذا الملف؟

حين لا يظهر ملف في `git status` ولا تعرف لماذا:

```bash
git check-ignore -v debug.log
```

```text
.gitignore:2:*.log	debug.log
```

الملف، ورقم السطر، والقاعدة المسؤولة. مفيد جدًّا مع `.gitignore` طويل أو ملفات متعدّدة.

## أماكن أخرى للتجاهل

- **`.gitignore` داخل مجلّد فرعي:** قواعده تنطبق على ذلك المجلّد وما تحته.
- **ملف تجاهل عام لجهازك** لملفات نظامك ومحرّرك، فلا تضيف `.DS_Store` و`.idea/` لكل مشروع:

```bash
git config --global core.excludesFile ~/.gitignore_global
echo ".DS_Store" >> ~/.gitignore_global
```

- **`.git/info/exclude`:** نفس الصيغة، لهذا المستودع وعلى جهازك فقط، ولا يُرفع. لملف تجريبي شخصي لا يهمّ الفريق.

## ملف متتبَّع بالفعل

`.gitignore` يمنع الملفات **غير المتتبَّعة** فقط. ملف أضفته سابقًا يستمر Git في تتبّعه حتى لو كتبت اسمه في `.gitignore` بعدها. لإخراجه من التتبّع مع إبقائه على جهازك:

```bash
echo "config.local.json" >> .gitignore
git rm --cached config.local.json
git commit -m "Stop tracking local config"
```

`--cached` تعني "احذفه من Git لا من القرص". ولمجلّد: `git rm -r --cached node_modules`.

## سرّ وصل إلى المستودع؟

إذا رفعت `.env` فيه مفتاح حقيقي، فإن `git rm --cached` وcommit جديد **لا يكفيان**: الملف ما زال في الـ commits السابقة، وأي شخص نسخ المستودع يملكه، وروبوتات تمسح GitHub بحثًا عن المفاتيح خلال دقائق من الرفع. بالترتيب:

1. **ألغِ المفتاح فورًا** (Revoke / Rotate) من لوحة الخدمة، وأنشئ واحدًا جديدًا. هذه الخطوة الوحيدة التي تحميك فعلًا.
2. أخرج الملف من التتبّع وأضفه لـ `.gitignore`.
3. إن كان لا بد من حذفه من التاريخ نفسه، فأدوات مثل `git filter-repo` تعيد كتابة التاريخ، وهذا يتطلّب تنسيقًا مع كل من نسخ المستودع.

## مجلّد فارغ لا يظهر

Git يتتبّع الملفات لا المجلّدات، فالمجلّد الفارغ لا يُرفع. العُرف أن تضع داخله ملفًا فارغًا اسمه `.gitkeep`. الاسم مجرّد اتفاق، لا ميزة في Git.

## أخطاء شائعة

- **إضافة الملف لـ `.gitignore` بعد تتبّعه وانتظار اختفائه:** استخدم `git rm --cached`.
- **`!` داخل مجلّد متجاهَل:** تجاهل `logs/*` لا `logs/`.
- **`/build` وأنت تقصد كل مجلّدات `build`:** الشرطة في البداية تعني الجذر فقط.
- **رفع `.env` ثم حذفه فقط:** المفتاح مكشوف في التاريخ. ألغِه.
- **تجاهل `package-lock.json` أو `poetry.lock`:** هذه **يجب** أن تُرفع؛ تضمن أن الجميع يثبّت نفس الإصدارات.
