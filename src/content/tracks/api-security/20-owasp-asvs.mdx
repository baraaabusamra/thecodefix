## ما هو OWASP ASVS؟

ASVS (Application Security Verification Standard) هو معيار من OWASP يحدد متطلبات أمان التطبيقات ومستويات الضمان المختلفة. يساعد الفرق على بناء تطبيقات آمنة وتقييم مستوى الأمان الحالي.

> 💡 هذا الدرس يشرح **النسخة 5.0** — النسخة الحالية للمعيار، صدرت رسميًا في 30 مايو 2025 بمؤتمر OWASP Global AppSec EU في برشلونة، وهي أول تحديث جوهري منذ نسخة 4.0 (2019) ونسختها الفرعية 4.0.3 (2021). التحديث لم يكن مجرد ترقيم جديد — أعاد OWASP هيكلة الفصول بالكامل.

```text
هيكل ASVS 5.0 (17 فصلاً، بعد أن كانت 14 بنسخة 4.0):
  - V1: Encoding and Sanitization (الترميز والتعقيم)
  - V2: Validation and Business Logic (التحقق ومنطق الأعمال)
  - V3: Web Frontend Security (أمن واجهة الويب الأمامية)
  - V4: API and Web Service (واجهات API وخدمات الويب)
  - V5: File Handling (التعامل مع الملفات)
  - V6: Authentication (المصادقة)
  - V7: Session Management (إدارة الجلسات)
  - V8: Authorization (الصلاحيات)
  - V9: Self-contained Tokens (الرموز ذاتية الاحتواء — JWT وشبيهاتها)
  - V10: OAuth and OIDC (فصل مستقل جديد بالكامل)
  - V11: Cryptography (التشفير)
  - V12: Secure Communication (الاتصال الآمن)
  - V13: Configuration (الإعدادات)
  - V14: Data Protection (حماية البيانات)
  - V15: Secure Coding and Architecture (البرمجة الآمنة والمعمارية)
  - V16: Security Logging and Error Handling (التسجيل ومعالجة الأخطاء)
  - V17: WebRTC (فصل جديد بالكامل — اتصالات الصوت/الفيديو المباشرة)
```

أبرز ما تغيّر: فصلا **OAuth and OIDC** و**WebRTC** لم يكن لهما وجود مستقل في نسخة 4.0 (كانا إما غائبين أو مبعثرين ضمن فصول أعم)، و**Self-contained Tokens** أُفرد لأول مرة كفصل قائم بذاته بدل أن يكون بندًا فرعيًا ضمن المصادقة. مستويات الضمان الثلاثة (L1/L2/L3) لم تتغيّر كمفهوم — لا تزال تراكمية كما بالأسفل — لكن أرقام المتطلبات الفردية أُعيد توزيعها على الفصول الجديدة، فأي مرجع قديم لرقم متطلب بصيغة 4.0 (مثل 2.1.1) لا يقابله بالضرورة نفس الرقم بنسخة 5.0.

## مستويات الضمان

| المستوى | الوصف | لمن؟ |
|---------|-------|------|
| **L1** | أساسي (Automated) | كل التطبيقات - ثغرات يمكن اكتشافها تلقائياً |
| **L2** | قياسي (Manual) | تطبيقات تتعامل مع بيانات حساسة - يحتاج مراجعة يدوية |
| **L3** | متقدم (In-Depth) | تطبيقات عالية الخطورة (بنوك، صحة، أمن وطني) |

> ⚠️ أرقام المتطلبات بالأمثلة التالية من نسخة **5.0** فعليًا (لا 4.0) — لاحظ كيف اختلفت أرقام الفصول عن أي مثال قديم رأيته لهذا المعيار قبل صدور 5.0.

```javascript
  },

    "2.2.2": "التحقق يحدث بطبقة خدمة موثوقة (server-side) لا بالعميل فقط"
  },
  "V7_Session_Management": {
    "7.2.3": "معرّف الجلسة عشوائي تشفيريًا بـ128 بت entropy كحد أدنى",
    "7.4.1": "إبطال الجلسة فعليًا بعد logout أو انتهاء الصلاحية"
  },
  "V8_Authorization": {
    "8.2.1": "الوصول على مستوى الوظيفة مقيّد بصلاحيات صريحة",

```

> 💡 لاحظ أن حماية BOLA (8.2.2) صارت بنسخة 5.0 **متطلب مستوى L1 الأساسي** — لم تعد تنتظر مستوى L2 كما كانت ضمنيًا بنسخة 4.0. هذا يعكس كونها أشهر ثغرة API فعليًا (راجع [درس BOLA بالمرجع](/reference/api-security/bola)).

### المستوى 2 (L2) - قياسي

```javascript
// متطلبات إضافية - L2 (كل L1 + L2، ASVS 5.0)
{
  "V8_Authorization": {
    "8.1.2": "توثيق قيود الوصول على مستوى الحقل (قراءة/كتابة)",
    "8.2.3": "منع قراءة/تعديل حقول لا يملك المستخدم صلاحية عليها (BOPLA)",
    "8.4.1": "عزل بيانات كل مستأجر (tenant) بتطبيقات Multi-tenant"
  }

```

> 💡 بحكم عمومي (لا رقم متطلب دقيق محدد هنا لتجنّب الاجتهاد): MFA للحسابات الحساسة وتخزين كلمات المرور عبر bcrypt/argon2 لا يزالان ضمن توصيات فصل V6 (Authentication) بنسخة 5.0 — راجع [الفرق بين ASVS 4.0 و5.0](/blog/owasp-asvs-4-vs-5) لو تحتاج تفاصيل انتقال دقيقة لبند بعينه.

```javascript
  ]
}
```

## تطبيق ASVS في التطوير

### مرحلة التخطيط

```javascript
// اختيار المستوى المناسب
function determineAsvsLevel(application) {
  const { dataType, users, impact } = application;

  if (impact === 'critical') return 'L3'; // بنوك، صحة
  if (dataType.includes('personal') || users > 100000) return 'L2';
  return 'L1'; // مواقع بسيطة
}

// متطلبات ASVS في ملف Requirements
const asvsRequirements = {
  L1: ['V2-1', 'V5-1', 'V6-1', 'V8-1', 'V14-1'],
  L2: ['L1', 'V2-2', 'V3-1', 'V4-1', 'V7-1', 'V9-1', 'V13-1'],
  L3: ['L2', 'V1-1', 'V10-1', 'V11-1', 'V12-1'],
};
```

### مرحلة التطوير

```javascript
// استخدام ASVS في PR Review
module.exports = {
  rules: {
    'require-auth': {
      meta: { severity: 'error' },
      create(context) {
        return {
          MethodDefinition(node) {
            // ASVS 13.1.1: تأكد من وجود middleware auth على API
            if (isAPIRoute(node)) {
              const hasAuth = node.value.body.body.some(
                stmt => isAuthMiddleware(stmt)
              );
              if (!hasAuth) {
                context.report({
                  node,
                  message: 'ASVS 8.2.1: API endpoint بدون تقييد وصول صريح على مستوى الوظيفة',
                });
              }
            }
          },
        };
      },
    },
  },
};
```

### مرحلة الاختبار

```javascript
// اختبار ASVS تلقائي (أرقام المتطلبات وفق نسخة 5.0)
const asvsTests = {
  'V12': {
    name: 'HTTPS إلزامي (Secure Communication)',
    test: async (url) => {
      const res = await fetch(url.replace('http://', 'https://'));
      return res.ok;
    },
    severity: 'critical',
  },
  '1.2.4': {
    name: 'Parameterized Queries',
    test: async (url) => {
      // SQLi test
      const res = await fetch(`${url}?id=1' OR '1'='1`);
      return res.status === 400 || res.status === 500;
    },
    severity: 'critical',
  },
  '8.2.2': {
    name: 'BOLA Protection',
    test: async (baseUrl, token) => {
      // اختبار IDOR
      const res1 = await fetch(`${baseUrl}/api/users/1`, {
        headers: { Authorization: `Bearer ${token}` },
      });
      const res2 = await fetch(`${baseUrl}/api/users/999`, {
        headers: { Authorization: `Bearer ${token}` },
      });
      return res1.status !== res2.status;
    },
    severity: 'high',
  },
};
```

## ASVS 5.0 و OWASP Top 10 (2025)

جدول توجيهي (وضعه The Code Fix لربط الدرسين ببعض، وليس مخططًا رسميًا تنشره OWASP) لأي فصول ASVS 5.0 تغطي كل فئة من [OWASP Top 10 نسخة 2025](/learn/api-security/00-intro):

| OWASP Top 10 2025 | فصول ASVS 5.0 ذات الصلة |
|-------------------|------------------------|
| Broken Access Control (يضم SSRF الآن) | V8 (Authorization) |
| Security Misconfiguration | V13 (Configuration) |
| Software Supply Chain Failures | V15 (Secure Coding and Architecture) |
| Cryptographic Failures | V11 (Cryptography), V14 (Data Protection) |
| Injection | V1 (Encoding and Sanitization), V2 (Validation) |
| Insecure Design | V2 (Validation and Business Logic), V15 (Architecture) |
| Authentication Failures | V6 (Authentication), V9 (Self-contained Tokens), V10 (OAuth/OIDC) |
| Software/Data Integrity Failures | V14 (Data Protection), V5 (File Handling) |
| Logging and Alerting Failures | V16 (Security Logging and Error Handling) |
| Mishandling of Exceptional Conditions | V16 (Error Handling) |

## أدوات ASVS

```bash
# ASVS تلقائي باستخدام OWASP ASVS Gateway
git clone https://github.com/OWASP/ASVS
cd ASVS/tools/asvs-gateway
npm install
node asvs-check.js --level L2 --config config.json

# تحويل ASVS لمتطلبات Jira
node tools/export-to-jira.js --level L2 --format csv
```

```javascript
// أداة ASVS بسيطة (نسخة 5.0 — 17 فصلاً بدل 14)
const asvs = require('./asvs-5.0.json');

function generateChecklist(level = 'L1') {
  const requirements = [];

  for (const [section, items] of Object.entries(asvs)) {
    for (const [id, req] of Object.entries(items)) {
      if (req.levels.includes(level)) {
        requirements.push({
          id,
          title: req.title,
          description: req.description,
          section: req.section,
          level,
        });
      }
    }
  }

  return requirements;
}
```

## شهادة ASVS

```text
للحصول على شهادة ASVS:
  1. حدد مستوى الضمان (L1, L2, L3)
  2. قيم تطبيقك حسب المتطلبات
  3. وثق النتائج والأدلة
  4. راجع مع خبراء (اختياري)
  5. انشر التقرير (اختياري)

مستويات الشهادة:
  ✅ ASVS Level 1 Verified
  ✅✅ ASVS Level 2 Verified
  ✅✅✅ ASVS Level 3 Verified
```

> ⚠️ ASVS ليس مشروعاً لمرة واحدة - إنه عملية مستمرة. كل تحديث أو ميزة جديدة في تطبيقك قد تؤثر على مستوى الامتثال لـ ASVS.
