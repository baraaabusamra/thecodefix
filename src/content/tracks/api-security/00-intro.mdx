## ما هو أمن التطبيقات؟

أمن التطبيقات (Application Security) هو ممارسة حماية التطبيقات من التهديدات الأمنية عبر اكتشاف وإصلاح الثغرات في التصميم والبناء والتشغيل. يهدف إلى منع الوصول غير المصرح به للبيانات أو التلاعب بها.

## لماذا الأمن مهم؟

- **حماية بيانات المستخدمين**: تسرب البيانات قد يؤدي لمسؤولية قانونية وفقدان الثقة.
- **الامتثال للمعايير**: مثل GDPR و PCI-DSS و HIPAA.
- **التكلفة**: إصلاح الثغرة بعد الإطلاق أغلى بـ 30 مرة من إصلاحها أثناء التطوير.
- **السمعة**: اختراق واحد قد يدمر سمعة شركة.

## ثالوث CIA

```text
C - Confidentiality (السرية): لا يمكن لأحد غير المصرح له قراءة البيانات
I - Integrity (السلامة): لا يمكن تعديل البيانات دون إذن
A - Availability (التوفر): النظام متاح عند الحاجة
```

أي ثغرة تنتهك واحدا أو أكثر من هذه المبادئ.

## OWASP Top 10

OWASP Top 10 هي قائمة بأهم 10 ثغرات في تطبيقات الويب، يصدرها مشروع OWASP غير الربحي. بعد أن ظل إصدار 2021 هو المرجع لسنوات، صدر تحديث **2025** (أُعلن نهاية 2025 واعتُمد رسميًا مطلع 2026) وهو أول مراجعة جذرية منذ 2021. القائمة الحالية:

1. **Broken Access Control**: ثغرات الصلاحيات — يبقى المركز الأول، ودمج فيه SSRF الذي كان بندًا مستقلاً سابقًا
2. **Security Misconfiguration**: إعدادات أمنية خاطئة — صعد للمركز الثاني
3. **Software Supply Chain Failures**: ثغرات سلسلة التوريد البرمجية — فئة جديدة توسّع بند "المكونات القديمة" السابق ليشمل كل سلسلة التوريد (تبعيات، أنظمة بناء، توزيع)
4. **Cryptographic Failures**: أخطاء التشفير
5. **Injection**: حقن الأكواد (SQL، NoSQL، OS)
6. **Insecure Design**: تصميم غير آمن
7. **Authentication Failures**: أخطاء المصادقة
8. **Software or Data Integrity Failures**: سلامة البرمجيات والبيانات
9. **Security Logging and Alerting Failures**: ضعف التسجيل والتنبيه الأمني
10. **Mishandling of Exceptional Conditions**: سوء التعامل مع الحالات الاستثنائية — فئة جديدة كليًا، تغطي أخطاء معالجة الحالات الطارئة والاستثناءات التي تسرّب معلومات أو تتجاوز الفحوصات الأمنية

> 💡 SSRF لم يعد بندًا مستقلاً في هذه القائمة العامة، لكنه لا يزال بندًا مستقلاً (API7:2023) في OWASP **API** Security Top 10 الذي يعتمد عليه هذا المسار — ستمر عليه بالتفصيل في درس التهديدات ودرس SSRF لاحقًا.

```javascript
// مثال: ثغرة Broken Access Control
// سيئ - لا يتحقق من صلاحية المستخدم
app.get('/api/users/:id', (req, res) => {
  const user = db.findUser(req.params.id);
  res.json(user);
});

// جيد - يتحقق من هوية المستخدم
app.get('/api/users/:id', authenticate, (req, res) => {
  if (req.user.id !== req.params.id && !req.user.isAdmin) {
    return res.status(403).json({ error: 'غير مصرح' });
  }
  const user = db.findUser(req.params.id);
  res.json(user);
});
```

## العقلية الأمنية

- **لا تثق بأي مدخل**: افترض أن كل بيانات تدخل التطبيق خبيثة.
- **الدفاع في العمق (Defense in Depth)**: لا تعتمد على طبقة حماية واحدة.
- **المبدأ الأقل صلاحية (Least Privilege)**: امنح أقل صلاحية ممكنة لكل مكون.
- **الفشل الآمن (Fail Secure)**: عند حدوث خطأ، افترض الرفض لا السماح.

> ⚠️ الأمن ليس ميزة إضافية - هو متطلب أساسي في كل تطبيق. تجاهله قد يكلفك عملك وسمعتك.
