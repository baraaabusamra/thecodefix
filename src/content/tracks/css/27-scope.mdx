## المشكلة التي يحلّها

بنيت مكوّن بطاقة `.card`، وكتبت بداخله `a { color: blue; }` لتلوين روابطه. المشكلة: هذا المحدّد لا يعرف حدود البطاقة — سيلوّن **كل رابط في الصفحة كلها** بمجرد وجود `a` بأي مكان تحت `.card` في الشجرة، وقد يتسرّب لمكوّنات متداخلة داخلها لم تقصدها أصلًا.

الحل التقليدي كان تسمية طويلة (منهجية BEM مثلًا: `.card__link`) لتفادي التسرّب يدويًا. `@scope` يحل نفس المشكلة **على مستوى المتصفح نفسه**، بلا أي اصطلاح تسمية.

## الصياغة الأساسية

```css
@scope (.card) {
  a { color: #7c5cff; }      /* فقط داخل .card */
  img { border-radius: 8px; }
}
```

كل محدّد بداخل `@scope (.card) { }` يُقيَّد تلقائيًا: يجب أن يقع العنصر **داخل شجرة `.card`** ليتأثر. نفس القاعدة خارج `@scope` كانت ستطال كل `a` و`img` بالصفحة.

## `:scope` — الإشارة للجذر نفسه

بداخل الكتلة، `:scope` يشير للعنصر الجذر (`.card` هنا) وليس لأبنائه:

```css
@scope (.card) {
  :scope { border: 1px solid #e5e0f0; }   /* البطاقة نفسها */
  h2 { font-size: 1.1rem; }                /* أبناؤها */
}
```

## Donut Scoping — تحديد حدّ سفلي أيضًا

أضف `to (...)` لتعريف **حدّ سفلي** تتوقف عنده الأنماط — فتُنسّق المنطقة "الكعكة" بين الجذر والحد، لا الحفرة في وسطها:

```css
@scope (.card) to (.card-content) {
  img { border: 3px solid gold; }
}
```

هنا تُنسَّق أي `img` داخل `.card`، **إلا** ما وقع داخل `.card-content` — منطقة مثالية لتنسيق "الإطار" الخارجي لمكوّن مركّب دون التأثير على محتواه الداخلي القابل لإعادة الاستخدام (مثل مكوّن مُدرَج بداخله).

## القربية (Proximity) بدل التسمية الطويلة

عند تعارض قاعدتين من نطاقين مختلفين **بنفس الأولوية (Specificity)** بالضبط، لا يحسم ترتيب الظهور في الملف كالمعتاد — بل **القربية**: القاعدة التي جذرها الأقرب للعنصر المستهدف تفوز.

```css
@scope (.theme-light) { .btn { background: white; } }
@scope (.card)        { .btn { background: #7c5cff; } }
```

لو كان الزر داخل `.theme-light` وداخل `.card` معًا، يفوز أقرب جذر إليه فعليًا في الشجرة — بصرف النظر عن أي القاعدتين وردت أولًا بالملف.

> 🔑 القربية تتدخّل فقط عند **تساوي الأولوية تمامًا**؛ الأولوية والطبقات (`@layer`) و`!important` تظل أقوى منها دائمًا وتُحسم أولًا.

## `@scope` لا يعزل المظهر، فقط يقيّد المحدّدات

نقطة يخطئ فيها كثيرون: `@scope` **ليس** حدود عزل حقيقي مثل Shadow DOM. الخصائص الموروثة (كـ `color` و`font-family`) تستمر بالمرور عبره من الخارج للداخل بشكل طبيعي — هو يقيّد فقط أي عنصر **يطابقه** المحدّد، لا تدفّق الوراثة.

## جدول مقارنة سريع

| | تسمية طويلة (BEM) | `@scope` |
| --- | --- | --- |
| يمنع التسرّب | نعم، يدويًا بانضباط المطوّر | نعم، يفرضه المتصفح |
| يحتاج اصطلاح تسمية | نعم | لا |
| يعزل الوراثة | لا (ولا BEM أصلًا) | لا |
| حدّ سفلي (Donut) | يحتاج محدّدات استثناء يدوية | `to (...)` جاهزة |

## الأخطاء الشائعة

- **❌ توقّع أن `@scope` يعزل كل شيء** مثل مكوّن معزول تمامًا → الوراثة تمر عبره كالعادة.
- **❌ نسيان أن القربية تعمل فقط عند تساوي الأولوية** → لا تفسّر بها كل نتيجة غير متوقعة قبل التأكد من الأولوية أولًا.
- **❌ كتابة `@scope` بلا قوسين `()` حول الجذر** خارج وسم `<style>` مضمّن → القاعدة بلا جذر تُحسب فارغة في ملف CSS خارجي.

## خلاصة

`@scope (.root) { ... }` يحصر تأثير محدّداتك داخل جزء محدَّد من الصفحة بلا أي اصطلاح تسمية، و`to (...)` يضيف حدًّا سفليًا لتنسيق "الإطار" دون المحتوى الداخلي (Donut Scoping). تذكّر أنه يقيّد المطابقة فقط لا الوراثة، وأن القربية تحسم التعارضات فقط عند تساوي الأولوية تمامًا.
