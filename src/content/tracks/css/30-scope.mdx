## المشكلة التي تحلّها

بنيت مكوّنَي `.card` و`.article` وكلاهما يحتوي عنصر `<p>` — لكنك تريد تنسيقًا مختلفًا لفقرات كل واحد. الحل التقليدي أحد أمرين:

1. **محدّدات مقيَّدة يدويًا**: `.card p { ... }` و`.article p { ... }` — تعمل، لكنها تكبر وتتعقّد كلما تداخلت المكوّنات.
2. **اتفاقية تسمية صارمة** مثل BEM (`.card__paragraph`) — تحل المشكلة، لكنها تحتاج انضباطًا يدويًا من كل من يكتب الأنماط، ولا شيء يمنع أحدًا من كسرها بالخطأ.

قاعدة **`@scope`** تحصر تأثير مجموعة من القواعد داخل جزء محدد من شجرة DOM مباشرة في CSS نفسه — بلا تسمية خاصة ولا محدّدات مقيَّدة يدويًا.

## الصياغة الأساسية

```css
@scope (.card) {
  p {
    color: #334155;
  }
}
```

هذا يعني: طبّق `p { color: #334155; }` فقط على عناصر `<p>` الموجودة داخل أي عنصر يطابق `.card` — لن تتأثر فقرات `.article` إطلاقًا، رغم أن المحدّد `p` وحده بلا `@scope` كان سيطبّقها على كل فقرات الصفحة.

- **`(.card)`** هنا هو **جذر النطاق (scope root)** — نقطة البداية التي يبدأ منها البحث عن العناصر المطابقة.
- القواعد داخل `{ }` تُطبَّق **فقط** على عناصر داخل هذا الجذر (أو الجذر نفسه إن استخدمت `:scope`).

## تحديد حد أقصى: `to (...)`

`@scope` تدعم أيضًا **حد نهاية (scope limit)** يوقف تأثير الأنماط عند عمق معيّن:

```css
@scope (.article) to (.comments) {
  p {
    line-height: 1.8;
  }
}
```

هذا يُنسّق فقرات `.article` لكن **يتوقف** عند الوصول لعنصر `.comments` — فقرات قسم التعليقات المُضمَّن داخل المقال لا تتأثر، رغم أنها من ناحية DOM بداخل `.article`. الحد غير شامل (exclusive) — عنصر `.comments` نفسه وما بداخله خارج النطاق تمامًا.

## استهداف جذر النطاق نفسه بـ `:scope`

للتحكم بمظهر جذر النطاق ذاته من داخل قاعدة `@scope`، استخدم المحدّد `:scope`:

```css
@scope (.alert-box) {
  :scope {
    border: 1px solid #f59e0b;
    padding: 12px;
    border-radius: 8px;
  }
  strong {
    color: #b45309;
  }
}
```

## لماذا هذا أفضل من محدّد طويل يدويًا

```css
/* الأسلوب التقليدي — يحتاج تكرار السياق في كل قاعدة */
.sidebar .widget .link { color: #7c5cff; }
.sidebar .widget .link:hover { color: #5b3fd6; }
```

```css
/* @scope — يفصل "أين" عن "ماذا" مرة واحدة لكل قواعد المكوّن */
@scope (.sidebar .widget) {
  .link { color: #7c5cff; }
  .link:hover { color: #5b3fd6; }
}
```

الفرق الجوهري: **قوة التحديد (Specificity)** داخل `@scope` تُحسب من المحدّدات الفعلية بداخلها فقط — جذر النطاق نفسه لا يضيف أي قوة تحديد إضافية، فيبقى `.link` هنا بسيطًا وسهل التجاوز عند الحاجة، بعكس تكديس المحدّدات يدويًا.

| | محدّد مقيَّد يدويًا | `@scope` |
| --- | --- | --- |
| يفصل السياق عن القاعدة | لا، يتكرر بكل سطر | نعم، مرة واحدة |
| قوة تحديد إضافية | تتراكم مع كل مستوى | لا تتأثر بجذر النطاق |
| حد نهاية للتأثير | يحتاج محدّدات نفي `:not()` معقّدة | `to (...)` مباشرة |

## الأخطاء الشائعة

- **❌ توقّع أن `@scope` يستبدل الحاجة لأسماء فئات واضحة** → ما زلت تحتاج فئة أو محدّد يحدّد جذر النطاق؛ الفرق أنك لن تحتاج تسمية كل عنصر فرعي داخله.
- **❌ نسيان أن حد `to (...)` غير شامل** → العنصر المطابق لحد النهاية وكل ما بداخله خارج تأثير القاعدة تمامًا، وليس فقط "يبدأ الاستثناء بعده".
- **❌ الاعتماد عليها بلا التحقق من دعم المتصفح المستهدف لمشروع قديم** → دعمها عبر المتصفحات الرئيسية الثلاثة (Chrome وSafari وFirefox) اكتمل في ديسمبر 2025؛ لتوافق مع إصدارات أقدم استخدم محدّدات مقيَّدة يدويًا كبديل.

## خلاصة

`@scope` تحصر تأثير مجموعة أنماط داخل جزء محدد من الصفحة — جذر بداية اختياري وحد نهاية اختياري — بديل عملي عن اتفاقيات تسمية مثل BEM أو محدّدات طويلة متكرّرة، بلا أي أثر إضافي على قوة التحديد.
