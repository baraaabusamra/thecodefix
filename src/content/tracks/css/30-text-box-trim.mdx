## المشكلة التي تحلّها

جرّبت هذا الموقف غالبًا: تصمم زرًا أو شارة (badge) بارتفاع محدد، تضع النص بداخله، وتوسّطه عموديًا بـ `flex` أو `grid` — ومع ذلك يبدو النص "غير متوسّط تمامًا"، وكأن فيه فراغًا خفيًا أعلى الحروف أكثر من أسفلها.

السبب ليس خطأ منك: كل سطر نص في CSS يحجز مساحة أطول قليلاً من ارتفاع الحروف الفعلي، لأن `line-height` يضيف فراغًا فوق وتحت النص ليستوعب حروفًا بامتدادات مختلفة (كالنقاط فوق الحروف، أو الأجزاء النازلة تحت السطر مثل `g`/`y`). هذا الفراغ ("leading") ضروري للنصوص متعددة الأسطر، لكنه يزعج بالضبط في عناصر قصيرة كالأزرار والعناوين حيث تريد توسيطًا بصريًا دقيقًا.

الحل التقليدي كان تعديل `line-height` بقيمة مجرَّبة بالتخمين، أو هوامش سالبة (`margin` بقيم سالبة) تُحسب يدويًا لكل خط — حلول هشّة تنكسر مع تغيّر الخط أو حجمه.

## الصياغة والقيم

خاصية **`text-box`** اختصار (shorthand) لخاصيتين: `text-box-trim` (أي حافة تُقصّ) و`text-box-edge` (إلى أين تُقصّ):

```css
.tight {
  text-box: trim-both cap alphabetic;
}
```

يكافئ كتابة الخاصيتين الطويلتين منفصلتين:

```css
.tight {
  text-box-trim: trim-both;      /* اقصص الحافتين: فوق وتحت */
  text-box-edge: cap alphabetic; /* فوق: حتى قمة الحروف الكبيرة | تحت: حتى خط الأساس */
}
```

### قيم `text-box-trim`

| القيمة | المعنى |
| --- | --- |
| `none` | لا قصّ — السلوك الافتراضي المعتاد |
| `trim-start` | قصّ الفراغ من الحافة العلوية فقط |
| `trim-end` | قصّ الفراغ من الحافة السفلية فقط |
| `trim-both` | قصّ الفراغ من الحافتين معًا — الأكثر استخدامًا عمليًا |

### قيم `text-box-edge`

تحدّد **إلى أين** يصل القصّ، وتُكتب كقيمتين (حافة علوية ثم سفلية):

| القيمة | تعني |
| --- | --- |
| `text` | حدود الخط الافتراضية (metrics الخط نفسه) |
| `cap` (علوية فقط) | قمة الحروف الكبيرة (Capital height) |
| `ex` (علوية فقط) | ارتفاع الحرف الصغير x |
| `alphabetic` (سفلية فقط) | خط الأساس (baseline) — لا نزول تحته |

## مثال: زر بتوسيط عمودي دقيق

```css
.badge {
  display: inline-flex;
  align-items: center;
  padding: 6px 14px;
  background: #4f46e5;
  color: white;
  border-radius: 999px;
  font-weight: 600;

  /* بدون هذا السطر، النص يبدو أقرب لأسفل الشارة قليلاً */
  text-box: trim-both cap alphabetic;
}
```

بلا `text-box`، الفراغ الإضافي أسفل الحروف (المخصَّص أصلاً للأجزاء النازلة مثل `g`) يجعل النص يبدو مزاحًا للأسفل قليلاً رغم أن `align-items: center` يوسّطه حسابيًا حسب صندوق السطر الكامل، لا حسب الحروف المرئية نفسها.

## التدهور اللطيف (Graceful Degradation)

المتصفح الذي لا يعرف `text-box` بعد **يتجاهلها بصمت** ويعرض السلوك القديم المعتاد (فراغ إضافي بسيط) — لا كسر تخطيط، ولا حاجة لـ `@supports` كإلزام، على عكس ميزات أخرى أحدث قد تكسر التخطيط بلا بديل. يمكن استخدامها مباشرة كتحسين تدريجي.

## الأخطاء الشائعة

- **❌ توقّع أن `text-box-edge` بقيمة واحدة فقط تكفي** → تحتاج غالبًا قيمتين (علوية ثم سفلية) عند استخدام الخاصية الطويلة منفردة؛ الشورت‌هاند `text-box` أوضح لهذا السبب.
- **❌ استخدامها بدل `line-height` كليًا** → `text-box` تقصّ الفراغ الزائد حول الصندوق النصي فقط، ولا تُغيّر التباعد بين الأسطر في فقرة متعددة الأسطر — لا تزال `line-height` هي الأداة الصحيحة لذلك.
- **❌ الاعتماد عليها لعناصر تحتوي نصًا متعدد الأسطر متوقّعًا ارتفاعًا ثابتًا للسطر** → القصّ يؤثر على حافتي الصندوق الكليتين (أول وآخر سطر)، لا على كل سطر منفرد داخل فقرة طويلة.

## خلاصة

`text-box` (واختصاراتها الطويلة `text-box-trim` و`text-box-edge`) تحذف الفراغ الخفي الذي يضيفه `line-height` فوق وتحت النص، فيصبح التوسيط العمودي للأزرار والشارات والعناوين القصيرة دقيقًا فعليًا بلا حيل هوامش سالبة — وبما أن تجاهلها آمن على المتصفحات القديمة، يمكن تبنّيها اليوم كتحسين تدريجي مباشر.
