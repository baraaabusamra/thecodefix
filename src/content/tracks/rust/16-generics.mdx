## المشكلة: نفس المنطق لأنواع مختلفة

دالة تجد أكبر عنصر في قائمة أعداد صحيحة، وأخرى لقائمة كسور، وثالثة لقائمة حروف. نفس الأسطر تمامًا، والفرق في النوع فقط. الأنواع العامّة تكتب المنطق **مرة واحدة** مع "نوع متغيّر" اسمه عادة `T`.

## دالة عامّة

```rust
fn largest<T: PartialOrd>(list: &[T]) -> &T {
    let mut max = &list[0];
    for item in list {
        if item > max {
            max = item;
        }
    }
    max
}

fn main() {
    println!("{}", largest(&[3, 7, 2, 9]));       // 9
    println!("{}", largest(&[1.5, 0.2, 8.1]));    // 8.1
    println!("{}", largest(&['ب', 'ي', 'أ']));    // ي
}
```

- `<T>` بعد اسم الدالة يعلن معامل النوع.
- `: PartialOrd` **قيد** (trait bound): "أي نوع يمكن مقارنته بـ `>`". بدونه يرفض المترجم `item > max`، لأن ليس كل نوع قابلًا للمقارنة.

هذا الفرق الجوهري عن القوالب في C++: Rust تفحص الدالة العامّة **مرة واحدة** بقيودها، لا عند كل استخدام. إذا استدعيتها بنوع لا يحقّق القيد، يقول لك المترجم أي قيد ناقص بالضبط.

## صيغة where للقيود الكثيرة

```rust
use std::fmt::Display;

fn describe<T>(item: &T) -> String
where
    T: Display + Clone,      // يجب أن يحقّق الاثنين
{
    format!("القيمة: {item}")
}

fn main() {
    println!("{}", describe(&42));
}
```

حين تكثر القيود أو معاملات الأنواع، `where` تجعل التوقيع مقروءًا.

## هيكل عامّ

```rust
#[derive(Debug)]
struct Point<T> {
    x: T,
    y: T,
}

let int_p = Point { x: 1, y: 2 };
let float_p = Point { x: 1.0, y: 2.0 };
// let mixed = Point { x: 1, y: 2.0 };   // ❌ x و y يجب أن يكونا نفس T
println!("{:?} {:?}", int_p, float_p);
```

لنوعين مختلفين عرّف معاملين: `struct Pair<A, B> { a: A, b: B }`.

### أنت تستخدم هذا كل يوم

`Vec<T>` و`Option<T>` و`Result<T, E>` و`HashMap<K, V>` كلها أنواع عامّة في المكتبة القياسية. فهم الأنواع العامّة يعني فهم توقيع أي دالة في التوثيق.

## طرق عامّة، وطرق لنوع محدّد

```rust
struct Point<T> {
    x: T,
    y: T,
}

impl<T> Point<T> {
    fn x(&self) -> &T {               // لكل Point<T>
        &self.x
    }
}

impl Point<f64> {
    fn distance_from_origin(&self) -> f64 {   // لـ Point<f64> فقط
        (self.x * self.x + self.y * self.y).sqrt()
    }
}

fn main() {
    let p = Point { x: 3.0, y: 4.0 };
    println!("{} {}", p.x(), p.distance_from_origin());   // 3 5
    let q = Point { x: 1, y: 1 };
    println!("{}", q.x());
    // q.distance_from_origin();    // ❌ غير موجودة لـ Point<i32>
}
```

`impl<T>` تعني "لكل T"، بينما `impl Point<f64>` تضيف طرقًا لنوع واحد فقط. هكذا يكون للنوع العام سلوك إضافي حين يناسب نوعه الداخلي.

## صفر تكلفة: كيف؟

Rust تولّد عند الترجمة **نسخة متخصّصة** لكل نوع استخدمته (تسمّى monomorphization): `largest` تصبح فعليًا `largest_i32` و`largest_f64` و`largest_char`. النتيجة سريعة تمامًا كما لو كتبتها يدويًا، بلا أي فحص أنواع أثناء التشغيل. الثمن: ملف تنفيذي أكبر قليلًا وترجمة أبطأ. وحين تحتاج العكس (قائمة فيها أنواع مختلفة معًا في وقت التشغيل)، فهذا عمل [الكائنات السمة `dyn Trait`](/learn/rust/24-trait-objects).

## أخطاء شائعة

- **نسيان القيد:** `fn largest<T>(list: &[T])` مع `>` تعطي `binary operation > cannot be applied to type &T`. أضف `T: PartialOrd`.
- **إرجاع `T` بدل `&T` من شريحة:** يحتاج `T: Copy` أو `Clone` لأنك لا تملك العناصر.
- **`largest(&[])`:** `list[0]` تسبّب `panic` مع قائمة فارغة. الأأمن إرجاع `Option<&T>` (أو استخدام `iter().max()` الجاهزة).
- **تعميم كل شيء مبكّرًا:** اكتب النسخة المحدّدة أولًا، وعمّمها حين تحتاج نوعًا ثانيًا فعلًا.
- **خلط `impl<T> Point<T>` و`impl Point<T>`:** الثانية خطأ؛ `<T>` بعد `impl` تعلن المعامل.
