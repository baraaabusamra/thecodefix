## المرجع &: استخدم دون أن تملك

**الاستعارة** تعني أخذ **مرجع** لقيمة بدل ملكيتها. المالك يبقى المالك، والقيمة لا تُحرَّر حين ينتهي المرجع:

```rust
fn length(s: &String) -> usize {
    s.len()
}   // s مرجع فقط: لا شيء يُحرَّر هنا

fn main() {
    let s = String::from("مرحبًا");
    let len = length(&s);          // نُعير مرجعًا
    println!("{s} طولها {len}");   // ✅ s ما زالت ملكنا
}
```

`&s` تُنشئ مرجعًا، و`&String` في التوقيع تعني "مرجع إلى String". المراجع للقراءة فقط افتراضيًا.

## المرجع القابل للتعديل &mut

```rust
fn add_excl(s: &mut String) {
    s.push_str("!");
}

fn main() {
    let mut s = String::from("مرحبًا");   // المتغيّر نفسه يجب أن يكون mut
    add_excl(&mut s);
    println!("{s}");                       // مرحبًا!
}
```

`&mut` تكتب في ثلاثة أماكن: المتغيّر (`let mut`)، والاستعارة (`&mut s`)، والتوقيع (`&mut String`). هذا التكرار مقصود: كل من يقرأ الكود يرى أين قد تتغيّر القيمة.

## قاعدتا المستعير (Borrow Checker)

في أي لحظة، لكل قيمة **واحد** من الاثنين:

- **أي عدد** من المراجع للقراءة (`&`)، **أو**
- **مرجع واحد فقط** للتعديل (`&mut`).

وكل مرجع يجب أن يبقى **صالحًا**: لا يعيش أطول من القيمة التي يشير إليها.

```rust
let mut s = String::from("hi");
let r1 = &s;
let r2 = &s;          // ✅ قراءتان معًا
println!("{r1} {r2}");
// انتهى استخدام r1 و r2 هنا

let r3 = &mut s;      // ✅ لا قراءات نشطة الآن
r3.push('!');
println!("{r3}");
```

"نشطة" تعني: سيُستخدم المرجع لاحقًا. المترجم يرى أن `r1` و`r2` لم يعودا مستخدمين بعد `println!`، فيسمح بـ `&mut` بعدها. لو حاولت استخدام `r1` بعد `r3` لرفض.

### لماذا هذه القاعدة؟ مثال يفسد في لغات أخرى

```rust
let mut v = vec![1, 2, 3];
let first = &v[0];        // مرجع لعنصر داخل المتجه
// v.push(4);             // ❌ cannot borrow `v` as mutable because it is also borrowed as immutable
println!("{first}");
```

`push` قد تحتاج مساحة أكبر، فتنقل كل العناصر لمكان جديد في الذاكرة، ويصبح `first` يشير لذاكرة محرّرة. في C++ هذا خطأ صامت يعمل أحيانًا وينهار أحيانًا (iterator invalidation). في Rust لا يُترجم أصلًا. والقاعدة نفسها، "كاتب واحد أو قرّاء كثيرون"، هي التي تمنع **سباقات البيانات** بين الخيوط وقت الترجمة.

## المرجع المعلّق: ممنوع

```rust
// fn dangle() -> &String {   // ❌ missing lifetime specifier
//     let s = String::from("hi");
//     &s                      // s تُحرَّر عند نهاية الدالة
// }

fn no_dangle() -> String {    // ✅ أرجِع الملكية نفسها
    String::from("hi")
}

fn main() {
    println!("{}", no_dangle());
}
```

المترجم يرفض إرجاع مرجع لقيمة ستُحرَّر. الحل غالبًا إرجاع القيمة المملوكة. ومتى يحتاج المترجم معلومات إضافية عن أعمار المراجع؟ هذا موضوع [درس الأعمار (Lifetimes)](/learn/rust/18-lifetimes).

## متى أستعير ومتى آخذ الملكية؟

| التوقيع | المعنى | متى |
| --- | --- | --- |
| `fn f(x: &T)` | سأقرأ | الأغلبية الساحقة من الدوال |
| `fn f(x: &mut T)` | سأعدّل في مكانه | إضافة عنصر، تحديث حالة |
| `fn f(x: T)` | سآخذها نهائيًا | تخزينها في struct، تحويلها لشيء آخر، إرسالها لخيط |

ابدأ بـ `&T`، وانتقل لغيرها فقط حين تحتاج.

## أخطاء شائعة

- **`cannot borrow as mutable because it is also borrowed as immutable`:** مرجع قراءة ما زال مستخدمًا. أنهِ استخدامه قبل التعديل، أو انسخ القيمة التي تحتاجها (`let first = v[0];` لعدد من نوع Copy).
- **نسيان `mut` في أحد الأماكن الثلاثة:** المتغيّر والاستعارة والتوقيع.
- **مرجعان `&mut` لنفس القيمة معًا:** ممنوع حتى في نفس الدالة.
- **إرجاع مرجع لمتغيّر محلّي:** أرجِع القيمة المملوكة.
- **`&String` في التوقيع:** يعمل، لكن `&str` أكثر مرونة لأنها تقبل `String` والنصوص الحرفية معًا ([درس الشرائح](/learn/rust/10-slices)).
