## ليش هذا الدرس "لمحة" لا درسًا كاملًا؟

الدرس السابق غطّى C++23 كمعيار مكتمل ومنشور رسميًّا تقدر تعتمد عليه
بمشروع فعلي. C++26 وضعه مختلف: لجنة معيار C++ (WG21) أنهت **العمل
الفني بالكامل** على C++26 باجتماع لندن (Croydon) نهاية مارس 2026،
بتصويت 114 مع مقابل 12 ضد و3 امتناع — يعني قائمة الميزات صارت
"مقفلة" نهائيًّا، لكن المسودة لسا بطريقها للتصويت الدولي الرسمي (ISO)
قبل ما يصير معيارًا منشورًا بالكامل، تمامًا متل ما مرّ C++23 بنفس
المرحلة قبل نشره النهائي.

عمليًّا هذا يعني: الميزات **لن تتغيّر** جوهريًّا، لكن دعم المترجمات
لسا **تجريبي** بالكامل. GCC 16.1 (نفسه المذكور بالدرس السابق) يقدّم
دعمًا تجريبيًّا مبكرًا خلف أعلام صريحة، وClang يدعم جزءًا منها بصيغة
`-std=c++2c`، بينما MSVC ما عنده تطبيق علني لمعظمها لهلق.

> 💡 هذا الدرس تعريفي حتى تفهم اتجاه اللغة القادم — لا تعتمد على هذي
> الميزات بكود إنتاجي حقيقي قبل ما تتأكد من دعم كامل ومستقر بمترجمك.

## الانعكاس (Reflection) — رؤية بنية البرنامج وقت الترجمة

الانعكاس الساكن (static reflection) يسمح للكود نفسه يسأل المترجم عن
بنية النوع وقت الترجمة: ما أعضاؤه؟ ما أسماؤها؟ — بدل ما تكتب هذا
المنطق يدويًّا لكل نوع. هذا أساس أدوات مثل التوليد التلقائي لـ
serialization أو طباعة تصحيح الأخطاء (debug printing) دون مكتبة خارجية
أو ماكرو معقّد.

الميزة تعتمد على عنصرين جديدين:

- **عامل الانعكاس `^^`**: يأخذ اسم نوع أو كيان ويحوّله لقيمة من نوع
  `std::meta::info` من الترويسة `<meta>` — تمثيل وقت-ترجمة لذلك الكيان.
- **عامل الوصل (splice) `[: ... :]`**: يعكس العملية — يحوّل قيمة
  `std::meta::info` رجوعًا لكود حقيقي بمكانها بالبرنامج.

```cpp
#include <meta>
#include <print>

struct Point {
    int x;
    int y;
};

int main() {
    // ^^Point: يحوّل النوع Point لقيمة انعكاس (std::meta::info)
    for (std::meta::info member : std::meta::nonstatic_data_members_of(
             ^^Point, std::meta::access_context::unchecked())) {
        // splice غير مباشر عبر identifier_of لقراءة اسم العضو كنص
        std::println("{}", std::meta::identifier_of(member));
    }
    // الناتج: x ثم y
}
```

- **`nonstatic_data_members_of(^^T, ctx)`**: يرجّع قائمة انعكاسات لأعضاء
  النوع `T`، مفلترة حسب سياق الوصول `ctx` (`unchecked()` يرى كل الأعضاء
  بغض النظر عن `private`/`public`، و`unprivileged()` يرى العام فقط).
- **`identifier_of(member)`**: يرجّع اسم العضو كنص وقت الترجمة.

> 💡 مرتبط بميزة أخرى بنفس المعيار: عبارات التوسّع (expansion statements)
> عبر `template for` — تسمح بالتكرار وقت الترجمة على مجموعة انعكاسات،
> بديل أوضح من حيل القوالب المتداخلة القديمة لنفس الغرض.

## العقود (Contracts) — تعبير صريح عن الافتراضات

قبل C++26، التحقق من افتراضات دالة ("هذا المعامل لازم يكون موجب"،
"القيمة المرجعة لازم تكون غير صفرية") يعتمد على `assert()` عادي أو
تحقق يدوي بجسم الدالة — لا شيء بتوقيع الدالة نفسه يوثّق الشرط. C++26
(اقتراح P2900) يضيف صياغة مخصّصة لثلاثة أنواع من التأكيدات:

```cpp
int divide(int a, int b)
    pre(b != 0)              // شرط مسبق: يُفحص قبل تنفيذ الدالة
    post(r: r * b == a || a % b != 0) // شرط لاحق: يُفحص على القيمة المُرجعة r
{
    contract_assert(b != 0); // تأكيد داخل جسم الدالة، مثل assert لكن جزء من المعيار
    return a / b;
}
```

- **`pre(condition)`**: شرط مسبق على معاملات الدالة، جزء من توقيعها.
- **`post(r: condition)`**: شرط لاحق على القيمة المُرجعة، باسم مستعار
  `r` لها داخل الشرط.
- **`contract_assert(condition)`**: تأكيد داخل جسم الدالة أو lambda —
  محله `assert()` لكن ضبط تفعيله عبر خيارات المترجم لا عبر `NDEBUG`.

المعيار يعرّف أربعة أوضاع تنفيذ لهذي التأكيدات: `ignore` (تجاهل كامل،
بلا أي تكلفة أداء)، `observe` (فحص وطباعة تحذير عند الفشل بدون إيقاف)،
`enforce` و`quick_enforce` (إيقاف البرنامج عند الفشل، بفرق بسيط
بتفاصيل التعامل مع الاستثناءات أثناء الفحص). GCC 16.1 يفعّل الميزة عبر
`-std=c++26 -fcontracts`، ويختار وضع التنفيذ عبر
`-fcontract-evaluation-semantic=<mode>`.

> 💡 فرق مهم عن `assert()` التقليدي: تفعيل/تعطيل العقود قرار المترجم
> (أو المشروع)، مو مجرّد تعريف/عدم تعريف `NDEBUG` بملف واحد — هذا يمنع
> تناقض شائع بمشاريع كبيرة بين وحدات تُبنى بخيارات مختلفة.

## أخطاء شائعة

- التعامل مع C++26 كمعيار جاهز للاستخدام الإنتاجي اليوم — العمل الفني
  انتهى وصُوِّت عليه، لكن النشر الرسمي ودعم المترجمات الكامل لسا
  بالطريق؛ اعتبره اتجاهًا مستقبليًّا تتجهّز له، لا معيارًا تبني عليه
  مشروعًا حقيقيًّا الآن.
- تفعيل `-freflection` أو `-fcontracts` بدون `-std=c++26` صراحة —
  الميزتان مربوطتان بهذا المعيار تحديدًا، ولن تعملا مع `-std=c++23` أو
  الافتراضي.
- الخلط بين `contract_assert` و`assert()` التقليدي وافتراض أن نفس قواعد
  `NDEBUG` تنطبق عليه — لكل منهما آلية تفعيل مختلفة تمامًا.
